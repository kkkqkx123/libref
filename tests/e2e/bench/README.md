# 检索问答基准（冻结夹具归档）

本目录用真实使用场景做检索问答基准：文档来自第三方文档站，源码来自该库的官方仓库，
两者都经生产获取工具取得，而不是用本仓库自己的文件凑语料。

**获取只做一次。** 抓取与克隆发生在临时目录里，产物导出成不可变归档后立即丢弃临时层；
此后的构建、评测与扫描只读归档。语料因此不会随站点改动、提供方漂移或本机目录结构变化，
门禁下限也只在归档修订不变时有效。

- **归档**：`fixtures/{项目}/docs` 与 `fixtures/{项目}/code-{ref}`，一目录一份；源码分支的目录名
  带 ref 标签，跟随默认分支的固定叫 `head`（如 `fixtures/httpx/code-head`），固定发布的写成标签名，
  所以列出目录就能看出载荷是分支头还是某次发布。文档分支存原始正文（不是净化文本），
  源码分支存固定提交、**只含被索引子树**的工作树打包（不含版本库，条目保留仓库相对路径，
  所以源码地址与索引整仓时一致）。身份（库、生态、版本）写在元数据里，不写进路径，
  所以移动归档不会改变它描述的对象。
- **不入库**：`fixtures/`（归档）、`data/`（数据集）、`outputs/`（报告）全部忽略；
  只有规格、脚本、判定集与门禁进版本库。
- **规格**：`bench.json` 列出每个项目分支的获取配方与身份。当前十八个主夹具覆盖七个生态位与
  九种语言的解析机制，外加六个干扰池源码夹具：

  | 夹具 | 生态 / 语言 | 档位 | 机制 |
  |---|---|---|---|
  | `httpx/docs`＋`httpx/code-head` | pypi / Python | 中 | 相对导入、装饰器、异步、协议 |
  | `zod/docs`＋`zod/code-v4.6.7` | npm / TypeScript | 中 | 路径别名、桶文件重导出、多包 |
  | `jsoup/docs`＋`jsoup/code-jsoup-1.24.1` | maven / Java | 中 | 泛型、重载、内部类、注解 |
  | `fiber/docs`＋`fiber/code-v3.7.0` | go / Go | 中 | 接口嵌入、包级命名、同名方法跨包 |
  | `vue/docs`＋`vue/code-v3.5.45` | npm / TypeScript | 大 | 中文语料、多包大仓子树、桶重导出 |
  | `pydantic/docs`＋`pydantic/code-v2.14.3` | pypi / Python | 中大 | 第二套站点生成器、围栏表格密集 |
  | `FluentValidation/docs`＋`code-12.2.0` | nuget / C# | 中 | 泛型、表达式树、链式调用 |
  | `Rocket/docs`＋`code-v0.5.2` | crates / Rust | 中 | 过程宏、属性宏、声明可见性 |
  | `gradle/docs`＋`code-v9.9.1` | maven / Java+Kotlin+Groovy | 大 | 跨语言混排、构建脚本、生成代码 |
  | 干扰池（`boltons`、`mitt`、`gson`、`mysql`、`once_cell`、`Dapper`） | 各生态 | 小 | 只做源码分支，无判定集 |

  每个主项目都是同一个库的文档站与官方仓库，两分支共享术语，因此可以写跨分支查询。
  小库档由干扰池里最便宜的 `mitt`（1 文件）与 `once_cell`（5 文件）覆盖下限；
  大仓档由 `vue` 多包子树与 `gradle` 子集承担（成本另记）。
- **每夹具有体检断言**：文档分支要求页数与块数非零；源码分支必须声明 `languages`，
  并要求语言分布与声明一致、文件全解析、实体/调用/源码块非零，否则构建直接失败。
- **可选配方字段**：文档分支的 `path_prefixes` 限定路径前缀（用于同页多版本的站点，
  例如 Read the Docs 的 sitemap 会把同一页的多个版本都列出来）；`follow_links` 允许在
  sitemap 只列落地页时跟随站内链接（默认只收发现页）；`extra_urls` 显式补种导航栏专属页面
  （正文抽取会裁掉导航栏，这类链接跟随不到）；源码分支的 `exclude_globs`
  按仓库相对路径排除条目，用于把测试、基准与已废弃子树挡在语料外（语料是库的参考材料，
  测试脚手架会替实现回答问题）；源码分支的 `ref` 指定发布标签，缺省则跟随默认分支并记为 `head`。
  源码分支的版本由 `ref` 推导，规格里不写 `version`。新增发现层规则：llms.txt 按同格式
  取链接最多的层级（section 文件不再截获产品文件），跨格式仍是 llms.txt 优先于 sitemap。
- **文档版本**：文档分支必须声明 `doc_version`，取值就是站点声明的原样字符串（`2.9`、`v3.x`、
  `latest`），站点什么都不声明时写 `unversioned`。获取时按"页面路径段 → canonical → 版本元数据"
  的顺序取证，观测值与声明不一致就失败；`unversioned` 是记录下来的事实，不是猜的缺省值。
- **语料语言**：文档分支必须声明 `corpus_lang`（`en` 或 `cjk`）。构建时从入库页面实测含 CJK 的
  页数占比，与声明不符即失败：跨语言分栏的方向由这个字段决定，声明错了分栏就指向反方向。

## 运行

```bash
uv run python -m tests.e2e.bench.fetch              # 获取并冻结归档（联网，一次即可）
uv run python -m tests.e2e.bench.fetch --only httpx/docs --reacquire   # 重新获取，产生新修订
uv run python -m tests.e2e.bench.build              # 离线回放归档，产出 data/bench.db
uv run python -m tests.e2e.bench.evaluate           # 方法矩阵 + 专项探针 + 门禁
uv run python -m tests.e2e.bench.evaluate --real    # 真实嵌入与重排，门禁含融合与精排
uv run python -m tests.e2e.bench.sweep [--real]     # 参数扫描
LIBREF_RUN_BENCH=1 uv run pytest tests/integration/test_retrieval_bench.py -q
```

`fetch.py` 支持 `--only ID` 与 `--reacquire`：没有 `--reacquire` 时已存在的归档不会被覆盖。
网络或站点不可用退出码为 2，标记环境不可用，不算回归。`build.py` 与 `evaluate.py` 退出码
非零表示归档校验或门禁不满足，报告里同时列出失败项与全部观测值。归档缺失时构建直接报错，
门禁用例跳过。

## 冻结与校验

- 获取时先导出到暂存目录，成功后才落到归档；归档写完后重读一遍校验内容摘要，再置为只读。
- 构建读归档时校验身份、获取配方与载荷摘要，并在消费过程中重算页集合摘要或源码树摘要，
  任何不一致都是硬失败。归档被改动、规格被改动但没有重新获取，都会在这一步暴露。
- 构建只接受空目录，或只含 `bench.db` 与 `manifest.json` 的上一次数据集；其他目录直接拒绝，
  不会先删再建。
- 评测先校验判定目标都在语料里：指向数据集从未收到的页面或源码路径时直接报错，
  不把它当成"所有方法都检索失败"的召回损失。
- 归档修订是载荷摘要的前 12 位，写进数据集清单与报告；`gates.json` 记录下限所属的修订，
  修订不符即门禁失败，提示重新测量下限。
- 获取先写进暂存目录，成功后才替换归档；中途失败不留下半个归档，也不会破坏已有归档。
- 归档在磁盘上可直接离线拷贝复用；不需要额外配置开关。
- 人工核对归档内容时，用标准解包命令展开到临时目录查看，不要解到仓库树内：第三方源码会被
  测试收集器与静态检查扫到，归档本身也因此保持单文件形态。

## 文件职责

| 文件 | 职责 |
|---|---|
| `bench.json` | 夹具规格：项目分支的获取配方与身份 |
| `archive.py` | 归档契约：规格解析、目录布局、元数据、摘要校验、只读冻结 |
| `fetch.py` | 获取：生产抓取服务抓文档、生产仓库管理克隆源码，导出成归档后才丢弃临时层 |
| `build.py` | 离线回放：归档正文 → 净化分块落库，归档源码 → 解析挖掘，产出数据集与清单 |
| `judgments.json` | 判定集：按夹具标识分组，查询、类型（qualified/semantic/cjk/absent）、调参/门禁划分、期望目标 |
| `evaluate.py` | 方法矩阵、专项探针、门禁检查与报告生成；`--suggest-gates` 按本次测量打印建议下限 |
| `metrics.py` | 纯排序指标：分级 nDCG、Recall@k、MRR@k、空结果率、重复率、配对重采样区间 |
| `fakes.py` | 两种向量与重排端点：确定性离线替身，以及读环境文件的真实模型（`--real`） |
| `gates.json` | 版本化门禁：修订绑定、全文路 test 分栏下限（读未降级行）、弃答下限与误弃答上限、全方法结构不变量、真实模型下的融合与精排下限（`real_floors`）、跨语言方向下限（`cross_lingual_floors`，只读召回） |
| `sweep.py` | 参数扫描：检索期旋钮复用数据集，索引期分块旋钮各自重建数据集 |

## 方法矩阵与门禁口径

- `precise`：生产全文单路，代表性路径，两种模式下都进入绝对下限门禁。
- `fused` / `fused_rerank`：生产融合与重排接线。默认跑确定性替身，只受结构不变量约束
  （结果不得出现重复材料）；加 `--real` 时改用 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`
  （密钥取自仓库根环境文件，缺失即报错），此时融合与精排一并进入 `real_floors` 下限。
- **分级相关**：判定目标按命中形态分两级——命中点名的那一节记 2 分，只命中目标页但落在别的
  小节记 1 分，其余 0 分。nDCG 用分级增益，召回仍是二值（等级 ≥1 即命中）：召回回答
  "够不够得着"，nDCG 回答"排得好不好"。源码语料的块路径就是文件路径，所以等级只有 1/0，
  分级差异全部来自文档语料。
- **调参与门禁分栏**：每条判定带 `split`（`dev`/`test`），按夹具与类型分层对半划分。门禁只读
  `test` 分栏，扫描只读 `dev` 分栏；报告两栏并列。判定集缺任一侧或某个类型没有留出查询时，
  评测在加载阶段直接失败，不会悄悄退化成零条。
- **区间与显著性**：报告给出按查询重采样的 95% 区间；扫描表对每个变体给出与默认值的配对差值
  及其区间，区间跨零即标注"不显著"。两查询的换位在小夹具上就值 0.1，没有区间时这类移动会被
  读成改进。
- **无答案两类度量**：`absent` 同时报"空结果率"（有没有返回结果）与"弃答率"（证据判定是否
  拒绝作答），后者才是生产行为；非 `absent` 查询的"误弃答率"给弃答设上限——只测前者时，
  一个对什么都弃答的检索器能拿到满分的无答案指标。检索没有返回任何结果的查询不计入误弃答：
  那时弃答是唯一正确答案。
- **下限怎么来**：`--suggest-gates` 按本次 `test` 分栏测量打印建议下限（比测量值低两查询的
  口径，小夹具自动放宽），弃答下限取各方法族的最小值再减 0.15。脚本不写门禁文件：冻结是人
  的判断，会自动改写的下限不再是门禁。
- 探针在每类语料的首个夹具上跑（文档类：材料预算、置信度、查询整形、首位保留；
  源码类：副表加载成本），报告标出所属夹具。池级三分（目标在 topk 内 / 在池内但掉出
  topk / 不在池内）在全部夹具的 fused 行上直接给出，不另跑检索：聚合丢分才归因到聚合方式。

## 扩展

- **加项目分支**：在 `bench.json` 加一条（项目、分支、身份、配方），跑 `fetch.py`，
  在 `judgments.json` 加同名的判定集键，在 `gates.json` 补该夹具的修订与下限。
  新夹具声明 `tier`（`main` 缺省；`pool` 只做源码分支、无判定集、不评分不进门禁，
  用于无答案与跨库消歧的干扰材料）与成本预算（源码 `max_files`、两类 `max_build_ms`），
  超限构建直接失败。有 `path_prefixes` 的文档夹具构建时断言每页路径落在前缀内。
- **判定集**：`targets` 用绝对 URL（文档）或仓库内相对文件路径（源码），可给多个等价目标；
  `heading` 用标题子串进一步收窄文档命中，并决定该条的最高相关等级。每条带 `query_lang`
 （`zh`/`en`，查询自身的语言）与可选 `scope`（`scoped` 缺省，或 `global`：检索时不带库
  作用域，`targets` 须写完整地址，用于跨库消歧）。类型分四类：`qualified`（点名符号
  或 API）、`semantic`（描述意图）、`cjk`（跨语言查询）、`absent`（语料里没有答案）；
  前三类计入召回与 nDCG，`absent` 只看空结果率与弃答率。每个夹具要求有答案查询
  不少于 40 条，当前 377 条（八个夹具 45–50 条，含无答案与 16 条全局查询）。
- **真实模型运行**：`--real` 直接调用生产传输层，不落快照文件；每次运行都会重新编码全部
  向量道块（约 49553 块），耗时按端点速率决定。
- **跨语言查询**：方向由（`query_lang`，夹具 `corpus_lang`）二元组读出来，报告按方向分栏
  （如 `zh->en`），两者失败原因不同（词表不共享 vs 分词与展开），不共享同一行。
  全文单路在结构性不匹配时明确降级：状态置 `cross_lingual`，该行不计入全文路召回失败。
  判断证据是否充分时，查询与语料不共享书写系统会被记为不可测量并停在"弱"档，
  因此跨语言查询不会被误判为"语料里没有答案"。跨语言下限只在真实模型下进门禁
  （`cross_lingual_floors`，缺省即只报告）：离线替身跨书写系统没有共同词项，测的是替身。
- 设计依据与后续扩展方向见 `docs/bench/`。
