**打分尺度**（最小 / 中位 / 最大）：

| 语料 | 全文单路 | 融合 | 融合加精排 |
|---|---|---|---|
| 文档 | 4.52 / 19.49 / 69.48 | 0.032 / 0.043 / 0.067 | 0 / 0.273 / 1.000 |
| 源码 | 5.54 / 12.58 / 22.23 | 0.020 / 0.039 / 0.070 | 0 / 0.252 / 1.050 |

**融合对全文首位页面的保留**：13/14；符号式 0/5 丢失、语义式 0/7、中文式 1/2（D11）。

**查询整形变体**（文档语料）：并集 0.643 / 0.381；全词必须命中 0.071 / 0.071。

**材料预算单位**：配置单材料 1500 字符、总预算 6000 字符；实测单次材料中位
2329 字符、1178 估计令牌，最大 1634 估计令牌，令牌字符比 0.49，中位被丢弃材料 0 条。

**置信度策略**：33 个回放用例（正确引用 / 错误引用 / 不引用），11 个错误引用被判为高置信
（误报率 0.333）；正确引用时全部为高置信。

**块标识与重复率**：源码块标识重复 634 行 → 纳入成员限定名后 50 行（剩余为分组标识重名，
同页同标识最多 10 行）；同时文档语料结果重复率由 0.057 降为 0。

**全文统计作用域**：同一代码同一参数下，文档单语料库全文单路 MRR 0.395，文档加源码混合库
0.381。全文排序统计作用于整张全文表，语料混合会改变 BM25 排序。

## 六、结论

1. **检索链路机制正确**：结果重复率为 0（同源孪生已去重）、融合保留全文首位 13/14、
   三个方法在源码语料的符号式查询上满分，精确路在文档语料 0.64 召回。没有发现接线错误。
2. **三个结构性问题成立且有量化证据**：打分尺度三档相差约三个数量级；置信度"有引用即高置信"
   在三分之一回放用例上误报；挖掘副表按版本整取，每次查询装配 131 个聚类集合且与条数上限无关。
3. **语料范围决定结论**：自指的历史与方案文档（大量讨论检索本身）会把全文单路拉低 0.07 召回、
   把融合保留从 13/14 拉到 11/14。基准语料必须固定为稳定子树，数字才有当门禁的意义。
4. **全文统计是全局的**：同一份文档在"单语料库"与"混合库"里 BM25 排序不同（MRR 0.395 与 0.381）。
   跨库比较分数或阈值时必须固定库内容，否则差异来自统计而非检索逻辑。
5. **参数敏感度分层明显**：真正改变结果的只有分块上限、融合平滑常数与向量权重、召回预算、
   精排深度；组装窗口、向量泳道上限、标题权重、挖掘 alpha 在本判定集上无差异。
6. **替身嵌入下的"越小越好"不可外推**：召回预算调小、精排深度调小都略微提升指标，
   原因是替身精排与替身嵌入偏弱，缩小窗口等于减少噪声；这不能作为真实模型下的结论。

## 七、参数设置建议

| 参数 | 现值 | 实测证据 | 建议 |
|---|---|---|---|
| `fts_w_title` | 5.0 | 1/5/10 三档指标完全一致 | 保持；标题权重在本语料无可测影响，改动无依据 |
| `fts_w_path` | 3.0 | 8.0 时 MRR +0.018，1.0 时 −0.004 | 保持；提升幅度不足一次评测噪声 |
| `fts_w_content` / `fts_w_url` | 1.0 | 未单独扫描（作基准列） | 保持 |
| `rrf_k` | 20 | 10：文档 +0.024、源码持平；60：源码 −0.074 | 保持 20；若后续真实嵌入下仍需调，候选区间 10～20 |
| `rrf_w_fts` / `rrf_w_vec` | 1.0 / 0.5 | 向量权重 1.0：文档 +0.131，源码 −0.074；0.25：文档 +0.024，源码持平 | 保持；两条语料的最优方向相反，必须等真实嵌入快照后再定 |
| `candidate_multiplier` / `rerank_candidate_limit` | 3 / 30 | 倍数 1 时文档 `+0.071/+0.017`，源码持平；倍数 6 无收益 | 保持；缩小预算的提升来自替身噪声，且会压缩真实重排的候选池 |
| `assemble_multiplier` / `assemble_min` | 2 / 10 | 三档指标完全一致 | 保持；它只是组装上限保护，不是质量旋钮 |
| `rerank_top_n` | 10 | 深度 5 时文档 `+0.071/+0.026`；30 无变化 | 保持 10；接真实精排后按质量与延迟重测，再决定是否下调 |
| `rerank_truncate` | 500 | 未扫描 | 保持 |
| `freq_alpha` / `cluster_alpha` | 0.15 / 0.05 | 四档指标一致，仅最终分变化 | 保持；判定集需补"必须靠挖掘加权区分"的查询后才可标定 |
| `chunk_bm25_max_terms` / `min_terms` | 150 / 45 | 80/30：召回 +0.071、MRR −0.044、融合 −0.142；300/90：MRR +0.069、融合 −0.357 | 保持；150/45 是全文单路与融合的唯一平衡点，两端都会牺牲一条路 |
| `chunk_embed_max_tokens` / `min_tokens` | 512 / 150 | 320/96 与 800/200 差异在噪声内（±0.006） | 保持 |
| `material_limit` / `answer_total_budget` | 1500 / 6000 字符 | 单次材料中位 2329 字符 ≈ 1178 估计令牌，最大 1634 | 保持；若改令牌口径，按实测约 0.49 折算，总预算取 3000 估计令牌附近 |
| `retrieval_max_versions` | 8 | 未覆盖（语料单版本） | 保持；多版本扇出需另建语料 |
| `snippet_radius` / `snippet_cap` / `window_preview_cap` | 60 / 400 / 300 | 展示层参数，不影响排序 | 保持 |
| `retriever_expand_window` / `retriever_window_radius` | 关 / 1 | 展示层参数；问答链路已显式关闭 | 保持 |

## 八、未覆盖与下一步

- 真实嵌入快照：向量权重、向量泳道上限、语义召回质量三项必须等录制真实嵌入后再定。
- 回答级判定：置信度策略需要真实回答录制，当前只有策略回放。
- 多版本扇出：`retrieval_max_versions` 与版本方向需要多版本语料。
- 延迟基准：本轮耗时都是同进程相对值，含替身实现本身的开销，不能当性能结论。
- 挖掘加权判定集：需要构造"只有挖掘加权才能把正确页面顶上来"的查询，当前判定集不敏感。
