# 检索问答基准实测数据与参数结论

> 时间：2026-11-13（UTC）。数据由 `tests/e2e/bench/` 产生，脚本与判定集入库，
> 下载物、数据集与报告不入库。复现命令见篇末。
> 检索语义与降级口径见 `docs/features/` 相关各篇与 `docs/architecture/tech-stack.md`。

## 一、数据来源

语料用真实场景的获取工具下载，不用本仓库自身文件：

- **文档分支**：`fetch.py` 调用生产抓取服务（`IngestService.scrape_docs`，robots/sitemap 发现、
  逐主机退避、正文抽取、快照留存）抓 `https://www.python-httpx.org/`，sitemap 发现 23 页全部入库。
- **源码分支**：`fetch.py` 调用生产仓库管理（`RepoManager.ensure`，dulwich 浅克隆）拉
  `https://github.com/encode/httpx`，索引 `httpx/` 子目录。
- **构建**：`build.py` 离线回放下载物，走生产净化、双泳道分块、落库、解析与挖掘；
  下载物固定在 `fixtures/lock.json` 记录的抓取指纹与提交标识上。

| 项 | 文档分支 | 源码分支 |
|---|---|---|
| 库 / 版本 | httpx / docs | httpx / head |
| 规模 | 23 页、483 块（向量泳道 232、全文泳道 251） | 23 文件、1197 块 |
| 解析 | — | 739 实体、1558 调用 |
| 挖掘 | — | 33 条序列模式、243 行聚类 |
| 下载指纹 | 页面 URL 集合 sha256、抓取时间 | 提交 `b5addb6` |
| 构建耗时 | 1.5 秒 | 0.7 秒 |

两个分支是同一个库：库记录为 `httpx`（生态 `pypi`），版本分别是文档与源码，
查询按版本作用域评测，这正是"库知识库"的真实用法。

判定集：文档 14 个有答案 + 2 个无答案，源码 9 + 1；类型分符号式、语义式、中文式、无答案；
文档按绝对 URL（可给多个等价目标）+ 标题子串锚定，源码按仓库内相对文件锚定。

两种运行模式：离线替身（词袋伪向量 + 词覆盖重排，确定性、不联网）与真实模型
（`BAAI/bge-m3` 1024 维 + `BAAI/bge-reranker-v2-m3`，候选 30、保留 10、截断 500）。

## 三、专项探针

**挖掘副表加载成本**（源码语料，33 条序列、243 行聚类）：条数上限 5 时每次查询装配
0 条模式、45 个聚类集合，中位 443 毫秒；上限 20 时装配 1 条模式、45 个聚类集合，中位 458 毫秒。
聚类集合数与条数上限无关，装配量由版本整取决定；毫秒差值是查询向量的真实编码延迟。

**打分尺度**（真实模型，最小 / 中位 / 最大）：

| 语料 | 全文单路 | 融合 | 融合加精排 |
|---|---|---|---|
| 文档 | 4.22 / 12.32 / 33.48 | 0.040 / 0.076 / 0.095 | 0.000 / 0.150 / 0.995 |
| 源码 | 4.29 / 9.59 / 29.43 | 0.031 / 0.074 / 0.095 | 0.001 / 0.150 / 0.948 |

**融合对全文首位页面的保留**：13/13，符号式、语义式、中文式均无丢失。

**查询整形变体**：并集 0.786 / 0.550；全词必须命中 0.286 / 0.286。

**材料预算单位**：配置单材料 1500 字符、总预算 6000 字符；实测单次材料中位 2259 字符、
691 估计令牌，最大 1594 估计令牌，令牌字符比 0.31，中位被丢弃材料 0 条
（估算器已改为按字符类别计权，口径见 `docs/archive/token-estimation.md`）。

**置信度策略**：39 个回放用例，13 个错误引用被判为高置信（误报率 0.333）；正确引用时全部高置信。

## 五、结论

1. **真实语料推翻上一版的自指结论**。上一版用本仓库文档与源码做语料，融合召回低于单路
   （0.571 对 0.643）、向量权重 0.5 → 1.0 的效果被放大成 +0.357。换成第三方文档站与官方仓库后：
   文档融合召回 1.000、MRR 0.762（单路 0.857 / 0.625），源码融合 0.889 / 0.889（单路 0.778），
   向量权重 1.0 相对 0.5 的真实增益是 +0.084 MRR（文档 0.798 对 0.714）。
   **用自己当语料会把参数与质量结论整体带偏。**
2. **融合全面优于单路，且不再丢首位**。13/13 页面保住全文首位；文档空结果率由 0.071 降到 0，
   源码由 0.111 降到 0。
3. **中文查询只能靠向量路**。文档中文式全文单路 0.500 / 0.250，融合 1.000 / 0.750；
   源码中文式全文单路 0.000，融合 1.000 / 1.000（精排回落到 0.333）。这条能力完全来自跨语言嵌入。
4. **精排是有代价的收益**：源码融合 0.889 → 精排 0.787（召回 0.889 → 1.000，MRR 反降），
   即重排模型在符号查询上会把本来已经对的顺序打散；文档在本次数据集上精排前后一致。
   精排深度不能降到 5（文档召回掉到 0.929）。
5. **挖掘加权在本判定集上不可标定**：四档参数指标完全一致。结论与上一版相同，但这次是在
   外部真实工程上复现的，仍缺少"必须靠加权区分"的查询。
6. **分块预算差异在噪声内**：全文泳道 80/30 与 300/90 让融合 MRR +0.036，向量泳道 320/96 与
   256/80 让融合 MRR +0.036 与 +0.066、单路 +0.036，方向不一致且幅度一到两个查询，
   不足以改默认值（分块口径已随令牌估算改造，见 `docs/archive/token-estimation.md`）。
7. **三个结构性问题依旧成立**：打分尺度跨约三个数量级；置信度"有引用即高置信"误报 0.333；
   挖掘副表按版本整取，每次查询装配 45 个聚类集合且与条数上限无关。
8. **真实模型的分值存在提供方漂移**：同一查询向量两次调用间有约 1e-3 的差异，足以让近似并列的
   两条结果换位（D13 曾从第 1 位掉到第 2 位）。真实模式的门禁须留一到两个查询的余量，
   跨轮比较看同轮内相对差异，不看绝对分值。
9. **真实语料暴露了一个生产缺陷**：同一页面的两个小节在片段截断后渲染出完全相同的摘录
   （httpx 的 `api/` 页把同一段参数表重复列在 `Client` 与 `AsyncClient` 下），
   用户会看到两条一模一样的条目。已在装配层按"页面 + 摘录"去重，重复率回到 0。

## 六、参数设置建议

| 参数 | 现值 | 实测证据 | 建议 |
|---|---|---|---|
| `rrf_w_vec` | 1.0 | 0.25 / 0.5 / 1.0 / 1.5 的文档融合 MRR 为 0.699 / 0.714 / 0.798 / 0.762 | 保持 1.0（两路等权），不再上调 |
| `rrf_k` | 20 | 10 / 20 / 60 的文档融合 MRR 为 0.762 / 0.798 / 0.762，精排后三者相同 | 保持 20 |
| `rrf_w_fts` | 1.0 | 与向量权重成刻度关系 | 保持 |
| `fts_w_title` / `fts_w_url` / `fts_w_path` / `fts_w_content` | 5 / 1 / 3 / 1 | 标题 1/5/10、路径 1/3/8 全部零差异 | 保持 |
| `candidate_multiplier` / `rerank_candidate_limit` | 3 / 30 | 倍数 1 时文档融合 MRR −0.084；倍数 6 无收益 | 保持 3 / 30 |
| `assemble_multiplier` / `assemble_min` | 2 / 10 | 三档完全一致 | 保持；这是上限保护，不是质量旋钮 |
| `rerank_top_n` | 10 | 5：文档召回 0.929、源码 MRR 0.759；30 与 10 相同 | 保持 10；不得下调 |
| `rerank_truncate` | 500 | 未扫描 | 保持 |
| `freq_alpha` / `cluster_alpha` | 0.15 / 0.05 | 四档零差异 | 保持；先补判定集再标定 |
| `chunk_bm25_max_terms` / `min_terms` | 150 / 45 | 80/30 与 300/90 融合 MRR 均 +0.036，单路无差异 | 保持 |
| `chunk_embed_max_tokens` / `min_tokens` | 512 / 150 | 320/96 单路 +0.036、融合 +0.036；256/80 融合 +0.066 | 保持 |
| `material_limit` / `answer_total_budget` | 1500 / 6000 字符 | 中位 2259 字符 ≈ 691 估计令牌（比值 0.31，类别计权后） | 保持；若改令牌口径，按 0.25～0.85 折算取 2000～3000 估计令牌 |
| `retrieval_max_versions` | 8 | 未覆盖（同库两版本，未构造多版本扇出） | 保持 |
| `snippet_radius` / `snippet_cap` / `window_preview_cap` | 60 / 400 / 300 | 展示层参数；摘录去重按这两项的结果比对 | 保持 |
| `retriever_expand_window` / `retriever_window_radius` | 关 / 1 | 展示层参数；问答链路显式关闭 | 保持 |

门禁：全文单路两种模式都设绝对下限（文档 0.80 召回、0.58 MRR；源码 0.72 / 0.72），
真实模型运行时融合与精排另设下限（文档 0.95 / 0.70 与 0.95 / 0.70；源码 0.82 / 0.82 与 0.95 / 0.72），
余量按提供方漂移的一到两个查询留出；结构不变量为"结果集内零重复材料"。

## 七、未覆盖与下一步

- 回答级判定：置信度策略仍需真实回答录制，当前只有策略回放。
- 多版本扇出：同一库的文档与源码版本已具备，但未构造跨版本竞争查询。
- 挖掘加权判定集：需要"只有挖掘加权才能把正确页面顶上来"的查询。
- 语言覆盖：当前语料全英文（含中文查询），缺 CJK 语料与多语言工程。
- 延迟基准：耗时是同进程相对值，真实模型每次查询另加一次查询向量编码（约 0.2～0.3 秒）。
