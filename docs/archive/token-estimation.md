# 令牌估算口径的标定与改造

> 时间：2026-11-13（UTC）。对象：`src/libref/chunking/budget.py::estimate_tokens`（嵌入泳道预算单位）。
> 真值取样自 `BAAI/bge-m3` 的 `usage.prompt_tokens`，样本来自 `tests/e2e/bench/` 的真实下载语料
> 与本仓库中文文档，复现方式见篇末。

## 一、结论

旧估算按"拉丁词段 ×1.33 + 汉字 ×1"计，实测只有真值的 0.46～0.69，且误差随内容类型漂移：
同一份 `chunk_embed_max_tokens=512` 在英文文档上兑现约 740 令牌、在 Python 代码上约 1100 令牌、
在中文文档上约 1300 令牌。已改为按字符类别计权（字母 0.25、符号 1、空白 0.2、中日韩文字 1、
其他文字 1，向上取整），实测比值收敛到 0.96～1.04，"估算合格但真值超预算"的块从 5/60 与 6/60
降到 0/40 与 1/40。

## 二、旧口径的三处结构性偏差

| 偏差 | 后果 |
|---|---|
| 标点符号不计数（两个正则只抓字母数字与汉字） | markdown 表格、代码符号几乎免费，符号密集文本系统性低估 |
| 标识符按"词段"计 1.33，与长度无关 | 长标识符与短词同价，代码低估 54% |
| 空白不计数；汉字按 1、拉丁按 0.37/字符折算 | 语言之间的相对成本错位：中文块比同预算的英文块多装约 2 倍真令牌 |

`estimate_tokens` 原注写的是"只需单调、不必对齐具体编码器"，这在把它当相对刻度时成立；
但配置项叫 `chunk_embed_max_tokens`，用户按 512 调参时预期的是真令牌，因此"单调"不足以为预算命名兜底。

## 三、测量方法

- 真值：真实嵌入接口返回的 `usage.prompt_tokens`，逐块单独编码（批量接口只回聚合用量）。
- 语料级样本：`tests/e2e/bench` 数据集里文档与源码各取 60 个向量泳道块（等距抽样）。
- 类级对照：英文散文、中文散文、Python 片段、markdown 符号行各一段，长度 296～848 字符。
- 中文补充：本仓库 `docs/app/config.md` 中长度超过 200 字的 8 个自然段。

## 四、实测数据

单位字符成本（真值）：

| 样本 | 字符 | 真令牌 | 令牌/字符 |
|---|---|---|---|
| 英文散文 | 848 | 214 | 0.252 |
| 中文散文 | 296 | 251 | 0.848 |
| Python 片段 | 777 | 315 | 0.405 |
| markdown 符号行 | 304 | 183 | 0.602 |

分块级估算/真值比（60 块抽样）：

| 语料 | 中位字符 | 中位真令牌 | 旧估算（中位 / 总和） | llm-suite 式常数（中位 / 总和） |
|---|---|---|---|---|
| 英文文档 | 542 | 166 | 0.686 / 0.682 | 1.078 / 1.097 |
| Python 源码 | 415 | 148 | 0.460 / 0.453 | 0.930 / 1.010 |
| 中文文档（8 段） | 816 | 509 | 0.388 | 0.773 |

按类别对 120 个真实块做最小二乘（汉字系数用中文样本固定），得到该模型下的等效系数：

```
字母 0.23   符号 1.00   空白 0.16   中日韩 0.85   其他 1.00
```

拟合质量：总量比 0.977、单块中位 0.949、p10 0.85 / p90 1.07；独立样本校验 0.91（英文）与 1.01（中文）。

## 五、改造后的口径与表现

系数取整上浮（保证预算是上限而非期望值）：字母 0.25、符号 1、空白 0.2、中日韩文字 1、其他文字 1。
纯 ASCII 文本走正则计数快路径，含非 ASCII 时逐字符分类；`count_terms`（全文泳道）保持不变，
仍与 FTS5 切分对齐。

改造后同一批样本的估算/真值比：

| 语料 | 总和比 | 中位 | p10 / p90 | 估算合格但真值超预算 |
|---|---|---|---|---|
| 文档（40 块） | 1.043 | 1.063 | 0.93 / 1.14 | 0/40（改造前 5/60） |
| 源码（40 块） | 0.960 | 0.930 | 0.80 / 1.06 | 1/40（改造前 6/60） |

单测把四类样本与实测真值写进 `tests/unit/test_chunking.py`，比值限定在 0.75～1.35，
常数漂移会直接失败；另有一组用例断言符号比字母贵、中文比同长度字母贵、纯空白记零。

## 六、与 llm-suite 的对照

两者结构相同（按字符类别加权），差在常数标定对象：

| 类别 | llm-suite 默认 | 本模型实测 | 本次采用 |
|---|---|---|---|
| 字母 / 数字 | 0.25 | 0.23 | 0.25 |
| ASCII 标点 | 0.5 | 1.00 | 1.0 |
| 空白 | 0.5 | 0.16 | 0.2 |
| 中日韩 | 1.0 | 0.85 | 1.0 |
| 其他 Unicode | 1.0 | 1.0 | 1.0 |

照搬 llm-suite 常数在本次样本上的偏差：英文散文 +16%、中文散文 +18%、Python 片段 −16%、
markdown 符号行 −26%。原因是 bge-m3 的切分把标点几乎逐字符计费、把空格并入后词，
而 GPT 系分词器相反（空格自成一 token、部分标点合并）。结论是采纳分类结构、按本模型重标常数。

## 七、影响面

| 项 | 改造前 | 改造后 |
|---|---|---|
| 文档分支块数 | 453（向量 202 / 全文 251） | 483（向量 232 / 全文 251） |
| 源码分支块数 | 1145 | 1197 |
| 文档检索（真实模型） | 全文 0.857 / 0.625，融合 1.000 / 0.786，精排 1.000 / 0.804 | 全文 0.857 / 0.625，融合 1.000 / 0.762，精排 1.000 / 0.762 |
| 源码检索（真实模型） | 全文 0.778 / 0.778，融合 1.000 / 0.911，精排 1.000 / 0.843 | 全文 0.778 / 0.778，融合 0.889 / 0.889，精排 1.000 / 0.787 |
| 问答材料（中位） | 2725 字符 / 505 估计令牌（比值 0.19） | 2259 字符 / 691 估计令牌（比值 0.31） |

（召回 / MRR 口径，k=5；材料令牌列由改造后的估算器计算，故与字符不同。）

质量差异在一两个查询之内，与分块预算扫描"块长不敏感（±0.03 MRR）"的结论一致，说明本次是
预算口径修正而非质量修正。门禁随实测重设：全文单路不变（文档 0.80 / 0.58，源码 0.72 / 0.72），
真实模型下文档融合与精排 0.95 / 0.70，源码融合 0.82 / 0.82、精排 0.95 / 0.72。
所有版本需重建（分块边界改变），这是一次性成本。

## 八、实测中的方法论发现

真实模型模式下，同一查询向量在两次调用间存在约 1e-3 的漂移（`max_abs_diff=0.0013`），
足以让近似并列的两个结果换位：文档判定集里 D13 在两次连续评测中从第 1 位掉到第 2 位。
因此真实模式的门禁必须留出一到两个查询的余量，报告里的绝对分值只能按"±0.03 MRR"读，
跨轮比较要看的是同一轮内的相对差异。

## 九、复标定流程

1. 取样本：`tests/e2e/bench` 数据集按语料等距抽样，加上中英文对照段落。
2. 取真值：逐块调用 `EmbeddingClient.encode_with_usage`，读 `usage.prompt_tokens`。
3. 拟合：先由纯中文样本定汉字系数，再对拉丁/符号/空白做最小二乘，最后取整上浮。
4. 回写：常数在 `budget.py` 顶部具名常量，单测锚点同步更新；语料重建后跑基准与门禁。

## 十、本次不做

- 问答材料预算仍是字符制（`material_limit` / `answer_total_budget`）。实测英文 0.19～0.25、
  中文 0.62～0.85 令牌/字符，同一字符预算对中文用户只兑现约三分之一的令牌量。
  改为同一估算器的令牌口径会改变配置语义与既有语料的展示口径，单独决策。
- 逐模型预置常数表：当前只服务 `BAAI/bge-m3`，换模型按第九节重新标定即可，不做并行预设。
