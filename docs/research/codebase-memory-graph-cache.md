# codebase-memory-mcp：大规模图遍历的内存邻接层

参考位置：`ref/codebase-memory-mcp/src/store/graph_mem.h`。

## 问题

在 850 万节点、1690 万边的索引上，SQLite 上的递归 CTE 图遍历耗时约 6.6 秒；带度过滤的 `search_graph` 约 3.9 秒，而同等问题在 django 规模索引上只需 20–100 毫秒。瓶颈在 B-tree seek，不在结果组装。

## 设计

- 一次顺序扫描覆盖索引，把边装入按类型内部化的 typed CSR：节点 ID → 入/出邻居 + 边类型。
- 节点行仍留在 SQLite；内存层只保存边结构。
- 缓存层键为 `(db path, version)`，版本由 store generation 和 rollback journal 状态共同确定，避免读到不同边集。
- 进程级 registry 用引用计数共享缓存；总内存有预算上限，超限不构建并回退 SQL 路径。
- 空闲驱逐按时间触发，不设定时器线程；构建失败不留部分缓存。
- 查询原语是带类型掩码的 BFS 和度数统计，返回 `(node_id, hop)`，最短跳数语义与 SQL 版一致。

## 对本项目的意义

libref 当前图通道先用 SQLite 事实表做惰性邻接读取，保持真相单一。若后续图谱规模让递归查询变慢，可增加可重建的进程内邻接缓存，但必须：

- 缓存键包含库版本与事实表水位；
- 超预算回退 SQL 路径，而不是截断真相；
- 保留边类型掩码、深度、节点数和扇出上限；
- 不把缓存内容写成新的真相表。
