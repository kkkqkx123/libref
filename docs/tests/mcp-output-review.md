# MCP 工具返回内容核查设计

目标是补上出口层的内容验证：服务层已有行为测试，但模型看到的是 MCP 工具返回的载荷。本设计用真实 MCP 服务器、确定性种子库和落盘文本，让人工逐项确认返回内容是否符合预期；不把人工核查混进自动门禁，也不新增业务实现。

## 范围

覆盖当前全部二十七个工具，按检索问答、阅读目录、发现解析、探查、源码洞察、治理与索引申请分组。每个工具至少记录一次正常返回；存在明显参数约束时再记录一次错误载荷。需要真实网络或真实仓库的探查用例默认跳过，输出里明确记为环境不可用；显式开启后才执行并写入同一份文件。

## 种子数据

用同一份临时 SQLite 库构造可手算的场景：一个文档库版本含多个块、节与链接边；一个源码库版本含实体、调用、导入边、挖掘模式、特征树、分组与标签；注册表与发现缓存预置固定候选；预置待审调用、任务与依赖行。写入仅通过现有服务入口与必要的测试种子语句完成，随后构建真实 MCP 服务器。

## 运行状态

默认离线，不使用真实注册表、向量后端与语言模型。向量后端禁用，问答缺模型时返回不可用原因，正好用来核查失败语义。每次调用前设置明确的主体：只读主体用于读工具，开发者主体用于反馈，审核主体用于审核与审批，申请主体用于索引申请。调用经 MCP 协议入口发起，返回结构化载荷原样落盘，不改写字段。

## 输出与核查

输出到 `tests/e2e/outputs/mcp/`，一个工具一份可读文本，附汇总与核查说明。核查时对照README逐组确认：检索看预设、降级与可答性；问答看引用编号与不可用原因；阅读看三种模式的边界标记与块序号；发现看候选字段与来源；探查看预算提示与限定回显；洞察看视图语义、行字段、分页与过滤；治理看状态流转、错误信封与审计副作用；索引申请看下一步工具、终态建议与审批约束。网络用例的缺口在汇总中列出，不视为通过。

## 落点

生成入口是 `tests/e2e/render_mcp_outputs.py`，核查说明放在 `tests/e2e/fixtures/mcp/README.md`。集成测试用临时目录调用同一入口，确认每个工具都有落盘结果且核心返回不是错误信封。输出目录沿用端到端忽略规则，不入库。

## 配套收口

解析与抓取审查输出补充生成时间和清单标签，避免历史产物无法追溯；Python 采样补进端到端仓库索引用例；真实模型连通脚本修正为现有语言模块路径；架构文档的工具清单与代码对齐。这些改动只修现状，不建立并行模块。
