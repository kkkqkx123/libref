# 解析验证设计：源码抽取与文档链路

范围是源码抽取与文档抓取分块两条链路的实际效果验证，不含问答。
写法约束是只改原模块，不建替代模块，设计文档只用自然语言描述。

## 目标

用真实第三方仓库与真实文档站点，检验声明抽取、别名解析、调用消歧，以及页面抓取、净化、分块在常规写法下的可用性。
单元层保证离线可重复，网络层隔离到专用目录，默认不影响常规测试。

## 项目选定

源码 Python 选用本地已有的爬虫框架核心包。
理由是文件规模适中，异步、装饰器、相对导入、包内重导出等写法齐全，且离线可用，无需联网。
不选用大而全的索引框架，因为文件数过多且含大量示例笔记，解析耗时大，结果难收敛。
不选用抽取引擎自身的蓝本仓库做主验证，因为同源验证容易循环论证，只适合做一致性旁证。

源码 JavaScript 选用小而典型的命令行解析库。
理由是同时提供模块导入与共通导入写法，类加链式调用密集，异步与动态导入齐全，许可证宽松，文件数少，适合做端到端抽取。
不选用本地文档服务仓库，因为该仓库以类型脚本为主，后缀与当前抽取器支持的后缀不一致。
单元层仍用顶层夹具覆盖导入别名、箭头函数、对象方法等边界写法。

源码 Java 选用小而典型的对象映射库。
理由是泛型、注解、内部类、枚举、重载、构造器调用齐全，结构规整，许可证宽松，规模适中。
本地暂无完整 Java 仓库，只有单个示例文件，因此完整仓库验证必须走网络，纳入端到端目录。
单元层用顶层夹具与查询黄金样例覆盖继承、实现、通配导入、接收者归属。

文档选用连通性基线单页站点加一篇栏位丰富的真实文档页。
理由是基线页几乎必然可抓，承担可用性下限门禁；富文档页含多级标题、代码围栏与表格，能检验净化与分块边界。
不选用大型文档站，因为页面过多、抓取耗时大、结果难收敛。
单元层用顶层文档夹具覆盖标题路径、围栏平衡、空块拦截等边界写法。

## 分层策略

单元层放在现有测试目录与顶层夹具目录，全部离线。
源码 Python 用本地爬虫框架核心包做受控采样，限制文件数与总耗时，断言声明与调用集合与标准库解析一致。
三语言边界写法用顶层夹具与查询黄金样例断言，不依赖网络。
文档用顶层文档夹具断言分块边界、围栏平衡与空块拦截，不依赖网络。
缓存指纹、别名作用域、置信分级、空结果拦截等行为在单元层固定。

端到端层放在测试目录下的专用子目录，允许真实网络。
源码做三件事：按固定提交拉取目标仓库，复用现有仓库索引入口全量解析，记录解析统计与置信分布。
文档做三件事：按固定地址抓取目标站点，复用现有抓取编放入口全量落库，记录结局分布与分块统计。
不断言精确个数，只断言结构不变量与可用性下限，例如无崩溃、增量复用生效、待定与空块比例在合理区间。
网络超时与失败只标记环境不可用，不视为解析回归。

## 网络纪律

凡涉及真实网站、注册表、代码托管拉取的验证，一律放入端到端子目录。
常规测试目录只允许模拟传输与本地回环，不得出现真实域名与外网拉取。
端到端默认跳过，需显式开启才执行，常规提交与门禁不受其影响。
目标仓库固定提交标签，目标站点固定地址版本，更新需同步说明，避免结果漂移。

## 度量与判定

单元层判定为精确相等，失败即回归。
端到端判定为区间与不变量，失败先区分环境抖动与解析退化。
源码三语言分别记录声明数、调用数、已抽取与推导与待定占比、空文件数、缓存命中数。
文档按站点记录抓取结局分布、入库页数、双路块数、空块丢弃数。
待定占比突增、崩溃、基线站点零入库视为阻塞，其余变化只记录不拦截。

## 落点

复用现有抽取、解析、缓存、分组、分块、抓取、落库与仓库索引入口，不新增抽取与抓取模块。
夹具扩展只加最小样本文件，不整体搬运第三方仓库，不镜像整站文档。
端到端 runner 复用命令行语义，报告与逐文件审查输出落盘为可读文本，不入库。
文档原始抓取体经快照存储留存本地，净化文本由导出步骤复用净化入口重新生成，
审查报告附原始与净化文件的对应索引，抓取时间与字节数只记录不设门禁。
