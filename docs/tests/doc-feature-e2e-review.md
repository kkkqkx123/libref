# 库文档特征端到端核查与判定集设计

目标是补齐文档特征挖掘的人工核查与效果验证：用离线确定性夹具走通生产派生链路，用冻结检索夹具的题目与评判验证实体对齐、块类型、覆盖、漂移与检索加权是否真的带来收益。本文只定验证方案，不新增业务实现。

## 一、现状与可行性判断

现有端到端目录已经提供两类可复用的形态：

- `render_usage_mining_outputs.py`：读 `fixtures/usage_mining/cases.json`，在临时库里生成实现、官方示例、文档片段与参考项目语料，调用生产挖掘与读模型，把结果写到 `outputs/usage_mining/`；集成测试用同一入口核查落盘。
- `tests/e2e/bench/`：真实第三方文档站与源码仓库的冻结归档，只有脚本、规格、判定集与门禁进版本库；`judgments.json` 的每题带 `id`、`type`、`split`、`query`、`targets`，已区分文档分支与源码分支，源码分支题目按仓库相对路径评判，文档分支题目按 URL 与标题锚点评判。

因此“效仿现有代码段召回提供题目和评判”的结论是：**题目与评判的组织方式可以直接借鉴，但不能把源码判定集原样当作文档特征真值。** 源码题目只判到文件路径，文档特征要判到块、实体、覆盖模式与一致性结论；源路径无法唯一推出这些值。可行做法是从源码分支题目中抽取限定符号名作为候选锚点，再由人工确认对应文档块与实体，冻结成独立的文档特征判定集。候选生成与真值确认必须分离，避免用被测实现自己生成真值。

## 二、当前资产复用结论

先盘点本地实际存在的资产，再决定离线夹具来源。不能把“设计上可复用”与“当前目录里已有数据”混为一谈。

| 资产 | 当前状态 | 复用结论 |
|---|---|---|
| `tests/e2e/bench/fixtures/` | 目录不存在或为空，`data/`、`outputs/` 也未生成 | 冻结归档尚未下载；归档层评测暂不可执行，默认离线层不依赖它 |
| `tests/e2e/snapshots/` | 本地有 `example.com` 与 `markdownguide.org/tools/bear/` 两页原始 HTML | 前者无标题、围栏与表格；后者有多级标题和表格，但语言标记代码块、废弃标记与 API 实体均为零；且快照目录被忽略，只能作为人工参考，不能当版本化夹具 |
| `tests/fixtures/docs/sample.md`、`sample.html` | 版本化离线样本，含标题路径、围栏、表格与 HTML 对应页 | 适合作为结构场景底座；围栏语言是 `bash`，会被示例抽取跳过，也没有 API 名与废弃标记，需要扩展 |
| `tests/e2e/fixtures/usage_mining/cases.json` | 版本化，含 `pkg.core.Service.create` / `run` 实现实体、一个 `doc_snippet` 源、社区模式与档案 | 最适合复用为 D3/D4 种子：把其中的文档片段物化成版本化 Markdown 页面，即可走通“文档块 → AST 调用 → 实体边 → 模式覆盖 → 一致性” |
| `tests/e2e/bench/judgments.json` | 版本化题目与评判，分文档/源码分支 | 复用题目结构与 `source_ref`，不复用源码路径作为文档特征真值 |

据此，离线夹具来源优先级固定为：**usage mining 实体与片段 → `sample.md` 结构骨架 → 现有快照中的可人工参考场景 → 冻结归档评测**。不能依赖未下载的归档，也不能把被忽略的快照提交成夹具。

如后续需要真实项目做效果验证，用仓库现有获取方法显式下载，不新增获取逻辑：

```bash
uv run python -m tests.e2e.bench.fetch
# 或只取一库：uv run python -m tests.e2e.bench.fetch --only httpx/docs
```

下载产物仍在被忽略的 `tests/e2e/bench/fixtures/` 中；评测报告需记录归档修订，门禁下限只在修订不变时有效。网络失败记为环境不可用，不视为离线回归。

## 三、验证分两层

### 离线确定性层（默认）

借鉴 usage mining 渲染器，新增 `tests/e2e/render_doc_feature_outputs.py`：读固定夹具、建临时库、调用生产服务、落盘可读报告。夹具由 `usage_mining/cases.json` 的实体与文档片段加上扩展后的 `sample.md` 结构场景组成。默认完全离线，不用网络、向量后端与语言模型；输出只供人工核查，不参与默认断言。集成测试只检查文件存在、汇总不变量与关键结果非空，不把人工判定写成单元测试。

### 冻结归档层（显式开启）

当前本地尚未下载 bench 文档归档，这一层暂不可运行。后续用现有 fetch 方法下载并构建后，新增独立评测入口 `tests/e2e/bench/evaluate_doc_features.py`，读取 `data/bench.db`，在真实规模的文档与源码分支上运行派生与检索对比。归档缺失时按环境不可用跳过；结果写到 `outputs/retrieval-bench/doc-features/`。这一层用于核对结果增强不改变排序，并记录派生证据质量，不标定加权门禁。

归档层若要让 AST 对齐生效，需要在建库阶段处理文档代码块：复用 `page_pipeline` 的共享代码块抽取与 `ingest_snippets` 入口，把归档原始正文中的围栏/HTML 代码块登记为 `doc_snippet` 语料源。该步骤只能调用生产入口或从中提取的共享函数，不在基准里重写解析逻辑。缺少代码块的库仍可验证规则匹配与检索加权，但对齐准确率不计入门禁。

## 四、夹具设计

新增目录 `tests/e2e/fixtures/doc_features/`，文件职责如下：

| 文件 | 内容 |
|---|---|
| `cases.json` | 库/版本、文档页清单、API 实体、社区模式、挖掘档案、预期不变量；形制对齐 usage mining 的 `cases.json` |
| `pages/*.md`、`pages/*.html` | 版本化固定正文：以 `sample.md` 的标题/表格骨架和 usage mining 的 `doc_snippet` 调用为基础，补齐语言标记围栏、参数小节、废弃标记、变更日志与跨页同实体；离线生成，不提交快照 |
| `questions.json` | 文档特征判定集；每题带来源、题目、稳定锚点、期望实体、期望块特征、相关等级与 dev/test 划分 |
| `README.md` | 生成命令、文件清单、逐项核查点与判定口径 |

`cases.json` 覆盖以下可手算场景：

- 一个页面含两段围栏示例，分别调用同一 API 的不同顺序，用于子序列覆盖与弱证据回退。
- 一个页面含参数表与返回值小节，用于 `params` 与 `return_hint`。
- 一个页面含废弃标记，用于 `drift` 判定与废弃排除过滤。
- 一个页面含变更日志标题，用于 `changelog` 块类型。
- 同名短名在两个包中各有一个实体，用于歧义丢弃。
- 一个页面无对应模式与实体，用于 `unknown` 而非猜测。

判定集条目字段固定为：`id`、`source`（`docs` / `code` / `cross`）、`source_ref`（bench 判定 id 或本地题号）、`type`、`split`、`query_lang`、`query`、`targets`（稳定锚点列表）、`expected_entities`、`expected_facets`、`expected_verdict`、`grades`。稳定锚点使用 URL、标题路径、块分组标识与限定符号名，不用 `documents.id`、行号或块序号；重新抓取或切换标签后仍可解析。相关等级沿用 bench 的强相关 2 分、一般相关 1 分，目标不命中为 0。

从现有题目生成候选的规则：

1. 文档分支题目直接继承 `query`、`targets` 与 `heading`，把 URL 与标题路径作为块锚点；实体字段先空置，按候选生成后人工确认。
2. 源码分支题目取目标路径上的实体限定名，生成“哪个文档示例展示了该 API”候选问题；目标路径本身不作为文档块锚点。
3. 跨分支候选必须同时有文档锚点与源码实体，才进入冻结流程；只有单边证据的题目标为草稿，不参与门禁。
4. 每题保留 `source_ref` 指回原判定集，便于追踪人工标注依据与后续归档修订变更。

## 五、输出设计

输出到 `tests/e2e/outputs/doc_features/`，沿用端到端忽略规则，不入库。文件名与核查点固定：

| 文件 | 核查内容 |
|---|---|
| `01-cases.txt` | 夹具身份、页面清单、实体、模式与档案，确认输入可手算 |
| `02-blocks.txt` | 每块的 facet 值、标题路径、围栏占比、废弃标记 |
| `03-links.txt` | 对齐边的匹配种类、置信度、证据样本，确认歧义被丢弃 |
| `04-coverage.txt` | 模式哈希、覆盖种类、支持度 |
| `05-consistency.txt` | `match` / `drift` / `unknown` 与证据指纹；模型关闭时说明为空 |
| `06-questions.txt` | 判定集条目、稳定锚点解析结果与人工期待，未解析锚点单独列出 |
| `07-ranking.txt` | 每题的检索排名、命中等级、结果增强关闭/开启两列 |
| `08-metrics.txt` | 对齐准确率、块类型一致率、覆盖率、漂移误报与 nDCG 差分 |
| `09-drift.txt` | 同库不同版本的 facet 与实体变化清单 |
| `SUMMARY.txt` | 各文件条数、锚点解析成功率、失败原因与不变量判定 |

渲染器只做参数解析、生产服务调用与结果格式化；指标计算复用 `tests/e2e/bench/metrics.py` 的排名与统计函数，不另写一套评分代码。视觉上让人工能横向比较：同一题目在加权关闭与开启时的排名是否变化、变化是否落在正确锚点上、是否只是噪声换位。

## 六、指标与门禁

判定集拆 dev 与 test：dev 用于选阈值和调档位，test 只用于最终报告与门禁。默认不冻结门禁；至少完成一次冻结归档回放后再把下限写入 `tests/e2e/bench/gates.json`，并绑定归档修订。

| 指标 | 口径 | 目标 |
|---|---|---|
| 实体对齐准确率 | 块级期望实体与 `doc_api_links` 的集合比较 | test ≥ 0.9 |
| 块类型一致率 | `block_type` facet 与人工期待一致 | ≥ 0.85 |
| 覆盖召回 | 期望模式出现在 `doc_pattern_coverage` 的比例 | 记录值，先不设门禁 |
| 漂移误报率 | 人工抽检 `drift` 样本中误判比例 | < 0.20 才允许默认展示 |
| 排序不变性 | test 上 nDCG@5 与 MRR@5 的配对差分及 95% 区间 | 结果增强关闭/开启必须完全一致，不作增益标定 |
| 过滤有效性 | 只要示例、排除废弃、仅对齐三类过滤后的命中率与结果数 | 记录值，用于确认过滤器不是空结果制造器 |

结果增强必须在同一池深、同一分块预算下比较，只切换 `doc_feature_annotation_top_n`；派生文本不得改变 score、候选池或名次。D3 只保留溯源与结果增强价值，不进入加权通道。

## 七、落点与实施顺序

1. 新增夹具目录与 `README.md`：复用 usage mining 实体与片段、扩展 `sample.md` 的结构场景；先冻结离线小场景，不依赖 bench 归档。
2. 新增 `render_doc_feature_outputs.py` 与 `tests/integration/test_doc_feature_outputs.py`，打通“夹具 → 生产服务 → 可读输出 → 不变量断言”。
3. 新增判定集生成器，从 `tests/e2e/bench/judgments.json` 产出候选题目；人工确认后写入版本化的 `questions.json`，草稿不进评分。
4. 需要真实项目验证时，用现有 `tests.e2e.bench.fetch` 显式下载归档，再新增 `tests/e2e/bench/evaluate_doc_features.py`，复用 bench 数据集构建与指标函数，支持归档回放与 dev/test 分栏报告。下载与回放都不进入默认提交门禁。
5. 完成一轮实测后再改 `gates.json` 与 `docs/bench/design.md` 的文档侧判定集说明；未实测前只记录目标值，不写门禁。
6. 更新 `tests/e2e/README.md`，补齐新增入口、输出目录与默认跳过规则。

## 八、边界

- 默认测试不联网、不调用模型；真实归档只在显式下载后使用，网络失败按环境不可用处理，不视为回归。
- 输出目录只供人工核查，断言只读不变量，不把人工判定写进单元测试。
- 题目与评判沿用 bench 的冻结归档语义：身份锚点、dev/test 划分、配对重采样与噪声带；不按项目复制评分逻辑。
- 生成候选题不替代人工真值；待审、冲突与被审核过滤的证据不进入冻结判定。
- 代码注释只描述实现意图，不引用设计文档编号。
