# 索引断点恢复与中途持久化

本文说明文档索引与代码索引的中途持久化与恢复逻辑：游标模型、两条索引链路的批推进顺序、向量水位语义、崩溃后重跑的行为。状态为当前实现。

相关代码：`services/infra/progress.py` 为游标唯一出入口，`services/docs/ingest.py` 为文档链路编排，`services/code/code_ingest.py` 为代码链路编排，`services/docs/scrape_sweep.py` 与 `services/ops/maintenance.py` 负责向量同步与集合校验，`services/infra/jobs.py` 与 `services/infra/version_lock.py` 负责任务心跳与版本互斥，`store/document_store.py` 与 `astminer/cache.py` 提供幂等写入与解析缓存。

## 设计原则

- 单表游标：恢复状态只放在 `ingest_progress` 一张表，每版本每分支一行，不另建 checkpoint 表。
- 计数偏移而非批次序号：`done` 是目标文件或地址计数，恢复从该偏移继续；批大小只影响分片，不影响落点，改批大小不需要失效游标。
- 幂等写入是恢复安全的基础：重跑已处理批次结果不变；游标滞后最多导致重复做功，不导致数据错误。
- 先同步派生索引、后推进游标：两条链路的批循环都在向量同步完成后才落游标，崩溃永不把游标推过未同步数据。
- 向量是派生索引：水位只记录派生同步进度，不作为源数据真相；一致性最终由集合校验兜底。
- 恢复前提是同一目标列表：指纹覆盖有序目标列表，列表变化则从头开始，不跳过错误区间。

## 游标模型

`ingest_progress` 主键为版本加分支，分支取值为文档或代码。行内字段含义如下：

| 字段 | 含义 |
|---|---|
| total/done | 目标总量与已完成计数，恢复偏移即 `done` |
| fingerprint | 有序目标列表的哈希，覆盖顺序与成员 |
| batch_size | 分片大小，只做记录，不参与恢复判定 |
| vector_done | 向量水位，主要用于展示，不作为恢复依据 |
| pending | 跟随抓取的前沿队列，存地址与深度二元组 |
| visited | 跟随抓取的已访问集合，排序后存快照 |

恢复判定规则：显式要求全新运行则清游标从零开始；无游标行从零开始；指纹不一致或总量不一致则清游标从零开始；一致时按记录偏移继续，偏移钳制在合法范围内。向量水位缺省时取游标值。

前沿队列兼容旧形状：历史行内存的是纯地址数组，读取时按深度零处理；新写入一律为地址与深度二元组。

## 文档索引恢复

文档链路分种子批与跟随两段，共用一个游标。

种子批按固定批大小推进，每批流程为抓取清洗入库、推送向量增量、落水位与游标。向量增量只做差量推送加计数回读，集合校验留到收尾。单页失败只记数，不中断本批。

跟随阶段的前沿队列与已访问集合在每轮子批次处理前持久化，恢复时按保存深度重新入队，未处理分片保留各自深度继续受最大深度约束。收尾阶段清扫实际访问过的页面缺席项，推送清扫增量并做集合校验（只告警不修复），记录站点版本证据，最后清除游标。

崩溃位置与恢复行为对照如下：

| 崩溃位置 | 恢复行为 |
|---|---|
| 批次入库前 | 该批次重跑，幂等写入保证结果不变 |
| 向量增量与落游标之间 | 游标未推进，该批次重跑 |
| 跟随轮次处理中 | 按持久化的前沿与深度继续，已处理地址去重跳过 |
| 收尾清扫或清除游标之后 | 下次为全量重跑，内容未变短路，向量保持已有状态 |

## 代码索引恢复

代码链路先做文件清点（排序保证确定性），恢复偏移按清点顺序切分剩余文件。

声明收集覆盖全部文件后全量刷新实体与导入边，因此实体层不需要恢复逻辑。调用实例与源码分块按批推进，每批流程为解析调用并增量写入、落分块、推送向量增量、落游标，同样先同步后标记。

恢复运行时先把库中现存调用身份载入存活集合，再累积本轮批次身份，最终清扫基于完整集合，不误删已跳过批次。源码页面清扫基于全量存活文件集合，不受偏移影响。

收尾阶段推送清扫增量并做集合校验与修复（默认开启），最后清除游标。向量同步失败只记数，不推翻源数据写入。

崩溃位置与恢复行为对照如下：

| 崩溃位置 | 恢复行为 |
|---|---|
| 声明收集阶段 | 游标尚未推进，下次从零开始，解析缓存命中，只付缓存查找成本 |
| 批次数据提交后、向量同步前 | 游标未推进，该批次重放 |
| 向量同步后、落游标前 | 该批次重放，幂等写入保证结果不变 |
| 清除游标之后 | 下次为全量重跑，调用全量写入后清扫，集合保持完整 |

## 向量水位与集合校验

向量同步分三档：批内差量推送默认关闭集合校验，只做计数回读；收尾调用默认开启集合校验，代码链路同时开启修复，文档链路收尾只告警不修复；嵌入模型或维度漂移时走整版本重建。

向量失败的语义统一为只记数、不致命：集合治理失败、删除失败、嵌入失败、校验失败都只累加失败计数并记录日志，不中断索引主流程。重放批次内容无变化时判未变更而不推送向量，缺口由收尾集合校验发现，代码链路由此修复。

## 中断、并发与心跳

- 版本锁保证同一版本同一时间只有一个写入者；持有者崩溃导致锁过期后，下次运行按过期接管语义继续。
- 任务队列记录心跳，超时未续的运行中任务标记为过期，不会无限占位。
- 抓取侧的页数预算在跟随阶段按已访问规模检查，超预算直接失败而不是静默截断；恢复后的前沿同样受该预算约束。

## 已知边界

- 已跳过区间内的文件内容漂移不在恢复覆盖内：该区间不再重解析，残留由全新运行消除。
- 文档链路收尾不做集合修复，向量同步崩溃留下的缺口在文档链路内不会自动愈合，需要模型漂移重建或外部修复触发。
- 游标本身没有心跳列：游标只在持有版本锁的运行起点读取，不需要独立心跳，超时恢复由任务心跳与版本锁承担。

## 测试

崩溃注入回归测试位于 `tests/integration/test_progress_resume.py`：调用集合在恢复重跑后与全量一致、跟随队列深度往返与旧形状兼容、向量同步崩溃后重跑的向量集合完整。向量同步行为由 `tests/integration/test_vector_sync.py` 覆盖。
