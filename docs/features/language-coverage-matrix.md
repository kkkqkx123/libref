# 语言特定内容覆盖矩阵

对象是源码抽取链路中按语言分层的实现，状态截至本次补齐后。
本表是后续修改的直接依据：凡未完整实现，一律在总览与分语言表中标记，
缺口细节只在缺口汇总一节描述，分语言表仅引用编号，不重复解释。

## 状态定义

完整指该层满足抽取规范且有断言覆盖，无已知缺口。
部分指该层可用但存在已编号缺口，缺口见缺口汇总一节。
缺失指该层整体未实现。
判定口径：语言本身无该形态时不记缺口，例如脚本方言无类型体不记缺口，
类型脚本缺失记为独立缺口；按规范有意裁剪的内容不记缺口，
集中在维持现状一节说明理由。

### c / cpp

C 与 C++ 使用独立 grammar wheel 与声明式语言配置：`.c` 归 C，`.h` 归 C++（C++ grammar 覆盖 C 头里的 C 构造，反向判断会把类与成员误判为自由函数和全局变量）。查询覆盖函数原型与指针返回函数、函数指针与函数引用、结构体、联合体、枚举、typedef、C++ 类与成员、宏定义与函数式宏、预处理条件、直接调用、成员调用和函数式宏调用。解析前对成对 `extern "C"` 守卫生成等长 shadow 源码，只中和两行花括号，行号、字节偏移与原文证据保持不变；不平衡形态原样交给 grammar。宏体只做低置信调用扫描，不做完整展开；包含链上的类型消歧仍未覆盖，参考项目挖掘时应用目标 API 前缀过滤。

## 缺口汇总

下表每行都是一项可执行的后续修改，含影响、改法与验收标准。
实现时按编号逐项关闭，并同步更新上表状态。

| 编号 | 语言 | 层 | 缺口描述 | 影响 | 后续修改 | 验证 |
|---|---|---|---|---|---|---|
| C01 | c/cpp | 调用 | 宏展开后的间接调用不可见 | 宏包装 API 的序列仍可能缺失 | 仅在宏体与宏参数内补低置信调用，不实现预处理器 | 宏包装示例的调用与证据断言 |
| C02 | c/cpp | 消歧 | 包含链上的类型与同名符号消歧有限 | 同名 API 可能落到错误实体 | 结合编译数据库与头文件实体表增强解析 | 同名符号差分夹具 |

## 维持现状

下表内容有意不做修改，后续如需重议，先更新本节理由再立新缺口，
不直接按缺口实现。

| 编号 | 范围 | 内容 | 理由 |
|---|---|---|---|
| W01 | go 调用 | 泛型实例化调用未抽取 | 实例化与下标在语法上不可区分，逐个捕获会把全部下标记为调用 |
| W02 | rust/c 调用 | 完整宏展开 | 只记录宏体与宏参数中可见的调用事实，展开后的间接调用无静态证据 |
| W03 | csharp 调用 | 委托调用与直接调用同形不区分 | 同形区分需要类型信息，超出当前两遍解析能力 |
| W04 | rust、java 依赖 | 类型约束与类型引用不进查询子集 | 抽取引擎无对应消费方，按规范裁剪 |

## 新增语言对照清单

登记前逐项确认：四段查询可编译；实体覆盖声明、继承、方法归属；
调用覆盖直接、成员、链式且接收者可拆分；依赖覆盖导入、通配、别名；
注释覆盖行与文档；别名覆盖末段与通配丢弃；
模块路径覆盖源码根剥离；消歧覆盖标准库前缀；
清单覆盖模块标识；夹具覆盖最小形状与空源。
对照中发现的新缺口按上表格式编号记入缺口汇总，
维持现状的裁剪记入上表并写明理由，不保留过渡逻辑。
