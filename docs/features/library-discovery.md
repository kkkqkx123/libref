# 库发现与模糊匹配

本文说明库发现的实现：入口、搜索扇出、模糊匹配的真实含义、排序规则、缓存与失败行为。状态为当前实现。

相关代码：`services/registry/discovery.py` 为编排唯一出入口，`crawler/registry/` 下各生态模块负责搜索解析，`crawler/github.py`、`crawler/websearch.py` 负责显式搜索通道，`services/factory.py` 负责装配。

## 入口

| 入口 | 形式 |
|---|---|
| 命令行 | `discover`（注册表扇出）、`search-web`（显式网页搜索）、`search-github`（显式托管搜索） |
| MCP | `library_search`、`web_search`、`github_search` |
| 问答编排 | 无结果时经 `library_search` 取建议，见服务端装配 |

`discover` / `library_search` 接受可选生态过滤。给定生态时只查该注册表；不给生态时按固定顺序扇出全部六个注册表（`npm`、`maven`、`pypi`、`go`、`crates`、`nuget`）。`search-web` 与 `search-github` 是独立通道，不参与注册表扇出，结果为未验证线索，调用方确认后以显式地址使用。

命令行参数校验：空查询报错；未知生态报错；条数限制为 1 至 100，默认取 `discovery_topn` 配置。

## 各生态搜索实现

| 生态 | 搜索地址 | 解析方式 | 精确命中增强 |
|---|---|---|---|
| 生态 | 搜索地址 | 解析方式 | 精确命中增强 |
|---|---|---|---|
| pypi | 站内搜索页 | HTML 锚点提取项目名、版本、描述 | 搜索为空时回退精确快照；命中项中与归一化查询相等者逐个取快照补全文档、主页、仓库、稳定版；非 200 响应一律视为降级 |
| npm | 注册表搜索接口（随制品基址走镜像） | JSON 对象展平，热度取月下载量或评分 | 精确命中取快照，失败则保留搜索级条目；搜索失败时回退精确快照，命中则单条返回 |
| maven | 检索服务 | Solr 文档展平为 `group:artifact`，热度取版本数 | 精确命中取快照，失败则保留搜索级条目；搜索失败时回退精确快照，命中则单条返回 |
| go | 模块文档站搜索页 | HTML 锚点提取模块路径 | 精确命中取快照；搜索无结果或有结果但无精确命中时追加精确尝试；文档地址默认为派生的模块文档页 |
| crates | 箱子搜索接口 | JSON 展平，含文档地址、主页、仓库 | 精确命中取快照，失败则保留搜索级条目；搜索失败时回退精确快照，命中则单条返回 |
| nuget | 注册查询接口 | JSON 展平，热度取总下载量 | 精确命中取快照补文档与主页；搜索失败时回退精确快照；发现阶段仓库地址恒为空，需仓库解析补全 |

要点：

- 搜索级条目只有搜索页给出的字段，文档与仓库多为缺省；只有归一化后与查询相等的名字才会触发一次快照补全，成功后来源从 `search:<eco>` 升级为 `registry`。
- 快照补全失败不影响该条目，只是不升级，继续以搜索级条目参与排序。
- 六生态搜索失败统一走精确回退：传输异常或服务端错误时先试精确快照，命中返回单条注册表级候选，未命中再报可重试；go 在有结果但无精确命中时也追加一次精确尝试，失败不影响已有结果。
- 搜索级地址与快照同等清洗：主页、仓库、派生文档页全部经统一清洗并尊重私有地址开关，清洗失败置空，不保留原文。
- 托管搜索仅在不限生态且配置了令牌时参与扇出，每次取前 10 条；显式 `search-github` 通道不限生态、无令牌也可调用。

## 模糊匹配的真实含义

本模块没有编辑距离或分词相似度计算。所谓模糊匹配由两部分构成：

1. **名称归一化**：查询按生态规则归一后再比较。各生态归一与精确解析共用同一函数：pypi 统一分隔符并小写，npm 小写，maven 去空白并要求 `group:artifact` 形态，go 仅去空白（路径大小写敏感），crates 与 nuget 小写。归一失败时回退为小写原文。
2. **确定性排序**：`rank_candidates` 按固定字典序排列，与模型无关。键顺序为：来源层级（注册表快照优先于搜索）、有无文档地址、有无精确相等、原生顺序、热度倒序；更新时间倒序做末位决胜，最新优先。

热度口径各生态不同：npm 取月下载量或评分，maven 取版本数，nuget 取总下载量，托管搜索取星数，pypi 与 go 搜索恒为零。跨生态比较热度只在前三键相同后才起作用，不代表跨生态真实流行度。

无仓库地址的条目统一附加一条提示：经仓库解析补全，或在代码索引前传入显式源。

## 缓存

`discovery_cache` 表以（生态域、归一化查询）为主键，存放排序后的候选 JSON 与抓取时间，可整体重建，不写 `libraries` 与 `versions` 表。

- 生态域为指定生态或 `*`；勾选预发布时后缀标记，隔离缓存。
- 新鲜缓存直接返回；离线模式只读缓存，缺失报可重试错误。
- `search-web` 与 `search-github` 各自以 `web`、`github` 为域走同一套缓存逻辑。

## 失败行为

- 单生态搜索失败计一次，不中断其余生态，失败原因按生态汇总；全部来源失败才报可重试错误，错误信息附带各源原因。
- 各生态搜索失败统一回退精确快照：命中则返回单条注册表级候选，未命中再报可重试错误；搜索页正常但无条目且精确快照缺失时返回空。
- 离线缺失、网络异常、服务端错误统一为可重试错误，由上层按“稍后重试或用暖缓存重跑”提示。
- 空查询、未知生态、条数越界、关闭发现开关均为参数错误，不进入搜索。

## 配置

| 配置项 | 含义 |
|---|---|
| `discovery_enabled` | 总开关，关闭后三通道均拒绝 |
| `discovery_topn` | 默认返回条数 |
| `discovery_cache_ttl_days` | 发现缓存有效期（天） |
| `discovery_offline` | 只读缓存，不触网 |
| `discovery_github_token` | 托管搜索令牌；扇出参与以此为准，请求头携带，不入库 |

## 分支覆盖

| 分支 | 行为 | 信息保留 |
|---|---|---|
| 新鲜缓存命中 | 直接返回，不触网 | 足够；无仓库提示重打且不污染缓存 |
| 离线有缓存 | 只读返回 | 足够 |
| 离线无缓存 | 报可重试错误 | 足够 |
| 单生态失败 | 计错并汇总原因，继续其余生态 | 足够；调用方可知哪家掉线 |
| 全源失败 | 报可重试错误 | 足够；错误信息汇总各源原因 |
| 搜索失败加精确命中 | 返回单条注册表级候选 | 足够；版本、文档、仓库来自快照 |
| 搜索失败加精确缺失 | 报可重试错误 | 足够 |
| 搜索成功但无精确命中（go） | 追加精确尝试，失败忽略 | 足够；已有结果不受影响 |
| 搜索级条目 | 直接参与排序 | 基本够；地址经清洗，私网置空，未验证不编造 |
| 快照补全失败 | 保留搜索级条目 | 足够 |
| 排序同分 | 更新时间最新优先 | 足够 |
| 参数错误 | 空查询、未知生态、条数越界、开关关闭均拒绝 | 足够 |
