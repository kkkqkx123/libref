# 探查与范围选择

本文说明两套探查工具与范围策略的实现原理与功能：探查在写入前做什么、不做什么，范围取舍按什么顺序判定，探查结论与真实抓取或索引行为如何保持一致。状态为当前实现。

相关代码：`services/docs/probe.py` 为文档探查唯一入口，`services/code/probe.py` 与 `services/code/probe_remote.py` 为源码探查唯一入口，`services/docs/scrape_plan.py` 的目标规划为探查与抓取共用，`crawler/scope.py` 为范围策略，`crawler/url_seeder.py` 为文档发现器。三出口（命令行、模型、网页）只做参数透传与校验，不重复实现分支逻辑。

## 入口

| 入口 | 文档探查 | 源码探查 |
|---|---|---|
| 命令行 | `probe-docs` | `probe-repo` |
| MCP | `doc_probe` | `repo_probe` |
| 网页 | `POST /doc-probe` | `POST /repo-probe` |

两套探查均为只读：文档探查不取正文、不清洗、不分块、不落库；源码探查不解析任何文件、不写仓库表。调用方应先探查确认范围，再提交抓取或索引任务。

## 设计原则

探查与执行共用同一发现器与同一范围策略，探查在取到目标列表后即止，抓取或索引从同一目标列表继续向后走。目标数量超过预算时抓取侧直接失败而不是静默截断，探查侧则把超预算标记在返回体里并照常给出实际规模，让调用方收敛范围后再提交。远端仓库按从便宜到贵的顺序逐级降级，每一级失败都进下一级，只有最后一级才抛错。

## 文档探查链路

文档探查分三步：发现、规划、采样头读取。

发现器按固定优先级尝试三类来源：先读站点的 `llms.txt` 系列，命中则以其为准；无命中则读站点地图（含索引与压缩包形态，递归展开）；仍无结果则读订阅源。任一来源内部按候选地址逐个取文本，失败的候选只记错误不中断整体。发现成功后按固定顺序做五层过滤：丢弃无意义地址，按后缀预判拒绝二进制等多媒体形态，跨站地址移入跨站清单，机器人协议逐条检查，存活预筛逐条做存活探测。剩余地址按文档身份去重后，再按查询词打分过滤与排序，最后做页数预算检查。

规划函数把三类候选拼在一起：调用方显式给出的单页地址、发现器接受的地址、跨站清单中未重复的地址。拼好后走范围策略逐条判定，通过后再按文档身份去重。若全部被拒绝且起始页自身符合策略，则回退到只抓起始页，保证单页站点可用。查询词非空时先按分数阈值过滤再按相关性排序，阈值只在调用方显式给出时生效。

采样头读取只针对接受列表的前若干地址，用区间请求头取每个页面前 64KB，并发上限为 4。只解析响应头中的内容类型，标题只从 HTML 头部提取，单地址失败只记录错误不抛错，返回顺序与采样顺序一致。

## 文档探查返回体

| 字段 | 含义 |
|---|---|
| source | 发现来源，取值为站点描述文件、站点地图、订阅源或无来源 |
| total_discovered | 发现器接受的地址数，范围过滤之前 |
| accepted/rejected | 范围策略接受与拒绝的地址数 |
| truncated | 发现阶段或来源侧发生截断 |
| failed | 未发现任何地址且发现过程遇到传输失败 |
| cross_site | 跨站清单长度 |
| max_pages/budget_exceeded | 调用方给的预算与是否超预算，超限不抛错 |
| follow_links/follow_expansion_unknown | 是否开启页内跟随，开启时实际抓取规模可能继续膨胀，探查无法预知膨胀量 |
| prefix_groups | 接受地址按两级路径前缀分组计数，最多 20 组 |
| samples/sample_details | 接受地址采样与每条采样的状态码、内容类型、标题或错误 |
| errors | 各来源候选地址的失败原因 |

## 范围策略

范围策略由起始地址加显式选项构造，缺省为同站策略：只接受与起始地址同主机的地址，跨站一律拒绝。显式选项全部为加法收紧或显式放行，不给即保持缺省。

判定按固定顺序执行：协议必须为网页协议；主机必须通过同站或子域检查；后缀黑白名单先看白名单，有白名单时只接受名单内后缀，否则拒绝黑名单内后缀；路径前后缀限定要求前缀命中其一、后缀命中其一；正则黑名单命中即拒绝，白名单非空时要求至少命中其一；最大深度限制相对起始地址所在目录的下探层数。

各选项含义：跨站放行允许全网，子域放行允许同域子域，路径前缀与后缀限定站点子目录形态，正则黑白名单处理白名单之外的特例，最大深度约束目录下探。额外单页地址同样走策略判定，不在策略内的单页会被拒绝并计入拒绝数。查询词与分数阈值不属于策略本身，由规划函数在策略之后执行。

## 查询词打分

打分只看地址文本：查询词分词后统计在主机与路径中的命中比例，路径越深略有惩罚，无命中得零分。规划与发现器共用同一打分：阈值过滤在前，相关性排序在后，空查询保持发现顺序。探查把查询词与阈值透传给发现器，与抓取的发现调用对齐，因此两边看到的候选一致；规划函数再对拼好的候选做一次同口径过滤，保证调用方显式单页同样受阈值约束。

## 预算与跟随

页数预算在抓取侧为响亮失败：候选超限直接报错，不做截断抓取。探查侧接受同样的预算参数，但只标记不抛错，调用方按返回的实际规模收敛范围。页内跟随只发生在抓取阶段，探查不取正文因而无法展开跟随；开启跟随时探查如实回显开关并提示膨胀未知，调用方不应把探查规模当作跟随抓取的规模上限。

## 源码探查链路

源码探查只做目录普查：统计候选文件、跳过与超大文件，分组计数，取采样，读清单依赖。本地路径直接遍历，远端地址走分级获取，两种形态汇合到同一份文件清单后再做单文件限定与预算判断。

文件清单只收录抽取引擎支持的后缀，子目录限定按相对路径前缀过滤。清单之外另计两类数量：命名上应跳过的路径，以及超过单文件字节上限的文件，两类都不进入有效文件。单文件限定按相对路径精确匹配，先过滤再做预算判断，未命中的限定路径逐条回显。预算超限直接抛错，与索引侧的预算语义一致。

清单依赖只在拿到本地目录时读取：合并包清单与构建脚本两类声明，最多 50 条。远端走托管接口或无 blob 树时没有本地目录可读，依赖为空。

## 远端分级

远端按从便宜到贵逐级尝试：命中新鲜的复用槽直接复用，无需任何网络；托管接口按目录清单接口取文件列表，无需传输对象；无 blob 树只做裸克隆并在库内走树统计目录元数据，不下载文件内容；最后一级做浅克隆并放入复用槽。每一级失败都降级到下一级，只有浅克隆失败才抛错。复用槽按归一化地址哈希定位，命中且新鲜时更新时间戳；时间戳更新失败视为过期而不抛错。

返回体标注数据来源与尺寸是否已知：托管接口中只有部分实现带文件尺寸，无尺寸时超大文件无法预判，尺寸已知标记为假。来源侧截断同样透出。

## 缓存

文档与源码各持一份进程内缓存，上限 64 条，超时按探查缓存有效期配置。文档缓存键包含起始地址、范围全文、采样数、头读数、预算与预筛；源码缓存键包含归一化地址、子目录、预算、采样数与单文件限定。归一化去掉首尾空白、`git+` 前缀与末尾斜杠，同一仓库的多种写法命中同一缓存。旧缓存在参数变化后自然失效，不做兼容。

## 分组与采样

文档前缀分组取路径前两级，根路径单独成组，按数量降序、名称升序取前 20 组。源码目录分组取相对路径首段、无目录文件归入根桶，后缀分组按扩展名计数，同样各取前 20。采样取有效文件的前若干条，条数缺省跟随探查采样上限配置。清单依赖最多 50 条。

## 与抓取或索引的对应

| 抓取或索引参数 | 探查是否镜像 | 说明 |
|---|---|---|
| 存活预筛 | 是 | 透传给发现器 |
| 查询词与分数阈值 | 是 | 透传给发现器，规划再做一次同口径过滤 |
| 路径前缀 | 是 | 透传给发现器用于来源选择 |
| 全部范围策略选项 | 是 | 同一策略同一判定 |
| 页数预算 | 标记而不抛错 | 抓取超限失败，探查超限标记 |
| 页内跟随 | 仅回显 | 探查无法展开，只提示膨胀未知 |
| 子目录限定 | 是 | 同一前缀过滤 |
| 单文件限定 | 是 | 先过滤再判预算，与索引顺序一致 |
| 文件数预算 | 是 | 同样响亮失败 |
| 取正文、清洗、分块、落库、解析 | 否 | 探查在目标列表处停止 |

## 配置

| 键 | 含义 |
|---|---|
| probe_sample_limit | 采样与样本详情的默认条数 |
| probe_fetch_sample_limit | 头读取的默认页数，0 表示禁用 |
| probe_fetch_timeout | 单页头读取超时 |
| probe_cache_ttl_hours | 探查缓存与复用槽新鲜度共用有效期 |
| follow_links_default | 未显式指定时页内跟随的默认值 |
| seeder_cache_ttl_hours | 抓取侧发现器缓存有效期，探查侧用探查缓存有效期 |
