# 符号与关系数据利用缺口与改进方案

> 依据：当前 `astminer/engine`、`astminer/resolution`、`services/code` 摄取落库与 `mining/store` 读取链路的实测盘点。
> 目标：抽取已有的符号与关系信号全部落库可查，下游挖掘与检索按需消费，不再解析一次丢一次。
> 范围：只改 `astminer/` 模型与缓存、`db/schema` 与迁移、`services/code` 摄取与读写、`mining/` 纯算法的输入形状；不改抓取分支，不改向量与问答主路，不新增出口。
> 约束：只修改原模块，不建替代模块；新增表与新增文件仅按职责拆分命名；不做任何向后兼容，历史库重跑重挖；代码注释只写意图，不引用本文编号。

## 1. 现状盘点

抽取侧是完整的：单文件产出声明、别名、原始调用三类记录，声明带限定名、种类、父子、签名、参数名、参数类型、返回类型、基类、字节区间、文档有无，调用带原始被调串、实参摘要、调用者、接收者、函数名、实参数、行与字节区间。解析侧也是完整的：全库声明索引、逐文件别名表、后缀索引、父子链、形参表、形参类型表、基类表、返回类型表，共同产出解析后被调名与三级置信，并编出调用序号。

落库侧开始丢失：符号表存了父、签名、参数名、基类、起止字节、深度，但丢了文件、行范围、参数类型、返回类型、文档有无；调用表存了接收者、函数名、实参数、序号、字节区间、作用域，但下游几乎只读被调名、文件、调用者、置信、行号、序号。别名闭包、变量别名、导入边、继承边的中间推导全部只活在解析瞬间，无表可查。

消费侧最稀疏：序列、频次、共现、分组、层次树只用被调名字符串加作用域；层次树按点分重造父子，不用真父子与基类；检索加权只用模式与分组，不用置信与实参；证据与归纳用实参但拿不到形参与签名。分组与源码分块是唯一用全符号区间信号的地方，但用的是内存声明而非库表，且明确不消费调用。

## 2. 缺口清单

| 编号 | 缺口 | 不补的后果 |
|---|---|---|
| 符号定位缺失 | 符号表无文件与行范围，定义跳查无源 | 证据到定义无法连接，只能按限定名字符串猜文档块 |
| 符号语义列缺失 | 参数类型、返回类型、文档有无抽了不存 | 工厂改写与接收者定型不可复现，归纳提示拿不到签名，豁免规则无库表输入 |
| 解析过程黑盒 | 只有三级置信，无解析路径来源 | 调参与排错只能重跑全量，无法区分同文件命中、别名展开、继承上查、类型回填 |
| 调用者未链接 | 只有被调实体引用，调用者只是字符串 | 调用图无法遍历，调用者签名与上下文无法参与挖掘 |
| 已存字段无人读 | 接收者、函数名、实参数、深度、基类写后闲置 | 重载区分、元数信号、层次信息全部浪费 |
| 导入边无表 | 文件别名只服务解析，导入关系不落库 | 跨文件引用、扇入扇出、内外部分离无数据源 |
| 层次树仿造 | 特性树按点分切字符串，不用真父子与基类 | 包结构与类继承混为一谈，导航失真 |
| 序列只看名字 | 实参与置信不进挖掘输入 | 重载合并、不可信调用拉平支持度 |
| 身份键脆弱 | 调用身份含行号与实参原文 | 格式化即漂移，清扫抖动大 |

## 3. 修改方案

### 3.1 符号落盘补齐（改 `db` 与 `services/code` 落库，原表加列）

符号表按抽取模型补齐定位与语义列：所属文件、起止行、参数类型列表、返回类型、文档有无标记。已有父、签名、参数名、基类、字节区间、深度保持原义，加查询索引只给限定名与版本作用域，不为新列逐一建单列索引。落库函数按新形状同步写入，清扫逻辑保持按版本全量对照。缓存记录同步加对应字段，旧缓存整体失效重解析，不写兼容分支。文档特征库表说明随改随调。

### 3.2 调用解析来源显性化（改 `astminer` 模型与 `services/code` 落库，原表加列）

调用表增加解析来源列，记录本次命中走的是同文件声明、别名展开、自身加继承上查、形参类型回填、工厂返回改写、后缀全局消歧中的哪一条，置信列保持三级不变。调用者实体引用列与被调引用对称补齐，落库时按限定名加种类回填，找不到则置空，不断言。接收者、函数名、实参数保持写入，并作为后续挖掘的可选输入透出，不再闲置。审核工作流仍只看置信与复核状态，来源列只用于排错与加权，不改变审核语义。

### 3.3 导入边独立成表（按职责新增，原解析不动）

新增版本作用域的导入边表，记录导入文件、别名、解析后目标、边种类。数据来源就是解析已用的别名表加标准化后的目标串，不另起新的抽取逻辑。持久化放在源码摄取的同一事务尾部，随版本全量刷新。查询侧只给按目标查导入者与按文件查导出两类读接口，供后续依赖分析与跨文件剪枝使用，本次挖掘主路暂不依赖它，避免扩大 blast 半径。

### 3.4 下游按需消费（改 `mining` 输入与 `services/code` 读写，原算法不动）

层次树改用真归属：叶子种类与父子深度优先取符号表的父与种类，缺失时回退到现有按点分推导，保证无回归。分组与频次保持纯名字输入不变。序列挖掘保持纯名字闭合挖掘不变，置信只做既有过滤语义，不进加权，避免排序漂移。证据与归纳查询在现有实参与共现之外，按需联查被调与调用者的签名与参数名，用于提示组装与片段渲染，不改变返回形状，只丰富文本。检索加权保持现有模式与分组两路，来源列与实参暂不进排序公式，只用于调试日志与健康计数。

### 3.5 身份与缓存治理（改 `services/code` 标识，原语义收紧）

调用身份从行号敏感改为作用域加字节区间加被调名加实参形状的组合，格式化抖动收敛到字节区间变化才变。实体身份保持版本加限定名加种类不变。进度水位、向量同步、任务载荷的字段名与语义不变，旧库重跑自然收敛，不做双写与双读。

## 4. 任务清单（按实施顺序）

1. 符号表加列与落库同步：文件、行范围、参数类型、返回类型、文档有无，缓存格式升级，特征库表文档同步。
2. 调用表加解析来源列与调用者引用列，解析返回值透出，落库回填，读写接口透出但不改排序。
3. 导入边表与摄取尾部刷新，加两个读接口，文档同步。
4. 层次树改真归属优先、点分回退；证据与归纳联查签名；健康计数加来源分布。
5. 调用身份键收紧，清扫逻辑随动，全量重跑验证。
6. 黄金样例与集成用例补齐：符号定位可查、来源可解释、导入边可查、树归属正确、旧缓存失效。

## 5. 验证标准

* 迷你多文件仓库重跑后，已知符号的文件行、参数类型、返回类型、文档有无均可查；已知调用的来源可解释，调用者引用非空。
* 导入边查询返回已知导入者集合；特性树已知类分支按真父子挂载，非点分猜测。
* 序列、频次、共现、分组结果与改前在同一夹具上一致，允许树结构按预期变化。
* 全量测试一次通过，输出先落文件再读，中途不反复全量运行。

## 6. 非目标

不做调用图遍历接口，不做跨函数数据流，不做实参语义归一化，不做置信加权排序，不做向量与问答主路改造，不做旧库旧缓存兼容，不做版本升级与发布动作。
