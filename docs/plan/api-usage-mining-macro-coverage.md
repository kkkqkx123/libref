# 用法挖掘宏证据覆盖提升

本文把真实仓库复核中残留的 MTL 宏覆盖问题拆成独立后续任务。目标是让宏调用成为可分层、可审查、可比较的一等证据，而不是只出现在健康统计里。

## 现状

当前完整角色语料下，MTL 档案的 `macro_coverage` 为 `527 / 30975 = 1.7%`，看起来很低；但同一档案的目标调用只有 1473 条，宏形态调用与目标调用的粗略比例约为 35.8%。官方示例档案对应数字为 560 条宏调用、7122 条目标调用，粗略比例约 7.9%。

因此“覆盖率低”主要是分母混入大量非目标调用造成的口径问题。MTL 本身是宏密集型用法，当前结果反而说明宏证据被严重低估。

## 影响

- 宏调用默认被挖掘链排除，序列模式、共现和频率偏向普通函数与 inline 函数。
- `RTE_MAX`、`RTE_MIN`、`RTE_VERSION_NUM`、`rte_memcpy` 以及 flow item/action 常量宏没有进入具名审查档案的模式、标签和问答提示。
- 宏覆盖率阈值无法指导修复，只产生笼统的 `needs_review`。
- 宏体调用的位置是定义处，现有规范 URL 会被误读为实际调用处。
- 宏定义随目标库版本变化，但当前没有宏体指纹，版本兼容只能按声明版本整体判断。
- 若直接放开宏调用而不保留状态，会把宏体 token 扫描结果误报成已解析目标 API。

## 根因

- 健康指标用宏调用数除以档案来源的全部调用数，而不是目标调用数或目标宏定义数。
- 档案只有 `include_ambiguous` 与 `include_unconfirmed` 两类放行开关，没有宏调用的显式策略。
- 宏抽取只扫描函数式宏定义体中的 `name(` token，不记录参数、宿主宏、嵌套层级和预处理条件。
- GNU 属性导致部分函数原型解析失败，例如 `rte_exit`，进一步放大前缀候选。
- 目标实体没有宏体签名或哈希，档案指纹无法反映宏定义变化。

## 设计原则

- 不做完整 C 预处理展开；条件编译分支会让事实互斥并显著放大成本。
- 宏调用始终保留 `INFERRED` 置信度与独立 `relation_kind`，不得静默提升为 `EXTRACTED`。
- 默认问答口径保持保守；具名审查口径显式放行并记录策略。
- 指标必须能定位到缺失的具体宏，而不是只给一个比例。

## 方案

### 指标重定义

保留原始 `relations.macro` 与现有宏比例用于审计，同时新增四项可反推指标：

- 宏调用占目标调用的比例，以 `in_target_api=1` 为分母。
- 目标宏定义中有调用证据的比例，以目标版本声明的宏实体为分母。
- 宏调用中解析到目标宏实体的比例，以宏调用为分母。
- 未解析或仅前缀命中的宏调用清单，按档案和调用数排序。

健康比较文件对官方示例、参考项目同屏展示上述指标，质量门槛引用同一份计算结果。

### 档案策略

为挖掘档案增加宏调用策略：

- 默认 `usage`：宏调用保持排除。
- 具名审查档案：允许宏调用进入模式与标签，输出标注 `macro_policy=review_only`。
- 默认问答材料：只有经审核状态批准且显式开启的宏调用可以进入。

具名档案放行宏时同时要求 `relation_kinds` 包含宏形态，并保持目标状态分层不变。标签和证据块必须说明宏调用来自宏体可见调用，不是预处理展开后的真实调用点。

### 抽取增强

在纯算法层增强宏调用记录：

- 从宏体 token 扫描升级为宏体片段解析；tree-sitter 可解析时提取参数，失败时回退 token 扫描。
- 记录宿主宏、宿主文件、宏体行号、嵌套层级和预处理条件。
- 对象式宏值中的调用形态也记录，但要与函数式宏区分。
- 嵌套宏只记录为独立宏体调用，不尝试展开。
- 增加 GNU 属性函数声明的文本兜底，修复 `rte_exit` 一类目标原型缺失。

### 证据与版本

- 渲染层区分普通调用点、宏定义点和可选的宏调用点；宏体调用链接到定义处并明确标注。
- 在目标实体事实中记录宏体签名或哈希，并纳入档案指纹。
- 版本兼容报告在声明版本不一致时继续标记 `version_unconfirmed`；声明一致但宏体不同，也要列出具体宏差异。

### 质量门槛

移除单一宏比例阈值，改为可证伪检查：

- 每个具名档案是否有宏调用记录；
- 默认档案是否混入未批准宏调用；
- 宏调用是否被标成 `EXTRACTED`；
- 目标宏定义覆盖数和未解析清单是否存在；
- 宏体证据是否携带宿主宏和定义位置。

低覆盖只触发 `needs_review`，并附带具体缺失宏名。

## 分阶段实施

第一阶段先完成指标重定义、宏策略和门槛调整，不改变数据库结构。第二阶段增强宏抽取与属性声明兜底，并为新增字段补迁移。第三阶段完成宏体指纹、证据定位区分和版本兼容报告。

## 验收标准

- MTL 具名审查档案的模式和标签中出现宏调用，默认 `usage` 仍不含未批准宏。
- 健康输出能反推出宏调用占目标调用比例、目标宏定义覆盖率和未解析宏清单。
- `rte_exit` 等 GNU 属性声明进入目标实体，不再只按前缀命中。
- 宏体证据带宿主宏、定义 URL 和 `macro_body` 标记。
- 宏体变化会改变档案指纹并触发派生表重建。
- 全程不做完整预处理展开，e2e 运行时间不因宏增强显著增加。

## 不做范围

- 不把宏展开后的内部实现调用当作用户调用。
- 不按所有架构头文件同时建立互斥的宏事实；条件宏只记录可用条件。
- 不把宏调用直接写进默认问答材料，除非存在明确批准状态。
