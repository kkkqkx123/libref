# Go / Rust / C# 库发现与关系提取补充方案

> 背景：前两个提交补齐了三语言的 AST 抽取、调用消解与落库，但库发现与注册表解析仍只覆盖 pypi、npm、maven；关系提取仍只有仓内调用，清单文件声明的外部依赖不可见。
> 目标：三语言的模糊发现、精确解析、文档抓取闭环可用；清单依赖落库为可查询的版本级关系。
> 约束：SQLite 唯一真源、服务层唯一编排、出口保持薄；网络全部经共享客户端工厂；排序确定性无模型参与；只增新表不改旧表。

## 1. 现状缺口

- 发现与解析的生态白名单只有三项，新语言的包名无法精确解析，裸名发现扇出也触达不到新源。
- 三语言各有事实注册表与文档站，但地址形态、版本语义、元数据字段各不相同，需要按生态拆分 provider，而不是复用现有三源逻辑。
- 关系侧：调用实例只覆盖仓内边；go.mod 仅读模块前缀，Cargo 与 NuGet 清单完全未读；registry 缓存的仓库地址回查只对旧三源开放，新语言按名建代码索引时找不到源。

## 2. 生态命名与别名

- 规范名定为 go、crates、nuget，与注册表域名心智对齐，短且无歧义。
- 别名只收常见写法：golang 归 go；rust、cargo、crates.io 归 crates；csharp、dotnet 归 nuget。裸名推断保持保守，仅新增一条高置信规则：含斜杠的裸名归 go（模块路径形态），其余仍要求显式生态。
- 凡出现生态白名单字样的校验、帮助文案、别名测试，同一改动内全部同步。

## 3. 库发现：分生态数据源

每个新生态新增一个 provider 文件，只放该源的地址构造、名称归一与载荷解析，调度与缓存仍走现有外观与服务。

- Go：版本真源用模块代理（latest 取稳定版，版本列表取全量），文档地址固定派生为 pkg.go.dev 的模块页（含版本后缀形态）；模糊搜索解析 pkg.go.dev 搜索页的模块链接，精确命中再走代理快照富化。标准库路径无版本语义，不进快照。
- Rust：快照与搜索统一走 crates.io 的箱子接口，版本列表过滤已撤回，稳定版优先用接口给出的稳定最大版；文档候选优先用注册元数据自带的文档地址，回退到 docs.rs 的版本页。
- C#：版本用注册索引的版本时间线（按注册顺序取最新非预发布为稳定版）；搜索走官方查询接口，携带下载量作热度；文档候选优先用包元数据的工程地址（非仓库根才收），回退到 nuget.org 包页。注册索引分页过大时只追有限页数，避免抓取发散。

## 4. 排序与缓存复用

- 沿用现有字典序排名键：有无文档地址、是否精确命中、源内原生位次、热度、更新时间。新源只提供各自天然的热度信号（crates 下载量、nuget 总下载量、Go 无热度记零），不做跨源分数融合。
- 发现缓存、离线语义、TTL、未启用报错全部复用现有机制，缓存键继续用规范生态名加归一化查询串，别名与规范名共享同一缓存条目。
- 无生态限定时的扇出从三源扩到六源加可选 GitHub，失败分类与空结果语义不变。

## 5. 精确解析与仓库打通

- 精确解析为新生态补齐归一与快照：Go 按代理转义规则处理路径大小写，crates 小写归一，nuget 大小写不敏感归一。
- 仓库地址回查的生态门从旧三源放开到六源，使按名建代码索引对新语言同样可用。Go 快照本身不带仓库地址，该生态按名建索引仍需显式源或外部覆盖，此处如实返回缺仓库语义，不伪造。
- 手工覆盖文件的生态校验同步放开到六源。

## 6. 关系提取补充

调用侧三语言已在前两提交交付，本方案只补清单层关系，不碰引擎与消解。

- 新增清单解析小模块，纯函数无存储依赖：读 go.mod 的模块声明与 require 段、Cargo.toml 的包名与依赖段、csproj 的包引用项。解析失败按无清单处理，不阻断建索引。
- 新增版本级依赖关系表，记录仓库版本声明的外部依赖（生态、名称、版本要求、来源文件）。与调用实例同版本作用域同删同建，重建索引即全量刷新，无需回填历史。
- Go 模块前缀归一继续复用既有函数，清单解析出的模块名与建索引时的前缀读取走同一归一，保证幂等。
- 读侧在代码服务层提供按版本列依赖的查询，供后续出口按需接入，本改动不新增 MCP 与 CLI 工具。

## 7. 配置与镜像

- 注册表基地址默认值新增三项，显式地址仍按生态逐键优先于预设。
- 国内预设只新增有把握的 Go 代理镜像；crates 与 nuget 暂无可验证的同接口镜像，走默认地址回退，不写未经核实的镜像地址。
- 不新增密钥与开关字段，现有离线、私有地址、缓存 TTL 语义直接适用。

## 8. 非目标

- 向量与检索算法变更、私有仓库凭证管理、通用网页搜索兜底。
- 泛型实例化调用、嵌套模块 go.mod、C# 别名 using 等引擎层已知近似，仍留待后续。
- 依赖传递闭包展开与漏洞关联，只存直接声明。

## 9. 落地顺序与验证

- 先交付三 provider 加外观调度与精确解析，再补发现搜索与扇出，最后接清单依赖表与读侧。
- 验证以离线注入传输为主：归一、载荷解析、搜索解析、精确富化、排名、缓存命中零请求、离线缺缓存明确失败、私有地址拒绝；清单解析用最小文本夹具断言；三语言迷你仓走一次离线建索引断言依赖落库。
- 合并为尽量少的一次全量测试运行，输出重定向到文件后阅读。
