# 基于名称查询的注册表解析设计

> 位置：`docs/plan/long-term/` 长效设计。解决 `ingest` 必须手填 `library/version/start_url` 的摩擦，让调用方只给生态加名称即可解析出文档源。数据源单一（文档对源码双路）不在本方案范围。

## 1. 背景与目标

调用方只提供生态加名称加可选版本，系统解析出可抓取的文档地址和确定的版本号，之后复用现有抓取链路入库。解析只回答去哪里抓和有哪些版本，不改变抓取、分块、向量、检索逻辑。

## 2. 是否需要预先维护的列表

需要，但不是静态硬编码名单，而是注册表现查为主、人工覆盖为辅、本地缓存兜底的混合解析器。

纯静态名单不可取，流行库文档地址与版本号持续漂移，私有库无法收录，维护成本随时间线性增长。纯现查也不可靠，注册表元数据中文档地址缺失或指向仓库首页是常态，离线环境与版本复现需要缓存。

预先维护的部分只保留少量高价值覆盖规则，而不是全量名单。

## 3. 范围与非目标

范围是 `PyPI` 与 `npm` 两个生态的名称解析、版本列举、文档地址排序、缓存与覆盖机制，以及命令行与 MCP 的名称直查入口。

非目标是源码仓库挖掘、版本内容抓取本身、向量与检索变更、私有鉴权仓库的凭证管理。解析器只产出文档源，抓取仍走现有发现加抓取链路。

## 4. 归属划分

新增能力只落原有分层内，不新增替代模块。按职责拆分，不按新旧拆分。

抓取侧在 `crawler` 内承担注册表网络查询与文档地址排序，纯网络逻辑，不读写库，复用注入式客户端以便离线测试。服务侧承担库解析编排，负责查缓存、调客户端、写缓存、应用覆盖规则，是唯一读写注册表缓存的位置。存储侧直接修改库记录结构并新增注册表缓存表，当前无旧数据，不做迁移。出口层只做参数透传，不做解析逻辑。

## 5. 数据模型

直接修改，不新增迁移。存量视为无，历史回填不做。

库表以生态加名称为唯一键，取代原先全局唯一的名称。生态缺省值为自定义来源，手工直填的 Walton-legacy 行自然归入该生态。库表同时记录主页、文档地址、仓库地址、解析来源与解析时间，供任务重放与人工核查。

版本表增加注册表确认标记。请求版本命中注册表版本列表则确认，未命中仍允许继续但标记为未经确认，以兼容私有版本与文档站自定版本号。

新增注册表缓存表，主键为生态加归一化后的名称，内容为解析结论而非注册表原文，包含已排序的文档候选地址、版本列表、稳定版、主页、仓库地址与抓取时间。名称归一化按生态分别处理，`PyPI` 侧折叠大小写并统一分隔符，`npm` 侧去除首尾空白并统一小写。

覆盖表不进数据库，随代码发布，按生态加名称精确匹配，只记录强制文档地址、来源与核验日期。覆盖表永远优先于注册表推导，只低于用户显式传入的地址。过期条目不在运行时悄悄降级，由持续集成门禁强制核验提醒。

## 6. 解析流程

调用方输入为生态加名称加可选版本加可选显式地址。生态缺省不猜测，裸名必须显式指定生态，只有 `@作用域/` 形态可直接判定为 `npm`，其余含糊输入一律要求补生态后重试。显式地址与名称解析互斥，同时给出视为用法错误。

优先级依次为显式地址、覆盖表强制地址、注册表文档候选排序、注册表主页回退。任何一步命中可用地址即停止，不再向下尝试。仓库地址永不直接作为文档地址，只在无文档地址时作为提示返回，不送入抓取队列。

版本未指定时取注册表标注的稳定版，无稳定版时在版本列表中过滤预发布后缀后按版本号比较取最大，版本列表为空则明确失败。指定版本时先校验是否在版本列表中，在则确认，不在仍允许继续抓取但标记未经确认。

## 7. 生态客户端行为

`PyPI` 侧查询包元数据接口，取出版本列表、稳定版、主页、项目地址表与仓库地址。`npm` 侧查询包元数据接口，取出版本标签、版本列表、主页与仓库地址。两者均只做只读查询，不触发安装，不执行远端代码。

文档候选排序依据注册表元数据的字段专制度，而非字符串匹配。`PyPI` 侧项目地址表中文档类条目优先于主页，主页仅在域名形态像文档站时采用。`npm` 侧主页为有效公开地址即采用。排序规则按生态分别描述，但依据统一。

查询失败分为三类。包不存在返回明确的未收录结论，不再尝试抓取。网络或限流失败返回可重试结论，调用方按现有退避重试，遵守注册表限流指示。元数据缺文档地址返回地址缺失结论，并附带主页与仓库地址供人工确认。三种结论映射为不同的任务失败原因，名称错误与运维问题不得混为一谈。

请求头携带项目标识，超时与重试复用全局抓取配置。注册表返回地址在入库前做规范化与过滤，只允许公开 `http` 文档地址进入抓取队列。内网地址与非公开注册表地址默认拒绝，私有镜像需经配置显式开启镜像地址与私有放行后方可使用。

## 8. 缓存与离线

正常模式为缓存优先。缓存命中且未过期直接使用，不产生网络请求。缓存过期时当次尝试刷新，刷新成功用新结论并更新抓取时间，刷新遇到网络或限流失败则降级使用过期缓存并标记来源为过期缓存。不起真正的后台任务，避免与现有进程内任务队列产生竞态。

离线模式只读缓存，缓存缺失即明确失败，不尝试网络。是否离线、缓存有效期、镜像地址、私有放行均由应用配置统一管理。

## 9. 出口变化

命令行抓取保留显式三参数形态，新增按名称解析形态。解析形态给定生态与名称即可，版本号可选，缺省取稳定版。显式地址与名称解析互斥，指定版本可选。解析结论在任务参数中同时记录生态、名称、解析出的地址、版本号、确认标记与解析来源，保证任务可重放。

检索侧无需变更，解析完成后仍按现有库加版本分区检索。后续可在检索入口增加按名称列举库的功能，不在本方案内。

MCP 新增只读的名称解析工具，返回解析结论或分类错误，不触发抓取。长耗时抓取仍走命令行任务队列。

## 10. 验证

以离线注入传输为主要验证手段，断言名称解析出期望地址与版本列表、排序符合字段专制度、覆盖表优先于推导、缓存命中时不产生网络请求、离线缺缓存时明确失败、未确认版本仍可继续但标记正确、仓库兜底不进抓取队列。另设少量真实注册表冒烟用例，默认关闭，仅在联网验收时手动执行。
