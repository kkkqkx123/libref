# 检索基准剩余失败分析与修复方案

依据：24 个夹具重建后的 `tests/e2e/bench/evaluate` 报告；失败共 14 项。本文记录根因、修复范围与验收口径，不在代码中引用本文结构编号。

## 失败分类

十项是门禁修订过期，涉及九个文档夹具与跟随默认分支的 `httpx/code-head`。归档摘要或获取配方变化后，`gates.json` 中旧修订的下限不得套用到新语料，评测因此硬失败；这不是检索实现退化。`httpx/code-head` 的变化来自上游分支移动，属于结构性不稳定。

四项是无答案弃答率不足：`zod/docs` 的 precise/fused/fused_rerank 三路为 0.500，下限 0.600；`pydantic/docs/fused_rerank` 为 0.250，下限 0.350。候选并没有召回失败，问题在答案性判定：无答案查询的通用词碰巧落在无关页上，词面覆盖达到 `weak` 阈值 0.5。典型查询包括 `css grid template areas`、`swift package plugin`、`kubernetes pod affinity rules`、`graphql codegen typescript plugin`、`ansible vault encrypted variables`。`pydantic` 只在重排方法失败，是因为判定读取重排后的头部候选，头部变化会把 `none` 翻成 `weak`。

## 修复方案

对答案性判定做一处有界修正：保留原有的池覆盖与头部覆盖，但增加“覆盖集中度”观察——如果查询单元分散在多篇候选里、没有任何一篇覆盖到一半以上的单元，则按分散程度扣减强度。无答案查询的典型形态是通用词散落在不同页面，扣减后落到 `none`；可答查询通常至少有一篇候选集中覆盖主题词，强度不变。跨语言降级维持原样，不参与扣减。

该规则已在全部 2619 条三方法检索记录上做过差分：两个失败语料的弃答率分别提升到 0.750 与 1.000，误弃答率最高 0.200，仍低于 0.250 门禁。它不替代人工判定，但能在当前判定集下消除已知误判，且不把错误写入门禁。

门禁修订过期不在本轮代码修复范围：更新 `gates.json` 需要先冻结夹具身份、扩充判定集并完成人工复核；现有约束要求保持门禁不变。默认分支夹具的稳定化也应与门禁重测一起做，单独改 `ref` 只会制造另一套失效修订。

## 验收结果

- `src/libref/store/evidence.py` 增加集中度观察与有界扣减；新增回归用例覆盖“分散覆盖降权”与“集中覆盖不降权”，原有答案性用例保持语义。
- `uv run pytest -q`：`918 passed, 36 skipped`；`ruff check`、`ruff format --check`、`mypy src` 均通过。
- 检索矩阵评测从 14 项失败降到 10 项，四项弃答失败全部消失，未出现新的误弃答失败；剩余十项均为门禁修订过期。
- `gates.json` 与 `doc_feature_alpha` 未改；门禁重测与默认分支夹具稳定化仍按前文约束延后。
