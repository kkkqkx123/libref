# 文档特征题目人工语义核对记录

依据：`tests/e2e/fixtures/doc_features/questions.json`、`tests/e2e/bench/fixtures/*/docs/pages.jsonl.gz` 与当前冻结归档回放结果。本文记录人工对照原始正文与题目后发现的问题、修复动作和复核口径；不写完整代码，也不把同源一致性误称为语义正确率。

## 核对方式

先逐库抽取题目的目标 URL、标题路径、查询片段、期望实体和判定，再回到原始归档正文定位同一章节，检查：

- 查询是否来自该章节正文，而不是页面导航、脚本或元数据。
- 标题路径是否确实对应章节标题。
- 期望实体短名或限定名是否在题目或标题中出现，并与正文语义一致。
- drift 题是否确实引用弃用、移除或替代说明。
- 无答案题是否确实没有受跟踪 API 边。

程序化标记用于列出可疑项，人工结论决定是改规则还是删题；没有把生成器输出直接当成人工真值。

## 发现的问题

1. 部分 HTML 站点题目从导航开始，例如 `Initializing search`、`On this page`、重复模块名列表。题目锚点虽能解析，但查询与正文语义脱节。
2. 实体短名过宽，把正文中的普通英文词误当成符号，例如 `available`、`original`、`defaults`、`collection`、`otherwise`。这些词恰好与源码短名相同，但不是题目要问的 API。
3. 漂移自动判定存在已知误报，例如通用政策、否定式问答、生命周期枚举和外部安全标准。它们已出现在 `drift_samples.json` 的人工 not_drift 结论中，却仍可能被物化成 drift 题。
4. 部分 drift 题的查询只取了章节第一段，没有指向正文中真正出现 deprecated/removed/no longer 的句子。
5. 个别章节路径命中页面导航节点，导致查询片段是菜单列表而不是正文说明。

## 修复动作

- 扩充导航标记，并把命中导航的标题或正文直接跳过，不再用页面开头兜底。
- 扩充通用词禁用表，实体短名与标题/查询必须同时可核验；只出现在正文远处的普通词不再进入 `expected_entities`。
- 物化器读取 `drift_samples.json`：人工 not_drift 的 URL 与标题片段不再生成题目。
- 查询片段优先选择含弃用语义的句子，只有当章节正文确实出现 `deprecated`、`removed`、`no longer`、中文弃用/移除词时，题型才标为 drift。
- HTML 页面继续先剥离 head、script、style 和表格标记，再定位章节。
- 旧真实站点题目继续整体删除并由物化器重建，不保留错误题目。

## 复核结果

- 重新生成后，每库仍为 30 条，dev/test 各 15 条。
- 导航标记命中：0。
- 标题无法在原始正文定位：0。
- 期望实体不在标题或查询中：0。
- drift 题型无弃用语义：0。
- 已知 drift 误报锚点被重新物化：0。
- 逐库抽查的示例、参数、表格、变更、drift、无答案题均与正文语义一致。

该核对只证明题目与归档正文和派生证据一致；独立第三方人工复核仍应在门禁决策前进行，`doc_feature_alpha=0` 不变。
