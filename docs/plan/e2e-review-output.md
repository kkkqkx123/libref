# 端到端解析分段审查输出与真实仓库夹具方案

## 背景

端到端验证目前只有一行式统计报告，写到临时目录随测试销毁，无法逐文件对照源码确认声明抽取、调用消歧与分段边界。参考包的做法是夹具、断言、输出三权分立：单份共享夹具树、断言只做断言、输出由独立生成器落盘供人工审查。本方案把该结构裁剪后落到本项目。

## 目标

补充可人工确认的输出能力，覆盖解析结果与分段结果。夹具改用真实仓库，仓库拉取到本地持久目录，同步一次多次复用。不新增抽取逻辑，只复用现有抽取引擎、消歧、分组、分块与仓库索引入口。

## 输出布局

审查输出落到端到端目录下的输出目录，按语言分子目录。每个仓库一份汇总文本，记录固定标签、实际提交标识、文件数、声明数、调用数、置信分布与缓存命中。每个源文件两份逐文件报告：解析报告列声明与调用明细及行列字节跨度，分段报告列分块标识、归属分组、种类、跨度、合并成员、块数与空块计数。本项目没有自然语言转换，分块内容退化为文件标记加分段跨度，不设摘要与双路对照。输出目录只读审查用，不入库，不参与断言，纳入忽略文件。

## 职责划分

断言文件只断言结构不变量与可用性下限，不写输出文件。现有索引 runner 收敛为薄封装，只做参数解析加服务调用，索引与导出逻辑分别归属仓库索引入口与新增的审查导出脚本。新增两个脚本，各一名一责：仓库同步脚本负责拉取与更新本地持久仓，审查导出脚本负责逐文件落盘解析与分段报告。命名描述职责，不做新旧版本区分。

## 真实仓库与本地复用

清单保留固定标签与远端地址，新增本地持久路径字段，指向端到端目录下的仓库目录。同步脚本复用现有仓库管理入口的浅克隆与更新语义，已存在则拉取更新，不存在则克隆，不做贮藏等写操作。Python 仓继续用本地只读参考包做受控采样，不整体搬运。断言与导出统一改从本地持久路径读取，网络失败仍标记环境不可用，不视为回归。

## 人工确认流程

同步一次后多次使用。先跑同步脚本，再跑审查导出，对照输出目录逐文件报告与本地持久仓源码核对声明跨度、调用归属与分段边界。疑问只记录不拦截，确认解析退化或待定占比突增才阻塞。

## 约束

不新增抽取模块，不引入外部依赖，不做校验和门禁，版本保持不变。常规测试目录不出现真实域名，端到端默认跳过，常规提交不受影响。
