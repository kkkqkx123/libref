# 正式 LLM 集成设计方案

目标是把当前散落在抓取编排里的临时编码调用收拢为正式传输层，并补齐重排与问答两路。嵌入、重排、问答统一走同一传输库与同一密钥通道，缺密钥时自动降级，不阻塞已有全文链路。

## 1. 现状与缺口

应用配置已登记嵌入模型名、维度、基址与密钥占位，密钥经环境注入不入库。请求形态已有三份手工验证文件分别覆盖嵌入、重排与本地同协议端点。抓取编排内含临时批量编码函数，行为正确但位置错误：传输细节落在编排层，且重排与问答无任何承载位置。向量存储只收已编码向量，检索服务仍是纯全文单路。

本次只收拢原有模块，不建替代模块。已有临时编码逻辑搬迁，不复制一份新实现。

## 2. 库决策

传输只用已有网络库，不新增嵌入或模型厂商专用依赖。已有网络库已随抓取链路引入，支持异步、长连接与离线模拟传输，足以承载三路兼容接口。数据校验沿用已有模型库。向量客户端仍只允许向量存储模块持有。

不引入厂商专用客户端、编排框架与本地权重分发库。手工验证文件已证明三路接口均为普通兼容接口，无需专用封装。

## 3. 模型映射

嵌入固定为免费的 `bge-m3`，维度固定为一千零二十四。该取值已写入配置默认值与向量元数据治理，变更即整体失效重建。

重排采用同系列配对重排模型，与嵌入同属免费档，形态与手工重排验证文件一致。单靠嵌入模型无法服务重排端点，这是接口层面的固有限制，因此接受一对模型而非单个字符串。

问答固定免费的 Qwen/Qwen3.5-4B。传输已就绪但调用链仍不接入，默认保持禁用。本期检索排序不需要生成，不硬编码任何付费问答模型。

## 4. 模块职责

按职责拆分传输与编排，不按新旧拆分。

编码传输模块负责批量编码、超时重试、归一与维度数量校验，不碰数据库与向量索引。重排传输模块负责按查询对文档列表打分排序，不碰数据库。问答传输模块负责按消息列表生成文本，首版只做非流式。三个传输模块均为纯内存输入输出，可单测。

融合检索模块负责双路召回、按排名融合、重排精排、频次加成与段落重组，是唯一知道全文与向量两路的编排位置。向量不可达或重排不可用时降级为纯全文单路并标记降级，降级判断在服务层。

抓取编排只负责先落真源后同步派生索引，失败计数不推翻真源写入。检索服务改走融合检索，并新增按真源全量重灌入口。三个出口只调服务层，不直接触达传输模块。

## 5. 配置与密钥

沿用现有嵌入四项配置不改名。新增重排四项：模型名、候选截断数、精排首部数与开关，基址与密钥默认复用嵌入同值。新增问答五项：模型名、基址、密钥、超时与开关，默认禁用。

密钥通道统一走带前缀的环境变量加仓库根环境文件加模板文件三件套。环境文件默认存在，不存在时传输层视为无密钥，直接走禁用路径，不发起实际调用。

## 6. 写入与检索流程

写入时抓取收集真源增量，收尾阶段校验集合并删旧点、编码新文档、批量写入向量。编码文本构造与查询编码共用同一规则，标题路径在前、正文在后。

检索时先编码查询，再按版本过滤取向量近邻，同时取全文候选，两路各取放大的候选数以留足融合材料。融合只消费排名，不消费两路原始分值。融合首部送重排精排，其余不送。频次加成只做有界乘法加成，不做大权重加法。最后按地址分组扩展兄弟与父标题块并合成片段。

## 7. 验证

离线模拟传输断言请求形态与手工验证文件一致，维度与数量失配抛错，限流与服务端错误退避重试。无密钥与服务端不可达对应测试跳过而非失败。对账语义为版本内向量点数等于文档表计数。检索基准沿用混合检索方案的双轨门禁，阈值变更需说明。收敛为一次全量运行，输出重定向后阅读。

## 8. 落地顺序

先落编码传输并搬迁临时逻辑，抓取行为不变。再落重排传输与融合检索的双路加精排。问答传输只落空实现与禁用测试，不接调用链。最后补重灌命令与出口接线。

## 9. 本次不做

问答生成链路、流式输出、中文分词更换、融合参数自动调优均不在本期范围。重排默认关闭，由基准裁决是否开启。
