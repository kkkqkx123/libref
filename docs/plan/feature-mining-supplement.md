# 特征挖掘补充功能细化修改方案

依据为 `docs/ref/libref特征挖掘功能评估与补充设计方案.md`（以下简称评估案）。本文把评估案第五章的补充方向落为可执行的文件级改动，按阶段给出改动点、行为与验收。全文只用自然语言描述，不贴完整代码。

## 一、目标与硬约束

- 把特征挖掘从单一结构频次统计补成多维特征体系，补齐总纲文档、质量度量、评测基准三块缺口。
- 硬约束沿用既有架构：`mining/` 保持纯内存算法、零数据库依赖，输入为普通 Python 数据结构；派生数据按挖掘档案隔离，SQLite 为唯一真源；模型只作用于归纳层，产物单独存表、可整体重建；三个出口只经 `services/` 读写，不直调 `store`、`crawler`、`mining`。
- 不做向后兼容，不保留旧口径。凡是口径变更，直接改原模块，不建替代模块；新增模块只按职责划分命名，不按新旧对比命名。
- 代码注释只写意图，不引用任何文档编号。

## 二、现状锚点

本次改动涉及的现状位置：

- 算法层：`src/libref/mining/` 下的 `feature_tree.py`（归属链频次聚合）、`cluster.py`（作用域交并比连通分组）、`frequency.py`（计数与截断）、`cooccur.py`（作用域集合）、`idiom.py`（`reuse_diversity` 健康信号已有但未文档化）、`induction.py`（模式标签提示词与校验）、`scoring.py`（检索加成）。
- 编排层：`src/libref/services/code/mining_refresh.py`（共享单次扫描 `_load_kept_calls`、派生重建与集合差清理）、`src/libref/services/code/mining_read.py`（`api_insight`、`pattern_insight`、`mining_health` 等读模型）。
- 存储层：`src/libref/db/schema.py` 与 `src/libref/db/postgres_schema.py` 中的 `seq_patterns`、`feature_nodes`、`api_clusters`、`pattern_labels` 四表定义。
- 配置层：`src/libref/config.py` 中的聚类阈值、归纳开关与检索加成权重。
- 调用实例真源列已具备 F2 所需全部输入：接口名、实参原文、实参个数、作用域键、解析种类、调用形态、目标状态、宏标记。F2 不需要改解析器。

## 三、阶段一：特征挖掘总纲文档

新增 `docs/features/feature-mining.md`，作为特征挖掘唯一总纲，其余文档只保留摘要并指向它。

- 总纲内容：四层特征模型定义（结构统计、用法形态、约束守卫、语义归纳）、每层的输入来源与事实性质（静态事实还是模型归纳）、特征树构建语义（归属链优先、点分回退、调用数沿父链累加、作用域按样本键去重）、聚类语义（交并比边、连通分量、代表成员取作用域最多者）、参数依据（聚类阈值与最小规模的取值理由与失效表现）、质量指标定义（覆盖率、提升度、复用度、多样性）与健康判读方法。
- 同步修订 `docs/architecture/code-indexing-chain.md` 中特征树与聚类段落，缩为算法摘要并指向总纲，不再两处维护细节。
- 验收：总纲与四表实际行为一致；交叉文档无口径分歧。

## 四、阶段二：用法形态特征与新派生表

目标是把评估案的 F2 层落地为真源派生数据，不动现有四表结构。

- 存储：在两种后端建 `feature_facets` 表，归属库版本与挖掘档案，列含义为维度名、取值、调用数、作用域数，同档案下维度加取值唯一。维度先收敛为三类：实参形态（由实参原文经掩码归一后的形态分布）、调用形态（调用实例上已有的调用关系种类）、调用序位（单样本内调用在序列中的位置分桶）。另在两种后端配套档案加维度倒序索引。迁移写法沿用项目现有增量风格，两后端在同一改动中同步。
- 算法：在 `mining/` 内新增按职责命名的形态聚合模块，输入为调用实例行的普通元组（接口名、掩码后实参、调用形态、样本键），输出为维度取值到调用数与去重后作用域数的映射，外加候选组合算子（实参形态与调用形态交叉）与每层截断。掩码复用 `idiom.py` 已有实参掩码逻辑，不另起一套。选择逻辑复用 `frequency.py` 的截断形制。
- 编排：在 `mining_refresh.py` 中新增与 `refresh_feature_tree` 对称的重建函数，复用共享单次扫描与审核过滤；空输入时清空本档案的形态表；写入沿用批量幂等加集合差清理；`mine_patterns` 主流程与 `_clear_derived` 同步纳入新表，保证空档案无残留。
- 读取：在 `MiningReadService` 新增形态列表方法，支持按维度过滤与按调用数倒序截断，缺表时返回空。
- 配置：新增每层截断上限与候选预算上限两个配置项，显式封顶组合爆炸。
- 测试：形态聚合模块配单元测试（掩码分布、作用域去重、截断确定性）；重建与读取配集成测试（含空档案清空与幂等重跑）。
- 验收：同一档案重跑结果一致；形态调用数与实例真源对得上；候选规模受预算约束。

## 五、阶段三：质量度量文档化与健康透出

目标是把已存在的复用度与多样性 helper 转为正式质量标准，并补上按需计算的关联度量。

- 文档：在总纲中正式定义复用度（模式支持总量的对数形态）与多样性（有效分组数的对数形态）的计算口径、判读阈值与停机含义；明确二者是健康信号而非排序主键。
- 读取：`mining_health` 新增复用度与多样性字段，取值来源为已落库的模式与聚类行，不新增存储；另对单特征按需计算支持样本数、覆盖率与提升度（相对独立性假设的偏离程度），由读模型在内存中完成，不落库。
- 检索门禁：特征选择生效前后，检索评测的召回与排序指标不得回退，复用既有检索评测入口。
- 验收：健康视图含新字段；度量口径与总纲一致；检索指标无回退。

## 六、阶段四：黄金特征集与回归基准

目标是补上特征侧的评测缺口。

- 以官方示例为主构造小规模人工标注语料，标注维度真值（形态归属与代表性模式），存为固定夹具。标注只覆盖形态层，不标注语义好坏，避免把模型偏好写成真值。
- 新增两类用例：黄金用例断言形态分布与代表模式命中；差异用例断言改造前后特征分布变化可解释（沿用既有差异用例形制，扩展到形态维度）。
- 评测语料固定提交与选择规则，档案隔离；待审未解析调用不进入黄金真值。
- 验收：黄金集稳定可重放；一次口径变更能被差异用例捕获。

## 七、阶段五：轻量守卫特征

目标是评估案的 F3 层，只做语法级近似标注，不做数据流分析。

- 特征定义收敛为三类：检查后使用（同一作用域内先判空或判错再调用）、配对使用（同一作用域内开启与关闭、申请与释放成对出现）、异常包裹（调用处于异常处理块内）。全部基于调用行已有的位置与作用域信息聚合，不新增解析器能力。
- 守卫特征写入同一 `feature_facets` 表的新维度值，不另建表；不可判定时直接缺席，不写猜测值；宏密集库在覆盖不足时按既有宏覆盖率口径标注限制。
- 算法仍放在形态聚合模块内，开关由配置控制，默认关闭，先在黄金集上验证准确性后再默认开启。
- 验收：黄金集上守卫标注可解释；关闭开关时行为与阶段四完全一致。

## 八、阶段六：特征选择管线

目标是把评估案的扩张加剪枝思想落为固定管线，防止组合爆炸。

- 管线三步都在纯内存侧完成：候选扩张（阶段二的组合算子在预算内生成候选）、显著性过滤（以对模式支持或检索加成的边际贡献为准，贡献接近零的候选丢弃）、每层截断（沿用既有截断形制保留前若干）。
- 选择只决定哪些形态值写入派生表，不改变真源调用实例；选择参数（预算、截断数、贡献阈值）全部进配置文件，显式可查。
- 验收：候选规模有硬上限；选择前后检索指标不回退；同一输入选择结果确定。

## 九、阶段七：聚类与特征树语义命名

目标是补上 `api_clusters` 与 `feature_nodes` 缺失的语义标注，复用模式标签的归纳链路形制。

- 存储：新增 `cluster_labels` 表，形制对齐 `pattern_labels`：归属库版本与档案、分组键哈希、成员原文、模型、提示版本、名称、摘要、类别路径、来源角色提示、更新时间。分组键由成员排序后哈希，保证幂等。同样在两后端同步建表。
- 归纳输入只含聚合后信息（成员限定名、成员规模、代表成员、共现上下文、档案来源角色），不含源码原文；输出校验（必填长度、类别路径限深、关联接口白名单、材料边界标记拒收）复用 `induction.py` 现有规则并收紧一条：关联接口必须落在版本实体集合内。
- 来源提示为必填字段：凡含参考项目语料的分组，标签必须携带人类可读的场景来源说明与非官方推荐声明，闭环既有复核报告中的标签误读问题。
- 编排复用归纳任务的批量提交与续跑形制，幂等键命中直接跳过；挖掘清理已消失分组的标签。
- 验收：重复归纳结果稳定；含参考项目语料的标签必带来源提示；未知接口引用被拒绝。

## 十、阶段八：消费面

目标是让特征在出口可用，但不改变检索与问答的主次关系。

- 读模型：`pattern_insight` 新增形态视图与特征摘要视图（维度分布加健康信号加代表模式），复用已有视图的分发形制与条数上限。
- 接口洞察：`api_insight` 的形态输出附带维度标签，不新增视图。
- 检索：`scoring.py` 在既有频次与聚类加成之外增加特征加成通道（形态命中加权），权重由新增配置项控制，默认保守；仍只作用于融合后头部，加成关闭时跳过加载。
- 问答：语义类别路径与名称只作展示增强材料，不参与排序与引用定位，与模式标签现行策略一致。
- 出口：MCP 与命令行只做参数透传与结果格式化，不写业务逻辑；网页侧在现有视图形制下增加特征维度浏览页，跨版本对比页留到阶段九。
- 文档：同步修订模型工具契约与网页视图说明。
- 验收：三出口同参同果；加成关闭时检索行为不变；问答引用不受语义标签影响。

## 十一、阶段九：跨版本与跨档案特征漂移对比

目标是评估案的演化对比能力，只做读时计算，不新增存储表。

- 读模型新增档案对比方法：并行加载两档案的派生表做集合差与分布对比，产出漂移清单（新增、消失、支持度显著变化的前若干）。
- 指纹变化只重算受影响部分，形制对齐既有增量索引思路；对比限定在同库不同版本或同版本不同档案之间。
- 网页侧增加与现有视图形制一致的对比页。
- 本阶段按需排期，前置依赖是阶段二与阶段四完成。
- 验收：同一档案自比对无漂移；版本升级的接口增删能被清单反映。

## 十二、配置项清单

本方案新增配置项（命名沿用现有风格，全部显式可查）：

- 形态层截断上限、候选预算上限、守卫特征开关、特征检索加成权重、漂移清单截断数。
- 聚类标签的候选上限与提示版本复用归纳配置的同类项，不另起名字。
- 密钥仍只走环境变量，不入库不进文件，日志只打脱敏快照。

- 新增派生表说明并入 `docs/features/db/` 下与现有表说明同形制的形态表文档。
- 新增跨档案漂移设计说明放入 `docs/analysis/`。
- 修订索引链路、模式归纳、模型工具契约、网页视图四处文档，使其指向总纲。
- 本计划实施中不同步改版本号。

## 十四、实施顺序与验证

- 顺序：阶段一与阶段二先行；阶段三与阶段四随后；阶段五至阶段八按依赖依次实施；阶段九最后。
- 每个阶段提交前至少运行完整测试套件、静态检查与格式检查，并把长输出先落文件再过滤查看；禁止为验证而做的额外编译。
- 凡改动检索或挖掘逻辑，必须附带黄金或差异用例。
