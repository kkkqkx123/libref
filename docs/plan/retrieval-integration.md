# 检索集成问题分析与修改方案

依据为当前代码实测与纯 SQLite 行为探测，不依赖任何历史设计文档。
全文检索与向量检索的集成目标：SQLite 是唯一真源，向量索引是可重建的派生数据，
写入时由编排层同步两路，读取时两路结果可用文档标识关联。

## 现状

全文路已经跑通：文档写入 SQLite 的 documents 表后，触发器自动同步外部内容表
documents_fts，检索服务用 MATCH 加 BM25 排序。向量路只存在一半：Qdrant 封装已经写好，
但抓取编排完全不调用它，入库的文档从不产生向量，删除文档也不清理向量点。
配置里有向量地址、集合名和编码模型占位，但没有任何代码消费它们。

## 问题

共六个，按严重程度排序。

写入与向量完全脱节。抓取服务只调文档存储，文档存储只写 SQLite。
向量存储的写入、删除、版本清理方法没有任何调用方。后果是向量索引恒为空或越用越脏：
页面重分块后旧向量点残留，页面删除后向量点残留。根因是当初只实现了存储原语，
没有实现编排接线。

单页写入不是原子的。一次页面存储分三次提交：先提交页面行，再提交旧文档删除，
最后提交新文档插入。中间崩溃会留下半页数据，页面行是新的而文档是残缺的，
全文索引也会处于中间态。根因是内部辅助方法各自提交，而不是由入口统一提交。

向量集合会被不同数据库串写。集合名是全局固定值，而文档标识是各库自增整数。
两台机器、两个库文件共用一个本地向量服务时，相同标识的向量点互相覆盖，
按版本过滤检索会串出别家的文档。这是误用抗性缺陷：默认配置就能走进错误用法。

集合维度校验有漏判分支。读取集合维度时遇到非预期形态直接返回空，
调用方把空理解为无需重建，脏集合被永久保留。分支覆盖了正常形态，
却把异常形态当作正常放行，掩盖了真正的配置漂移。

全文排序没有列权重。内容、标题、地址、路径四列等权计分。
标题和路径是人工精炼的短文本，命中它们本应比命中正文的长段落更显著，
等权把这种信号稀释了。结果是标题精确匹配的文档可能排在正文顺带提及之后。

检索结果没有文档标识。返回项只有地址、片段、标题等展示字段，
没有行标识。向量命中的回查、两路结果的关联、未来的融合排序都需要这个键，
现在拿不到，只能按地址字符串凑合，而地址在跨版本时并不唯一。

## 修改方案

共六项，与问题一一对应，全部只改原有模块，不新增替代模块。

文档存储返回同步增量。页面存储的返回从结局字符串改为结果对象，
携带结局名、本次删掉的文档标识列表和新插入的文档标识列表。
删除前先查出待删标识，保证增量完整。入口统一单事务提交，异常整体回滚。
调用方用结局名做计数，用标识增量做向量同步。旧的纯字符串返回不再保留。

抓取服务编排向量同步。抓取服务新增两个可选参数：向量存储和批量编码函数，
两者缺其一即走纯全文路，不报错。抓取仍先落 SQLite 并收集增量，
收尾阶段批量删旧点、编码新文档、批量写入。编码文本与全文列对齐，
标题路径在前、正文在后，定义收拢到向量存储模块一处，
保证写入与未来查询共用同一构造。向量阶段失败不推翻已提交的真源写入，
失败点数计入返回计数的独立键，供运维发现与后续重建。

集合名按库文件派生。新增纯函数，按数据库文件绝对路径的哈希给集合名加后缀，
内存库保持原名。命令行入口采用派生名，不同库文件天然隔离，
单库部署行为与今天一致。直接构造向量存储的调用仍可指定任意集合名，
已有测试不受影响。

维度未知视为失配。集合维度读不到预期形态时不再跳过校验，
直接删除重建并登记新模型元数据。重建语义与模型名、维度变更一致：
向量是派生数据，丢弃后按真源重灌。

全文加列权重。排序函数改为对四列显式加权，标题最高、路径次之、
内容与地址为基准。权重选择依据字段的信息密度，而非历史惯例。
这一条是排序调参，随附排序行为测试锁定，防止后续无意改动。

检索结果携带行标识。全文检索的每一项新增行标识字段，
与向量点标识同一编号体系。展示层忽略它即可，同步与融合逻辑使用它。

## 验证

文档存储测试更新为新返回形态，并新增增量断言：
重存页面时删掉的恰为旧标识、新增的恰为新标识；
删除页面时增量只含删除；批量回查按标识取回内容与标题。
向量存储新增离线测试：纯函数派生名的确定性与隔离性，
注入伪客户端验证未知形态触发重建。
抓取新增两则离线测试：伪向量加伪编码下同步行为正确，
编码抛错时抓取仍成功且失败计数准确。
全文新增排序测试：标题命中的文档排在仅正文命中的文档之前。
收尾合并为一次全量测试运行，输出重定向到文件后阅读。

## 本次不做

两路融合排序、重排模型、向量重建命令、中文分词更换都不在本次范围。
它们依赖本次打下的增量与标识基础，等写入链路正确且可观测后再做。
