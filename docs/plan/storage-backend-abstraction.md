# 存储后端抽象：剩余任务说明

> 参考：`~/code/code-context-engine` 的存储契约与后端选择实践（元数据/全文/向量三契约、装配层枚举分发）。
> 定位：接续 `docs/plan/multi-user-production-deferred.md` 中 T1 / A10，让同一套 `services/` 与三个出口既能以嵌入式后端跑单机部署，也能以共享后端跑中心服务部署。
>
> 进度：阶段一至阶段四已落地，阶段五（ES 全文分支）未启动；全文差分已判关系库原生全文充分，ES 继续推迟。本文只保留剩余任务的详细说明，已完成内容仅作背景简述。

## 1. 背景与已完成工作（简述）

目标是同一套服务代码覆盖两种部署形态，后端差异收敛在装配层：元数据与文档契约（SQLite 本地分支、PostgreSQL 远程分支）、全文契约（FTS5 本地分支、关系库原生全文远程分支）、向量契约（simvec 本地分支、Qdrant 远程分支），装配根产出不可变的存储包。保持"元数据是唯一真源、全文与向量是可重建派生索引"，租户隔离为契约强制语义，切换后端即全量重建、不迁移旧数据。

| 阶段 | 状态 |
|---|---|
| 一 契约固化 | 已完成：中立契约、装配根、服务层改依赖契约 |
| 二 远程元数据与原生全文 | 已完成：PG 合并 DDL、连接池会话、原生全文分支 |
| 三 控制面与多副本 | 已完成：任务、版本锁、进度、配额、审计、主体与密钥走会话契约，排空与配置指纹核对 |
| 四 向量契约对齐 | 已完成：诊断快照、部署身份派生集合名、租户过滤与重建语义统一；向量侧设置面与集合画像见 `docs/plan/vector-storage-settings.md`（集合治理已去驱动类型，走元数据会话写入） |
| 五 ES 全文分支 | 未启动（差分判据为充分，继续推迟） |

本轮已闭环的前遗留项：全文契约三处漂移修复（FTS5 版本过滤与计数租户、PG 权重顺序与归一化、生成列补地址权重及分隔符归一）、全文差分记录落盘、多副本认领压力与心跳恢复验证、DDL 对等用例（嵌入式迁移链为源、PG 合并脚本为投影）、任务服务的 PG 缺口收敛。证据见 `docs/plan/fulltext-diff-record.json` 与第 4 节。

约束（剩余工作仍须遵守）：不做通用 SQL 抽象与跨后端迁移，不为假设需求引入新引擎，不保留旧后端兼容层；密钥只经环境变量注入；部署环境不直连外网。

## 2. 剩余任务 R2：检索基准执行

现状：基准用例已有显式开关与归档缺失跳过，本机无归档且无外网，本轮仍跳过；等效覆盖暂由全文差分与既有检索门禁承担。

剩余动作：在有外网的机器上获取一次归档（获取脚本与评测脚本见 `tests/e2e/bench/` 下的说明文档），随后以显式开关运行基准集成用例，记录门禁结果。归档、数据集与报告目录按该目录说明不入库，检入的只有规格、判定集与门禁。

验收：基准用例在有归档环境一次跑通，门禁全过；无归档环境继续干净跳过。

## 3. 剩余任务 R5a：检索链的关系库方言路由

现状：混合检索与精确搜索仍直连 FTS 虚表并内嵌方言函数，关系库分支下不可用；全文契约后端已就绪但生产调用链调不到它。

剩余动作（二选一，先定方向再动手）：把关键词读路径收敛到全文契约（经句柄查回文档标识与分数，正文与详情回元数据会话读取），其余 SQL 的方言写法走会话的方言表达式；或明确声明中心部署暂不支持在线检索。若选收敛，需配双分支用例，精确搜索与混合检索在关系库分支可跑，并与嵌入式分支做结果差分对比。

验收：选定方向落文档；若选收敛，关系库分支检索可用、差分门禁通过、现有测试全绿。

## 4. 剩余任务 R5b：控制面剩余服务的方言收敛

现状：任务服务已按"枚举分发、方言表达式、契约插入、JSON 兼容读"模式收敛；进度、反馈、审核、保留、配额、审计、主体、版本锁仍含嵌入式时间与 JSON 写法。

剩余动作：逐个服务按任务服务的模式收敛，每个服务配双分支用例（关系库分支用例由连接串环境变量门控，无库时跳过）。一次收敛一个服务，保持全量测试常绿。

验收：各服务双分支用例通过；无库环境行为不变。

## 5. 剩余验证加码：大语料与 CJK 差分

当前"原生全文充分"的判据只覆盖受控拉丁语料。待 R5a 完成后补两项：中文查询行为差分（关系库把连续中文判成整体词，与 FTS5 的切分不对齐，需单独设门禁），以及真实语料上的排序与融合差分。ES 是否启动以此为准，在此之前 ES 保持推迟。
