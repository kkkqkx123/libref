# astminer 三语言第二阶段细化方案

> 范围：收尾第一阶段设计文档第九节列出的五个已知近似，外加三语言端到端落库验证。
> 原则：共享路径只收紧不放宽；纯函数下沉规则层，仓储状态只读服务层；缓存键不动，派生归一幂等可重放。

## 0. 目标与非目标

目标：同模块 Go 跨包调用达到精确消解；Rust 导入路径关键字相对当前模块归一；泛型调用在无歧义的两语言上可抽取；Rust 宏定义作为可调用实体落库；三语言从建索引到调用实例有一条离线集成测试覆盖。

非目标：Go 泛型实例化调用（实例化与下标在语法上不可区分，见第 4 节）；嵌套模块的 go.mod（只读仓库根，见第 1 节）；C# 别名 using（`using X = ...`，形态稀少，维持现状）；宏定义体内部展开。

## 1. Go 模块前缀剥离

现状：同模块跨包导入的别名目标带完整模块前缀，与按文件路径推导的声明限定名对不上，只能靠原始文本后缀回退给出推断级置信。

改动：建索引时读一次仓库根 go.mod 取模块声明；纯归一函数放规则层，输入点分别名与模块前缀，前缀命中才剥离；编排层在组装别名表时对 Go 文件应用归一，缓存命中与新抽取两条分支都走同一归一，保证幂等。缓存键与落库形态不变；go.mod 变更时旧缓存的别名未经剥离，只会回退到推断级，不产生错误精确结果，此处文档注明。

## 2. Rust 导入路径关键字归一

现状：路径渲染丢弃 crate、super、self 等首段，跨目录的 super 导入只能靠后缀回退。

改动：规则层新增路径段渲染，按语法子节点原文取段，不依赖具名标记；再按首段关键字相对当前模块解析：crate 段落到仓库根，self 取当前模块，super 逐个弹出。别名构建函数接收当前模块参数（引擎透传已有值，只补调用链）。解析失败回退到去关键字形态，与现状一致。

## 3. C# 命名空间核验收尾

嵌套命名空间与文件作用域命名空间靠区间包含建链，预期无需引擎改动。本阶段只补断言：嵌套类限定名逐层拼接、文件作用域下成员归属正确、基类不挂到包声明上。若断言失败再按区间归属修，不预设改动。

## 4. 泛型调用

Rust 泛型函数与泛型方法的被调节点包在泛型包装内，字段结构已实证，直接增补两形态并复用现有对象加函数捕获。

C# 泛型名节点由基名加类型实参表构成，点分函数在该节点类型上取首个标识子节点即基名。基类表中的泛型基类同步受益，归一到基名。

Go 暂不做：实例化调用 `f[T](x)` 解析为下标表达式作被调，值下标与类型下标语法不可区分；转换形态 `T(x)` 更与普通类型转换同形。逐个捕获会把所有下标调用与类型转换记为调用，噪声大于收益，文档注明。

## 5. Rust 宏定义实体

`macro_rules!` 定义新增种类宏，纳入可调用集合以便宏调用精确消解；分组上独立成组，不吸收成员。属性宏与派生宏非定义体，不进入。带路径的宏调用增补对象加函数形态。

## 6. 三语言端到端落库验证

新建三语言迷你仓库夹具（含 go.mod），走建索引入口离线建库，断言三语言声明落库、Go 同模块跨包调用为精确级、Rust 关联与自身调用为精确级。该测试只依赖本地目录克隆与 SQLite，不引入网络。

## 7. 验证计划

查询编译覆盖全部语言；每项改动配行内黄金断言；共享路径改动（基名归一、别名归一）跑全量单元与集成套件；格式与类型检查沿用既有命令。
