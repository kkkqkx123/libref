# 权限边界加固设计

## 背景与目标

现有权限体系采用 API Key 认证、角色映射 scope、`tenant_id` 行级隔离，并已具备启动闸门、配额与审计。它适合本机与受控内网，但存在四个实质问题：`admin:keys` 可通过任意 scope 与任意租户签发出等效超级管理员；全局租户由数据字段而非显式权限控制；Web、组合服务与独立 MCP HTTP 的鉴权路径不统一；Origin 校验用监听地址做子串匹配且忽略配置的允许来源。

本次修改的目标是把权限边界变成可执行约束，而不是文档约定。服务对外默认进入强制鉴权；开发模式必须显式开启且仅限回环；所有 HTTP 入口共用一个认证入口；scope 与租户提升必须可验证；拒绝、签发、吊销与配置刷新都要留下审计。

## 设计决策

### 身份与权限

- 保留 API Key 单一凭据，不引入会话、密码或外部身份系统。
- 角色仍是 scope 的静态展开，但新增平台管理员角色承载跨租户权限；普通管理员只能签发自身持有的 scope。
- scope 是闭合集合。未知 scope、超出调用者的 scope、超出调用者租户的主体一律拒绝。
- `*` 不再是普通可写租户字段，只能由平台管理员使用；行级过滤遇到 `*` 的绕过语义保留，但获得它的路径必须经显式权限校验。
- 引导管理员在首次启动时成为平台管理员；后续通过鉴权后的管理接口签发凭据。

### 认证链路

- `services/infra/auth.py` 是唯一的认证实现，负责 Bearer 解析、Origin 校验、主体解析与启动校验。
- 所有 HTTP 应用在应用组装处挂载同一个认证中间件；路由只读取中间件写入的主体并做 scope 判定。组合服务在扁平化路由后由外层中间件覆盖。
- 独立 MCP 只保留标准输入输出形态；流式 HTTP 仅由组合服务的 `/mcp` 提供，避免第二套无身份链路。
- Web 应用在自身内部挂载中间件，使独立 Web 与组合 Web 的认证行为一致。

### 传输与启动

- 默认 `auth_mode = "enforced"`；`dev` 必须显式配置，且只允许回环监听。反向代理到回环地址不改变服务端可见的监听地址，因此生产部署不得使用开发模式。
- Origin 校验改为解析后的精确匹配，来源是 `allowed_origins`；非浏览器请求没有 Origin 时允许，带 Origin 的浏览器请求必须命中明确配置的来源。
- 启动校验不再吞异常。引导失败、缺少引导凭据或配置错误都以退出码 2 终止。

### 凭据生命周期与审计

- Key 支持默认有效期与最大有效期；签发时校验，不设过期时间时套用默认值。
- 增加按主体吊销全部 Key 的管理操作。
- 认证失败、来源拒绝、scope 拒绝、Key 列举、Key 签发与吊销、配置刷新失败均写审计；审计写入失败不能阻断业务。

## 修改任务

1. 收敛认证实现，移除 `mcp_server/auth.py` 与未使用的 `auth_required`，更新所有导入与测试。
2. 收紧角色、scope 与租户签发约束，加入平台管理员与 Key 生命周期。
3. 修正 Origin 校验并与配置对齐，更新部署示例与文档。
4. 统一 Web、组合服务与 MCP 的出口形态，移除独立 MCP HTTP 与独立 Web 命令。
5. 补齐审计、启动失败传播与配置刷新错误处理。
6. 增加 scope、租户提升、Origin、审计与出口一致性测试，并统一验证。

## 验证口径

- 单元测试覆盖角色展开、未知 scope、签发范围、租户提升、有效期、吊销与 Origin 精确匹配。
- 集成测试覆盖强制鉴权下 Web 与 `/mcp` 的拒绝与放行、scope 不足的 403、审计落库、组合服务扁平路由行为。
- 最后统一运行测试、lint、格式检查与类型检查；不在修改过程中反复编译或重复执行全套验证。

## 完成情况

认证实现已收敛到 `services/infra/auth.py`，`mcp_server/auth.py` 与未使用的 `auth_required` 已移除。角色新增平台管理员，scope 与租户签发均受调用者权限约束，Key 有默认与最大有效期，并支持按主体批量吊销。Origin 改为精确匹配并接入 `allowed_origins`，默认鉴权模式改为强制。HTTP 应用统一在组装处挂载认证中间件，独立 MCP HTTP 与独立 Web 命令已移除。认证失败、授权拒绝、Key 列举与吊销、配置刷新失败均写入审计。

验证已统一执行：`uv run pytest` 全绿，`uv run ruff check src tests`、`uv run ruff format --check src tests`、`uv run mypy src` 均通过。

## 后续修正

本文描述的是该轮加固的目标态；后续审查发现 Key scope 只能扩大、跨租户资源操作缺少归属校验、平台管理员的 `*` 被当作写入租户、来源与配额路径分散等问题。修正清单与分阶段方案见 `docs/plan/permission-boundaries-repair.md`。
