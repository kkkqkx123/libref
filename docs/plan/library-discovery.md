# 类 ctx7 库发现能力设计

> 目标：在不破坏"SQLite 唯一真源、服务层唯一编排、出口保持薄"的前提下，补上 ctx7 式的模糊库发现与按需抓取闭环。检索与挖掘算法本身不在本方案范围。

## 1. 背景与现状差距

当前项目只有"精确解析 + 本地已入库检索"，缺少"模糊发现 + 全网一站式检索"。

| 能力 | ctx7（实测） | libref 现状 |
|---|---|---|
| 模糊库名 → 候选库列表（带排名） | `library <name>`，返回 `id/title/description/stars/trustScore/benchmarkScore/versions/totalSnippets` | 无。`resolve` 要求精确包名加生态（裸名直接报错），只返回单一结论，无模糊、无排名、无热度信号 |
| 跨库全局问答（零预抓取） | `search <query>`，中心化预索引语料直接出 `codeSnippets + infoSnippets` | 无。`search` 只查本地已入库，未抓取的库返回空；`catalog` 只列已入库 |
| 指定库文档问答 | `docs <libraryId> <query>`，支持 `language/version` 参数 | 近似有：`search --library --version` 加 `read_doc`，但前提是事先 `ingest` 过 |

## 2. ctx7 可借鉴的实现要点（基于 CLI 实测与客户端逆向）

服务端三组接口，全部为只读查询加 Bearer 鉴权，未登录限流可用：

| 接口 | 入参 | 出参要点 |
|---|---|---|
| `GET /api/v2/libs/search` | `libraryName`、`query` | 候选数组：编号、标题、描述、分支、更新时间、token 数、片段数、stars、trustScore、benchmarkScore、版本列表 |
| `GET /api/v2/context` | `libraryId`、`query`、`language`、`type` | `codeSnippets`（签名加参数加示例的结构化条）与 `infoSnippets`（散文条）分离；`language` 按语言重排；`301` 带 `redirectUrl` 的库迁移语义 |
| `GET /api/v3/search` | `query`、`library`（可重复，最多四个）、`version`、`language` | "发现加问答"合一的跨库直答 |

可直接借鉴的四点：发现与问答分离的两步式交互加一站式兜底；popularity 加质量加规模的三维排名信号；同一库多源并存（官网、源码仓、抓取站、`llms.txt` 各一条，用分支标记区分）；失败分类明确（迁移、配额、未收录各有语义，不静默回退）。

## 3. 数据源选型

| 数据源 | 覆盖 | 排名信号 | 成本与鉴权 | 结论 |
|---|---|---|---|---|
| npm 官方搜索 `registry.npmjs.org/-/v1/search` | npm 模糊搜 | 下载量、popularity、quality、maintenance | 免费匿名 | npm 侧发现首选 |
| Maven Central Solr `search.maven.org/solrsearch/select` | maven 坐标搜 | 版本数、时间戳 | 免费匿名 | maven 侧发现首选 |
| PyPI（仅 `/simple/<包>/` 精确页，无官方模糊搜索） | 精确校验 | 无 | 免费 | 只做精确校验，不做模糊源 |
| Libraries.io、deps.dev | 全生态 | stars、被依赖数 | 需 key、有配额 | 跨生态统一层备选，首版不接 |
| GitHub API（仓库搜索与仓库详情） | 全语言 | stars、更新时间 | token 才有可用配额 | popularity 分量来源，对标 ctx7 的 stars |
| Tavily、Exa、Brave Search | 全网文档地址 | 自带相关性分 | 付费 key | 仅当注册表无文档地址时兜底搜官网 |

首版只接免费匿名源（npm 搜索、Maven Solr、PyPI 精确校验、GitHub 可选增强），付费通用搜索后置，避免首版引入账单依赖。

## 4. 排序逻辑

各源原生顺序即相关性基准，不做跨源分数融合（npm 评分、Maven Solr 评分、stars 量纲不可比，硬融合只会引入不可解释的权重）。统一排序为确定性字典序键，数值越小越靠前：

1. 有无文档地址：有文档候选排前（发现的直接目的是找文档，无文档地址的仓库裸链降级）；
2. 精确匹配：归一化后与查询串相等的包名或坐标排前（npm 按小写，maven 按完整坐标，PyPI 精确查回天然命中）；
3. 源内原生位次：各源返回顺序的下标（相关性基准，各源原生排序本身已融合自家热度信号）；
4. 热度：npm 取月下载量（缺失回退搜索分），maven 取版本数，GitHub 取 stars，仅作跨源同层决胜；
5. 新鲜度：各源自带的更新时间倒序，末位决胜。

生态未指定时多源扇出合并仍用同一键；源内位次按各源自有下标比较，跨源比较同一下标时才落到热度决胜，需要精确结果时按生态分别查询。浅层搜索条目的文档可用性按主页存在且非仓库根判定，仓库根地址永不直接充当文档候选，与现有注册表规则一致。精确命中的条目走一次注册表快照富化，拿到排序后的文档候选。全程无模型参与，纯确定性排序。

## 5. 总体方案

本地真源定位不变，不代理 ctx7 远端（外部鉴权、配额、新鲜度不可控，且违背单机真源约束）。新增"发现加懒抓取"一层：发现回答"有哪些库、哪个更可信"，抓取仍走现有 `scrape_docs` 链路，检索仍只读本地。

归属划分：网络查询逻辑归 `crawler`（新建按源拆分的 provider 文件，不读写库，客户端经参数注入以便离线测试）；编排归 `services`（新建发现服务，唯一读写发现缓存）；出口只做参数透传与包络组装。默认关闭懒抓取，`search` 未命中已入库时返回结构化"未收录加候选"提示而非静默空结果，由调用方显式触发抓取。

非目标：向量与检索算法变更、私有仓库凭证管理、全生态统一索引、Web 抓取任务流改造。

## 6. 配置与环境变量调整

新增字段统一走现有三源优先级（CLI 显式覆盖大于环境变量大于配置文件大于内建默认），生效快照冻结只读。

| 字段 | 类型与默认 | 来源 | 说明 |
|---|---|---|---|
| `discovery_enabled` | 布尔，默认开 | 文件或环境 | 总开关；关闭后发现工具直接返回未启用错误 |
| `discovery_topn` | 整数，默认 10 | 文件或环境 | 单次返回候选上限，与分页上限共用校验 |
| `discovery_cache_ttl_days` | 浮点，默认 1.0 | 文件或环境 | 发现缓存有效期，对齐注册表缓存语义 |
| `discovery_offline` | 布尔，默认关 | 文件或环境 | 只读缓存，不触网；缺缓存明确失败 |
| `discovery_github_token` | 字符串，默认空 | 仅环境变量 | GitHub 增强查询用，无则降级为匿名配额 |
| 通用搜索密钥 | 暂不引入 | 付费搜索源后置，配齐后再加对应密钥字段，首版不留无用配置 |

两个密钥进 `SECRET_FIELDS`，配置文件内出现直接拒绝，与现有密钥规则一致。`SECTION_FIELDS` 新增 `discovery` 分组收拢前四个字段，密钥不进文件故不分组。`redacted_dict` 与 `settings_fingerprint` 无需改动，自动覆盖新字段。镜像方面：npm 与 maven 的发现地址跟随现有 `registry_bases` 与 `registry_mirror` 预设（显式地址优先于预设）；PyPI 模糊缺失不在镜像体系内解决。

## 7. 代理设置（复用现有爬虫体系）

发现侧 HTTP 必须经 `crawler/http.py` 的共享客户端工厂构造，逐条沿用既有语义：显式 `LIBREF_HTTP_PROXY` 优先于标准环境代理变量；显式 `LIBREF_NO_PROXY` 优先于环境 `NO_PROXY`，缺省回落到回环默认；显式代理会丢弃 httpx 原生 `NO_PROXY` 旁路，因此由工厂自行合并旁路挂载表，保证回环地址永不走代理；`*` 通配旁路视为关闭代理；注入测试传输时忽略代理，与 httpx 原生行为一致。

超时、重试、退避复用全局抓取配置（`request_timeout`、`fetch_max_retries`、`crawl_delay_default`），遵守各源限流指示；各发现源按主机独立退避。内网地址默认拒绝进入抓取队列，私有镜像沿用 `registry_allow_private` 显式放行语义。发现缓存的写入走服务层，与注册表缓存同锁。

## 8. API 设计

服务层新增发现服务，对外三个方法：按名模糊搜（生态可选）、候选明细（地址加版本加仓库）、懒抓取编排（显式触发，走现有任务队列与增量语义）。返回模型为 pydantic（含名称、生态、描述、稳定版、版本列表、文档候选、主页、仓库地址、stars 或下载量、来源标记），跨包边界无字段漂移。

MCP 新增 `library_search` 只读工具，入参为查询串、可选生态、条数上限；成功返回与目录对齐的包络（条目列表加总数），失败返回分类错误（参数错误、未收录、可重试、离线缺缓存）。现有 `search` 加可选的按需抓取开关，默认关闭；开启且本地无命中时先走"解析加抓取"再检索，并在结果中标记来源，不伪装成纯本地命中。`resolve` 与 `catalog` 语义不动。

Web 新增 `GET /library-search`（参数与 MCP 对齐，走同一服务方法），抓取沿用现有 `POST /scrape`，不新增提交入口。CLI 新增 `discover` 子命令（查询串加生态加条数，打印包络），`search` 加按需抓取开关（默认关闭）。所有出口延续薄层原则：参数校验、包络组装、错误收敛，不做排名与抓取逻辑。

## 9. 数据模型

新增发现缓存表（生态加归一化查询串为主键，存排序后候选、抓取时间），经版本化迁移引入；历史无旧数据，不做回填。候选中的 stars、下载量只做排名输入，不进 `libraries` 表，避免外部波动污染真源。

## 10. 落地顺序与验证

先做 npm 加 GitHub 的只读发现（无抓取副作用），再补 maven 与 PyPI 校验，最后接懒抓取开关与未收录提示。验证以离线注入传输为主（断言排序、缓存命中零请求、离线缺缓存明确失败、私有地址拒绝），少量真实源冒烟默认关闭。合并为一次全量测试运行，输出重定向到文件后阅读。
