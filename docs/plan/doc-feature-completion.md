# 库文档特征挖掘收尾清单与修改方案

依据：`docs/ref/libref库文档特征挖掘补充设计.md`、`docs/plan/doc-feature-mining.md`、`docs/plan/doc-feature-evaluation-redesign.md`、`docs/plan/doc-feature-data-repair.md`、`docs/plan/doc-feature-label-expansion.md` 与两轮端到端评测报告。本文只描述剩余任务的边界、落点与验收口径，不重复功能定义，也不在代码中引用本文结构编号。

## 一、完成度结论

专项设计中的 D1/D2 结构与内容特征、四张派生表、D3 实体对齐与模式覆盖、D4 确定性判定、派生刷新编排、任务化、检索加权通道、三类过滤器、MCP `doc_insight` 四视图和配套文档已经落地。抓取与挖掘成功后均能自动重建对应派生范围，重跑幂等，审核冲突证据不进入派生表。

尚未闭环的部分分三类：

1. 设计与实现方案明确要求、但当前代码缺失的能力：文档到特征树节点的挂接、D4 模型归纳的生产接线、Web 页面详情与前端过滤控件。
2. 设计列为交付判据、当前只完成基础设施的评测：每库 30–50 条人工判定题、对齐准确率与检索增益门禁。真实站点题目现为 270 条、各库 30 条，nDCG 配对差分仍基本为零，不能写入门禁。
3. 设计允许按评测结果暂缓的能力：默认打开 `doc_feature_alpha` 与 P2+ 文档主题树、图谱聚合。当前没有可标定增益，按风险条款保持关闭与不启动。

## 三、本轮修改方案

### 文档到特征树节点挂接

新增派生表 `doc_feature_node_links`，按档案与版本隔离，记录文档块、对齐实体与特征树节点路径三者关系。真源仍是 `doc_api_links`、`api_entities` 与 `feature_nodes`：由实体限定名在特征树中定位叶节点，再沿节点父链收集祖先节点，同名歧义和树中无对应节点的实体都不建边。

关联构建放在现有纯对齐模块中，输入普通字典，不访问数据库；批量写入、存活键求差删除和清除顺序放在唯一写入口 `services/docs/feature_refresh.py`。迁移作为新版本追加到现有链条，并同步 PostgreSQL 终态 DDL 与整版清除逻辑。

`doc_insight` 的 `links` 视图为每个对齐边附带命中的特征树节点路径；不新增第五个视图，避免出口形态漂移。

### D4 模型归纳的生产接线

刷新函数在模型归纳关闭时不构造网关。配置打开但未显式注入会话函数时，由刷新层通过既有共享网关构建器取得会话函数，沿用 per-endpoint 韧性状态；显式注入仍优先，便于评测和单测。模型只写 drift 样本的 `note`，不改确定性判定。单次调用中的失败计数进入刷新结果并以告警日志暴露，不推翻派生真源。

ingest、挖掘后刷新、任务 runner 与本机 CLI 无需各自解析模型配置，仍调用同一个刷新入口。

### 块级洞察与前端出口

`doc_insight` 四视图增加可选 `document_id` 过滤，供页面详情按块读取派生数据；四视图名称和输出形态不变。Web 请求模型、MCP 工具签名与 librefctl 参数同步追加该字段，随后重新导出 OpenAPI 快照与前端类型。

Web 前端新增一个文档洞察页，复用现有洞察页的查询、表格、错误与作用域控件形态；搜索页增加块类型、排除废弃、仅看对齐三个过滤控件并写回查询串；阅读页按当前页面的块标识读取对齐实体、覆盖模式与特征树节点并展示，读取失败不影响正文阅读。

## 四、本轮不修改的内容

- 不人工编造判定题或漂移标签；评测数据扩充属于真实语料上的标注工作。
- 不打开 `doc_feature_alpha` 的默认值，也不让详尽预设强制打开；当前归档回放除个别不显著波动外差分为零，没有标定依据。
- 文档特征派生本身不实现 RAPTOR 式主题树或 GraphRAG 式图谱聚合；独立图查询通道见 `docs/plan/graph-traversal-query-channel.md`。
- 不改变双路召回、RRF 融合、问答引用编号与四张既有表的唯一键口径。

## 五、验收口径

- 迁移可在空库与已有库上重放；关联表在整版清除时先于 `doc_api_links` 删除。
- 纯对齐函数在无数据库连接下单测覆盖父链收集、歧义跳过与无树节点跳过。
- 集成用例断言同版本重跑后关联行不变，审核冲突边不产生关联，模型开关关闭时不发起模型调用，打开且注入失败会话时计数增长而 verdict 不变。
- Web 契约检查通过，`doc-insight` 四视图在传入块标识后只返回对应块数据。
- 前端类型检查、契约检查与相关单测通过；后端相关单测与集成测试通过。

## 六、落地记录

本轮已新增迁移 33 与 `doc_feature_node_links`，完成纯对齐函数、批量刷新、整版清除与四视图读取接线；D4 在刷新层按配置解析共享网关并统计归纳失败；Web 前端增加文档洞察页、搜索派生过滤与阅读页特征摘要，OpenAPI 快照与前端类型同步重建。

验证结果：`uv run pytest -q` 为 952 passed、59 skipped；`ruff check`、`ruff format --check`、`mypy src librefctl/src` 通过；webui 的 `npm run check` 与 `npm test`（71 项）通过。冻结归档回放已重跑，报告新增树节点列，并修复按目标文档读取派生证据时的 1000 行截断。未标定项和 P2+ 仍按前文保持不动。

## 七、判定集标注与测试矩阵

现有文档特征夹具分两层。纯算法层是 `tests/fixtures/doc_features/golden.json`，含两个文档块、两个实体、片段调用、对齐边、模式与废弃样本；离线端到端层是 `tests/e2e/fixtures/doc_features/`，含 6 个页面（示例、参数表、废弃、变更日志、歧义短名、无实体叙述）、两版页面、3 个实体、2 个模式、12 条 demo 判定题和 40 条漂移抽检样本。冻结归档层另有 24 对文档/源码夹具与主检索判定集，文档侧题目现为 270 条。

本轮按 fixtures 可确定性判定的范围完成标注：

- 纯算法黄金集新增特征树父链与期望节点关联，单元测试按集合相等复核，避免只凭手写内联数据通过。
- 离线端到端夹具新增 6 个特征树节点和关联数量下界；12 条 demo 判定题均带 `expected_feature_nodes`，渲染报告按集合相等计算节点准确率并写入 `08-metrics.txt`，不变量检查节点路径与关联条数。
- 旧真实站点题目曾由归档物化器重建；人工核对发现导航残留、泛词实体和题面错配后，已删除物化器及其单测，并按 `docs/plan/doc-feature-question-manual-authoring.md` 分项目逐题手写替换。
- 270 条题目已定稿，每库 30 条、dev/test 各 15 条；题型覆盖限定名、示例、参数/返回、变更说明、表格、drift、无答案等，题目没有写 `document_id`。
- `expected_facets` 补齐块类型、标题深度、长度分桶、代码比例、表格标记、版本标记、示例语言、示例符号、参数名、返回值与废弃标记；离线与冻结归档报告都能核对这些标签。
- 实体只在目标页有对应 `doc_api_links` 且正文出现该符号时写入；节点只从目标文档 `doc_feature_node_links` 父链写入；判定只在目标页结论唯一时写入。没有证据的标签保持空值。
- `tests/e2e/bench/evaluate_doc_features.py` 新增树节点评分、逐项块特征一致率与报告列，并改为按目标文档读取实体边、块特征和一致性判定，消除全版本 `limit=1000` 截断；单元测试用最小内存库复核命中、缺失与按文档过滤三种情况。
- `doc_facets._return_hint` 的空 Markdown 行处理补回归测试，并统一该分支的格式化写法。
- 漂移样本扩到 40 条人工结论，其中 28 条 drift、12 条 not_drift；自动 drift 35 条、误报 7 条，样本规模仍不足以写门禁，只保留观测。
- 模型归纳用注入式成功/失败会话做差异测试：成功写 note、model 与 prompt 版本；失败只增加计数并保留原 verdict。
- 前端用 vitest 模拟 API，覆盖搜索页三类派生过滤参数、文档洞察页的块级过滤与四视图参数、阅读页按块读取并展示派生结果。

冻结归档已达到每库 30 条的题量下限，但标签仍来自归档正文与派生表的同源核对，不能替代独立人工语义判定；实体标签覆盖 93/270 题、判定标签 21/270 题、节点标签 14/270 题。漂移误报门禁同样缺足够人工样本。因此本轮没有改变 `doc_feature_alpha=0`，也没有写任何检索增益门禁；报告中的差分只作为后续标定依据。
