# 文档特征实体边与评测口径修复方案

依据：`docs/tests/doc-feature-unblocked-analysis.md`、`docs/issue/doc-feature-benchmark-followup.md`、冻结归档评测报告与当前生产代码路径。本文记录完整问题清单、改动边界与验证口径。实现只修改现有模块，不新增旁路模块，不改 `doc_feature_alpha`，不写门禁。

## 一、问题清单

### 数据问题

1. **生产侧没有实体来源绑定写入方**。`entity_source_bindings` 只有评测器和集成测试显式写入；抓取、挖掘与本机任务均不创建绑定。查询无绑定时回落到文档版本自身，而文档版本没有源码实体，生产对齐实际退化为名称匹配。
2. **歧义短名被全局丢弃**。`build_api_index` 对出现多个实体的短名与归一化短名直接标记为歧义，不留候选。受影响的实体在 gradle 为 9205/13810、zod 为 2550/4212、jsoup 为 2903/4488。正文里完整限定名出现很少，仅靠精确名无法补回。
3. **片段到块的回退绑定过严**。页面内围栏序号匹配失败时按调用名回退，但对齐层在块含围栏时只接受 hash 相等，回退得到的调用几乎无法生成强边。HTML `pre` 与 Markdown 围栏转换、分块合并都会触发这类回退。
4. **弱边被当成强边消费**。`doc_api_links` 中 `name_fuzzy` 约 95.5%，但实体对齐统计、过滤 `aligned_only` 和检索加成都不区分证据强度。93 条实体标签题中仅约 21 条有至少一条 `symbol` 或 `signature` 边。
5. **模式有效样本稀薄**。漏斗中的 `samples` 是“有调用的样本”，不是“同一样本至少两次目标调用”的有效样本。fiber 仅 22、Rocket 36、jsoup 11 条有效样本，低覆盖主要来自样本短与别名缺失。
6. **漂移仍是无对象关键词判定**。块级 `deprecated` 直接写 `drift`，40 条抽检中 7 条误报落在发布流程、安全基线、否定式问答、生命周期枚举与升级收益说明。
7. **节点标签有同源缺陷**。`VU22` 的期望节点在目标 URL 下没有对应关联，不能作为节点一致率样本。
8. **回放阶段耗时缺失**。评测器采集了夹具总耗时，但报告不输出阶段耗时和调用次数，无法区分摄取、挖掘、刷新与检索的成本。

### 评测口径问题

1. `examples_only` 等过滤器的命中率用全部 30 题作分母，而合格题每站只有 6–7 条；命中也只按 URL，不按标题路径。
2. 检索差分只给聚合 nDCG/MRR 区间，未区分“候选池外”“池内未进 top-k”“加权改变顺序”。离线复放的 270 题中 21 条目标在池外，7 条掉出 top-5，15 条排名后退。
3. 漂移误报只报比例，没有列出误报对象，无法据此修规则。
4. 判定标签来自归档正文与派生表同源核对，尚不能替代独立语义复核；离线词袋替身结果不能替代真实嵌入链路。

## 二、设计方案

### 实体边分层

保留 `symbol` 与 `signature` 为强边，`name_fuzzy` 为弱边，新增 `context_symbol` 作为中间证据档。强边用于对齐准确率和过滤；`context_symbol` 只进入洞察视图与诊断，不进入检索加权。`ALIGNMENT_BONUS` 不为中间档和弱边分配正权重。

### 歧义名上下文消歧

`build_api_index` 保留歧义短名的候选列表，不再整体丢弃。`align_documents` 用块正文、标题路径与标题中的父级标识做消歧：只有某个候选的显著父级名出现时才建 `context_symbol` 边；多个候活得票相同或没有上下文证据时仍不建边。扩展名与唯一短名维持原行为。

### 绑定顺序与证据降级

`_load_snippet_calls` 从 `doc_snippet_records` 取回片段 hash。`_map_calls_to_documents` 按“代码 hash → 页面内围栏序号 → 调用名”的顺序绑定，并记录每种绑定次数。hash 与序号绑定可保留 `symbol`；名称回退只生成 `context_symbol`，不再在含围栏的块上被静默丢弃，也不再冒充 AST 精确边。

### 生产绑定接线边界

版本绑定仍要求显式声明、同库、固定源码版本，不按生态或版本号猜测。`entity_source_version_id` 的自身回落只表示“该版本自己持有实体”，不再被当作生产对齐的成功路径。生产配置需要在索引前显式写入绑定；跨包文档若需要多个源码子树，应按 URL 前缀声明多个来源，而不是放开名称匹配。本次先完成纯算法与服务侧证据改造，绑定配置入口保持原职责边界。

### 评测报告改造

- 解析漏斗增加 `effective_samples`。
- 题目表增加强边对齐列，并单列强边一致率。
- 过滤器同时给出全题命中率、合格题数与合格题命中率；命中要求 URL 与标题路径同时匹配。
- 每题记录排名归因类别，站点汇总六类计数，并保留逐题明细。
- 输出绑定次数、阶段耗时和漂移误报对象清单。
- 不写门禁，不改默认权重；真实模型结果与离线替身分开呈现。

## 三、验证口径

- 纯算法单测覆盖：无上下文的歧义名不建边、父级上下文唯一时建 `context_symbol`、名称回退不升级为 `symbol`。
- 评测器单测覆盖：强边对齐、合格题分母与标题路径命中、排名归因分类。
- 集成测试确认刷新仍落在原版本，派生计数与四视图不回退。
- 冻结归档用同一份数据重跑，比较新旧报告的强边占比、有效样本数、过滤合格题命中率与阶段耗时；差分区间仍跨零时继续维持 `doc_feature_alpha=0`。

## 四、边界

- 不把 `not_target`、`partial`、`ambiguous` 片段提升为目标调用。
- 不因为弱边数量多就降低强边门槛或全局下调 `minsup`。
- 不补造缺失父链和缺失实体标签。
- 独立语义复核和真实模型链路缺失时记为不可测量，不以离线替身结论替代。

## 五、复测结果与观测

冻结归档已用同一份数据重跑并覆盖报告。全量测试为 977 passed、60 skipped；`ruff check`、`ruff format --check`、`mypy src librefctl/src` 均通过。

报告新增的观测值确认了原先被混合掩盖的事实：

- 93 条实体标签题中只有 20 条有 `symbol` 或 `signature` 强边；其余题目的“OK”来自弱边或中间证据档。
- 有效样本数分别为 httpx 42、zod 197、jsoup 11、fiber 22、vue 59、pydantic 92、FluentValidation 26、Rocket 36、gradle 268，解释了覆盖稀疏的来源。
- `aligned_only` 改为只接受强边后，保留数从接近全量降到 gradle 13/150、vue 21/150、pydantic 39/150，同时报告给出合格题命中率；过滤器不再把名称重叠当成对齐。
- 新增 `context_symbol` 主要用于诊断，不进入加权，也不再写回 `documents.metadata.entities`、特征树节点与一致性证据；派生节点数因此回落到强边口径。
- 新增逐查询排名归因与阶段耗时。排序差分仍有正有负，部分区间跨零，未形成可冻结的增益；`doc_feature_alpha` 保持 0。
