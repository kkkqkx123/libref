# 特征树、聚类与检索消费闭环设计

> 依据：课题需求分支 B（调用顺序与参数使用模式）、三层架构（挖掘纯内存、编排落库、版本隔离可溯源）、特征树频次与序列模式两篇对标分析、源码挖掘与混合检索两份细化方案已落地部分。
> 目标：补齐从调用实例到可用知识的中间层（分层特征、分组关系），并让检索真正消费挖掘产出，形成挖掘构建到知识检索的闭环。
> 范围：只改原有模块，不新增替代模块。新增文件仅按职责拆分：分层聚合与分组各一新模块；检索融合落在既有规划的检索模块；持久化只追加一次迁移，不改历史迁移。

## 1. 现状合理性判断

合理且保留的部分：

- 挖掘构建与知识检索分层正确。挖掘包保持纯内存、落库由编排层完成，算法可离线单测；存储层以 SQLite 为真源、向量为可重建派生索引，写入先真源后派生、失败只计数不推翻真源。
- 序列主路正确。按外围调用者分组保序成序列、归一化后做闭合模式挖掘、模式表幂等加清扫、证据查询时按有序子序列计算而不持久化，语义一致且无冗余列。
- 增量与幂等正确。文件哈希加指纹缓存、确定性语义键加集合清扫、待定调用送审，二次建索引行为可预期。
- 检索单路正确。全文按标题路径加权、触发器同步、行标识贯穿文档与向量点，为融合打下键基础。

不合理与断点：

- 频次与共现有两套实现。纯内存函数与检索服务查询各算一遍，层级计数与精确计数混用，共现函数无生产调用方且粒度与查询侧不一致。
- 模式表达太扁。模式行只有名称序列加支持度，没有参数形态、接收者种类、上下文层级，检索侧无法解释为何推荐该模式。
- 分层与分组缺失。当前只有扁平限定名计数，没有按模块、类、方法逐级聚合的特征树，也没有把经常一起出现或可互换的接口归为一组的聚类。参数习惯只能查原始分布，不能返回收敛后的形态。
- 检索不消费挖掘。全文检索完全不读模式与频次表，向量写入已接线但融合排序、段落重组、重排增益基准均未实现，挖出的支持度对排序零贡献。
- 桥接键缺失。文档块与调用实例只共享版本归属，没有块到接口的关联，频次想作用到文档排序时找不到归属。
- 治理未闭环。版本内多仓语义、审核状态流转、向量重灌入口、基准门禁均只有表或计划，没有可执行入口。

## 2. 需要补充的功能

挖掘完备性：统一频次入口，精确计数供截断、层级计数仅供展示；共现统一到作用域粒度，文件级只作为调用方的聚合选项；阈值、长度、截断规模、待定纳入全部由编排签名与任务载荷透出，命令行只做透参。

特征树：从调用实例与实体表批量构建静态分层特征，替代对标项目中依赖大模型的那部分建树逻辑，输出供浏览与检索共用。

聚类：将共现图转为接口分组，区分经常协同的组合与可互换的替代品，输出分组标识供检索扩展与展示。

检索消费：双路召回加融合加挖掘加权加段落重组完整实现，含降级标记、重灌入口、增益基准。

治理与评估：审核状态机、版本内单仓不变式显式拒绝、多仓场景用不同版本号隔离、检索基准双轨门禁。

## 3. 特征树实现思路

职责定位：特征树负责分层聚合，与频次计数、序列挖掘职责不同，故单立一个挖掘模块，不塞入现有频次模块。模块保持纯内存，只收实体与调用行，不读数据库。

输入：版本内实体清单（含限定名、种类、父级、签名、参数、基类）与调用清单（含被调名、实参摘要、实参数、接收者、置信）。默认只用显式与推导两级，待定经开关纳入。

分层规则：按限定名点分逐级建节点，种类挂在对应层，调用特征挂为叶子。叶子携带实参元数、字面量种类分布、接收者种类，不存原始字面量值，避免引入执行语义。参数类型与返回注解来自抽取层已有结构化字段，只做整形与截断，不做推断。

频次挂载：每个节点记调用次数与覆盖作用域数，沿父链向上累加。展示用层级聚合与挖掘用精确计数在此分离，截断只消费精确计数，展示可按层取前若干。

持久化：编排层在模式挖掘之后批量建树，一次落一张特征节点表。表意为版本内路径、深度、种类、调用数、作用域数、父路径。历史数据要求重跑回填，不做兼容。查询侧按路径前缀浏览，不在请求时全量建树。

剪枝与规模：默认关闭剪枝；开启时按精确计数取前若干，仍受支持度阈值约束。超长作用域截断计数，保证算法侧无感知。

## 4. 聚类实现思路

职责定位：聚类负责分组，与序列负责先后顺序职责不同，故单立一个挖掘模块。同样纯内存，输入为作用域集合，输出为分组，不碰数据库与抽取包。

输入构造：调用方按作用域构造集合，作用域定义与共现统一，即文件加外围调用者。文件级聚合只作为调用选项，不作为默认口径。

相似度与算法：用集合重合度衡量接口亲密度，纯标准库实现层次合并，不引入数值或机器学习依赖。合并过程确定性排序，相同相似度按名称断开，保证重跑结果稳定。阈值、最小组规模、最大成员数全部由编排透参，默认取小库可验证取值，大库由调用方显式提高。

结果语义：协同组表示经常同作用域出现，替代组表示上下文相似但很少同现。两类都落同一分组表，靠组内共现密度区分，不另建两套表。分组表意为版本内组标识、成员限定名、组规模、代表成员。证据仍查询时计算，分组只存成员关系。

消费方式：检索命中某成员时，同组兄弟作为扩展或备选展示，加权幅度小于直接频次加权，避免排序退化为分组排序。挖掘查询新增按组过滤能力，出口层薄封装。

## 5. 检索消费闭环实现思路

流水线落在既有规划的检索模块，不另起融合模块：双路召回、融合、挖掘加权、段落重组按序执行，全文单路保留为降级路径。向量不可达时标记降级返回，不在向量封装内静默降级。

召回：全文一路按既有权重取候选，向量一路按版本过滤取候选，各取三倍行数与固定下限的较大值，保证重排与重组有材料。编码文本构造与写入侧共用同一组装，保证查询与写入一致。模型或维度变更走既有集合治理，删集合后按真源重灌，重灌入口由服务层提供。

融合：只消费排名做倒数秩融合，权重与平滑常数全部进配置。文档语料全文通常强于向量，权重向全文倾斜，不取等权。缺席一路的候选在该路贡献为零。

挖掘加权：只对融合后前若干名做乘法有界加成，加成随支持度对数增长并归一到区间内，上限由配置约束，零加权时为无操作。信号按优先级取最大者：命中模式的支持度、接口精确频次归一值、同组兄弟的最大支持度。权重过大使排序退化为支持度排序，故配置上限保持小值。

桥接键：文档块到接口的归属按块内提及的限定名后缀匹配建立，命中多个取最大支持度；无提及时退化为版本级全局最大，不做无依据的强加权。代码来源的证据查询走既有有序子序列匹配，不受此桥接影响。

段落重组：按地址分组，命中块向后扩展兄弟块与父标题块至整节，片段取扩展后上下文，结果附来源路标记供调试。版本归属必填，库名缺省取最新版本，显式版本覆盖。

基准门禁：黄金集标注来源，指标用平均倒数排名与召回率，双轨记录全文单路与混合路，混合增益不足阈值则标红而非放宽阈值。频次与分组增益单列记录，不混入主门禁。阈值文件变更需显式说明。

## 6. 执行顺序与验证

先收敛统计口径，再建特征树，再做聚类，最后接检索。统计口径收敛是前置，否则树与组的频次不可比。特征树依赖实体语义稳定，聚类依赖作用域口径统一，检索依赖两者落表。

验证以小库端到端为锚：已知闭合模式存在且支持度精确、特征树路径可按前缀浏览且频次上下一致、已知协同接口同组且可互换接口不同组、检索三样例覆盖双路命中与单路命中、降级标记正确、向量对账一致、二次建索引三表行数不变、阈值单调收缩。每收敛一步做一次全量测试，输出重定向到文件后阅读，不在中途反复全量运行。

## 7. 本次不做

向量重排模型接入、跨函数跨文件长序列挖掘、语义特征演化与指令生成、前端审核界面与令牌鉴权界面、中文分词更换、多版本混合检索、历史数据兼容，均不在本次范围。旧库要求重跑建索引与重挖模式后才有新信号。
