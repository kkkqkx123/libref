# 基准回放问题修复方案

依据：本轮 24 个夹具建库、文档特征回放与检索矩阵评测的失败项。本文只描述改动意图与验收口径，不写完整代码。

## 修复范围

本轮完成两项代码修复，第三项经差分验证后决定不改：

1. **FluentValidation 原始源码副本入料**：站点把 Sphinx 的 `_sources/*.md.txt` 和渲染 HTML 一起列进 sitemap，造成同文两份、约一半文档块重复。文档获取配方增加 `exclude_patterns`，复用 `crawler.scope` 已有的排除规则；该字段进入归档配方摘要，规格一旦变化必须重新获取。只重取该文档夹具，随后重建数据集并复核重复页消失。
2. **清单身份误报**：NuGet 包名在归档里已归一为小写，而规格保留展示名；Go 模块声明的是导入路径，规格用的是短名。新增纯函数按生态归一比较：非 Go 生态大小写不敏感，Go 取导入路径最后一段并去掉 `vN` / `.vN` 版本后缀再比较。告警只比较身份，不改变库表落库名称；补纯函数测试覆盖两种误报与真实漂移。
3. **答案性判定对通用词过敏：词频加权方案不采用**。先在 `store/evidence.py` 试做候选池词频加权，并在全部 705 条检索结果上做差分：该改动没有提高 `zod/docs`、`pydantic/docs` 的弃答率，却把 `zod`、`vue`、`Rocket` 源码夹具的误弃答率从 0.14–0.20 抬到 0.29 左右，越过 0.25 门禁。全局抬阈值同样是以误弃答换弃答。词频加权代码已回退；后续在全部 2619 条三方法记录上验证了有界覆盖集中度扣减方案，详见 `docs/plan/benchmark-failures-analysis.md`。

## 不做的事

- 不改 `gates.json`。归档修订绑定已经过期，门槛重测需要判定集与漂移抽检先稳定；本轮不借修 bug 之机改阈值。
- 不替人工补判定集。新增六套文档夹具没有人工确认的实体与锚点，无法作为效果证据；这是数据工作，不是代码修补。
- 不给 `httpx/code-head` 的漂移门禁打补丁。默认分支天然会移动，重新获取后修订变化是预期行为；固定 ref 会改变夹具身份，应和门禁重测一起做。

## 验收结果

- `uv run pytest -q`：`916 passed, 36 skipped`；`ruff check`、`ruff format --check`、`mypy src` 均通过。新增的排除规则与身份归一测试可手算复核。
- FluentValidation 归档以新修订 `f8715ff9d669` 重新获取并通过摘要校验；重建后页数 61→31、文档块 799→397，`_sources` 页面归零，判定目标仍全部存在。
- 检索矩阵评测回到 14 项失败：10 项门禁修订过期、4 项已知的弃答率不足；本次改动没有新增误弃答失败。构建日志里的四条清单身份告警消失，库表没有新增重复实体。
- `tests/e2e/bench/README.md` 已更新配方字段说明和规模表；计划文档记录了仍未解决的非代码项与差分结论。
