# P2 关系挖掘数据形式问题清单与修改方案

> 依据：课题需求（官方文档之外的真实调用顺序与参数使用模式）、三层架构（挖掘构建与知识库检索的依赖方向）、源码挖掘链路细化方案。
> 目标：调用实例到序列模式的数据构造保序、去噪、可溯源；频次与共现可被检索消费；相对导入不再静默丢弃。
> 范围：只改原有模块，不新增替代模块，不新增数据迁移，不动算法本体。

## 1. 问题清单

现状链路为抽取调用实例落 `call_instances`，再按外围调用者分组排序成序列，经归一化后由自研挖掘器产出闭合模式落 `seq_patterns`。逐项核对后的缺口如下：

- 序列排序键降级。抽取时已算好组内序号与字节偏移，但组序列时只按起始行排序，同行多调用的先后顺序失真，直接污染调用顺序语义。
- 待定调用污染支持度。别名无法解析的调用与已解析调用等权进入序列，噪声抬高无意义模式的支持度；其审核落库不受影响，问题只在挖掘入口。
- 幽灵模式不清扫。实体与调用落库均按语义键集合清扫已消失行，模式表只做存在即更新，删源码后旧模式永久残留。
- 显式剪枝语义错误。剪枝用的层级计数含点分前缀父级，按深度取前若干会误删同等频繁的叶子，且与支持度阈值叠加后行为不可解释。
- 频次与共现无消费方。层级频次只在剪枝分支内用一次，共现矩阵零调用方；检索服务没有任何频次与共现查询，技术栈规划的频次重排无数据源。
- 模式不可溯源。模式行只有名称数组与支持度，无来源实例引用；调用实例层的实参、文件、行范围、置信在模式层面全部丢失，参数使用模式无法追问。
- 相对导入静默丢弃。相对导入一律返回空别名，上下文模块的模块路径推导与相对展开函数无人调用；包内调用被记为待定而非推导。

## 2. 修改方案

全部落在原有模块内，按依赖方向挖掘保持纯内存、落库与查询由服务层编排。

### 2.1 挖掘入口保序与去噪

序列构建的排序键改为起始行、字节偏移、组内序号、行标识四级，输入输出仍为纯限定名序列，算法侧无感知。挖掘默认只取显式与推导两级置信，待定调用仍落库与送审，只是不参与组序列；调用方显式要求时才纳入。两者均为入口过滤，不动抽取与解析。

### 2.2 模式清扫与剪枝修正

模式落库后按版本号删除不在本次产出集合中的旧行，返回清扫计数，与实体调用两表的清扫语义对齐。显式剪枝改为按完整限定名的精确计数取前若干，不再使用含前缀父级的层级计数；层级聚合函数保留作展示用途，不再进入挖掘主路。剪枝仍为显式选项，默认关闭。

### 2.3 检索侧补齐频次共现与溯源查询

不新增落库表，频次、共现、证据均在查询时由调用实例与模式表现算，保证与真源一致且无需迁移。检索服务新增五个只读查询：单接口调用次数与覆盖作用域数、单接口实参形态分布、单接口同作用域共现接口、版本内模式列表（含包含过滤）、给定模式的有序子序列证据（返回文件、外围调用者、行范围、实参、置信）。出口层按零业务逻辑原则薄封装：命令行挖掘子命令只加待定纳入开关，任务载荷随之扩展；知识库检索工具新增三个只读工具复用同一查询。

### 2.4 相对导入展开

抽取引擎按相对路径推导当前模块路径并传入别名构建；相对导入文本经相对展开函数换算为绝对模块前缀后，再按既有绝对导入逻辑拼接被导入名。绝对导入与通配行为不变；声明的限定名暂不加模块前缀，跨文件同名仍走既有按距离消歧，相对解析结果落在声明集合之外时置信为推导。

## 3. 验证

迷你仓库端到端保持通过，模式产出不变；新增用例覆盖同行多调用保序、待定默认排除与显式纳入、删文件后模式清扫、精确剪枝语义、五个检索查询的黄金样例、相对导入别名展开。收尾合并为一次全量测试运行，输出重定向到文件后阅读。

## 本次不做

声明限定名加模块前缀、模式行内持久化证据列、向量与重排集成、前端审核界面，均不在本次范围，待本链路正确且可观测后再做。
