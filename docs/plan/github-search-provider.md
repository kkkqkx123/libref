# GitHub 模糊搜索 provider 设计（下一阶段）

## 背景

精准提取失败时，仓库地址补齐的最高精度来源是代码托管搜索：
结果自带可直接克隆的仓库地址，常附带文档站，歧义时可用热度与描述确认。
本方案将其补为显式调用的独立入口，与网页搜索入口对称。
解析失败路径本身不自动调用，结果标注未核实，确认后走显式地址使用。

## 现状

搜索 provider 与结果映射已存在，挂在无生态限定的模糊发现扇出之下，
双重门控：仅不限生态时参与，且必须配置令牌。精确解析完全不经过该来源。
实测无令牌也可调用，匿名配额可用，结果质量满足仓库补齐要求。

## 非目标

- 解析失败不自动回填，精确解析保持纯注册表语义，离线语义不受影响。
- 不写覆盖文件，不污染版本分区与注册表快照缓存之外的存储。
- 不把该来源并入无生态扇出的默认行为，避免批量扇出耗尽匿名配额。

## 服务入口与门控

- 服务层解耦出独立显式入口，不经过注册表扇出。入口校验查询与条数，
  复用发现开关与离线语义，离线直接报错。
- 有令牌则携带，无令牌走匿名配额；限流与拒绝统一归为可重试类，
  线索提示配置令牌。令牌只走环境变量。
- 结果映射沿用现有形态，来源标为托管搜索，无仓库的沿用缺仓库标注。

## 出口与调用方式

- MCP 与命令行各加一个薄出口，只做参数校验加服务调用加结果整形。
- 失败指引中增加条件式文本提示该入口的存在，不发起网络请求。

## 排序规则

- 该来源进入统一排序时注册表来源优先，按热度排其后，
  避免外部热度压过注册表精确命中。显式单查无混合问题，
  规则用于约束后续可能的扇出合流。

## 落地顺序与验证

- 先交付服务入口解耦与薄出口，单测覆盖映射关系已基本具备，补齐即可。
- 集成测试用注入传输断言成功映射、匿名请求头、限流与拒绝分类、
  离线拒绝。
- 端到端用真实网络断言返回结构正确，限流与拒绝按环境不可用跳过，
  不视为回归。
- 合并为尽量少的一次全量测试运行，输出先落盘再读。
