# CLI 客户端拆分后续修正

密钥管理边界与后续架构任务的收口见 `admin-key-management-and-cli-boundaries.md`。

本文列出 `8a76c60 split cli client` 之后仍需处理的问题与实施顺序。命令边界以 `cli-client-split.md` 为准，客户端继续只经 HTTP 访问 Web API。

## 问题清单

1. 本机路径索引、本机仓库探查、直接挖掘与文档派生特征重建被整体删除，没有按方案保留在服务端本机 CLI。服务层仍保留“本机路径只由命令行使用”的约束，但对应入口已不存在。
2. 部署示例 `deploy/libref.toml.example` 仍含已删除的 `[client]` 配置段，按示例启动会因未知配置段失败；部署说明仍引用旧远端模式。
3. `tests/e2e/probe-discovery` 采集脚本仍调用已删除的旧命令；快照只改了 argv 标签，内容与当前 CLI/客户端输出形态不一致。
4. 客户端的用法与配置错误仍可能绕过统一 JSON 错误信封；`target_filter` 等非对象 JSON 参数会触发未包装异常；配额错误的字典型 `detail` 会被压掉。
5. `packages/librefctl` 未纳入常规 ruff/mypy 检查路径；命令表与 Web 路由的一致性、布尔三态、JSON 参数、客户端与 Web 响应的差分测试尚未覆盖。

## 阶段一：恢复服务端本机入口

新增服务端本机命令模块，只保留必须触达本机资源的入口：仓库索引（仅本机路径，远端仍走索引申请）、仓库探查、直接挖掘、标签归纳、文档派生特征重建。文档探查不在此列，统一由 `librefctl doc-probe` 提供。命令只调用服务层，不读取客户端配置，不带 `--remote`，不提供检索问答等面向 skill 的只读能力。

更新服务端 CLI 解析器、运维文档、探查与架构文档，明确这些命令只在服务端主机可用；更新服务端 CLI 解析测试，断言本机入口存在且客户端命令仍不存在。

## 阶段二：修复部署配置与说明

删除部署示例中的 `[client]` 段，修正部署说明中的配置段清单和 dev 模式描述，使示例配置可被当前配置加载器接受。

## 阶段三：修正探查采集链路

采集脚本分为两条路径：本机路径探查调用服务端本机 CLI；HTTP 探查与发现通过 `librefctl` 的 HTTP 传输访问进程内 Web 应用，不再直接调用服务层。快照的 argv 标签与输出形态随实际入口同步。

## 阶段四：收紧客户端边界

客户端解析错误和非法环境变量走同一个 JSON 错误信封与退出码 2；JSON 对象参数先做形状校验再进入请求体；服务端字典型错误详情保留可读信息。

补充解析、三态布尔、JSON 参数、命令表路由一致性以及客户端与 Web 响应差分测试。

## 阶段五：接入验证路径

把 `packages/librefctl` 纳入 lint、format 与类型检查路径，更新开发命令说明。验证以最终测试与静态检查为准；本阶段不新增发行包或版本。
