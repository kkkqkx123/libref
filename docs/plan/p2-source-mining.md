# P2 源码挖掘链路细化修改方案（分支 B）

> 依据：技术栈与模块划分两篇架构文档，以及知识图谱抽取、特征树频次、序列模式挖掘三篇对标分析。
> 目标：最小验证链路为仓库源码到调用实例，再到频次统计，最后将闭合序列模式落入序列模式表。
> 范围：新建源码抽取包，补齐频次、共现、归一化三个纯内存挖掘模块，扩展编排层与命令行出口，新增一次数据迁移。

## 0. 设计评审结论

原设计主干合理，予以保留：复用已落地的序列挖掘器与任务队列，不重写；声明式语言配置与通用抽取引擎的两层划分成立；两遍解析与三级置信划分成立；挖掘模块保持纯内存、落库由编排层完成的依赖方向成立；本阶段不扩展检索与审核出口的范围裁剪成立。

评审发现七处必须修正的硬伤，本次一并改入下文设计：

- 调用实例表缺少库版本归属。原表只有仓库名字符串，没有库标识与版本标识，编排层无法按版本过滤调用、无法写入版本隔离的序列模式表。本次以新迁移补齐库标识、版本标识与外围调用者字段，语义明确为同一库版本的自举源码挖掘，仓库名只做溯源。
- 缓存与仓库登记缺仓库维度。原缓存主键只含路径，跨仓库同名相对路径会互串。本次主键与读写一律带上仓库名，仓库登记表记录名称、来源地址、提交标识与本地路径。
- 指纹定义含糊。原指纹取语言描述符标识，升级语法包后未必变化。本次改为运行时版本加语法包版本加节点类型声明加配置版本的联合哈希，任一升级都使缓存失效。
- 频次剪枝误用。特征树场景的每层保留前若干名是展示用剪枝，直接放在挖掘主路会误删达到支持度的模式。本次主路默认不剪枝，仅当字母表过大时由调用方显式开启，结果仍受支持度阈值约束。
- 支持度默认值与小库验证冲突。固定下限二十在只有数个文件的验证仓库上恒得空结果。本次命令行默认支持度为二，大库调用方按序列规模自适应提高，不在代码中写死大数。
- 序列粒度缺外围调用者。原调用记录只有文件与行范围，文件级序列会把无关函数调用串成伪序列。本次抽取时记录外围函数限定名，序列构建优先按外围函数分组，缺失时回退到文件。
- 共现在主路空转。共现矩阵当前没有落库消费方，放在每次挖掘中计算是浪费。本次将其拆为独立函数，按需调用，挖掘主路默认不计算。
- 另有两处表述矛盾一并澄清：确定性标识不设冲突盐，语义键相同即同一实体；抽取记录的字段名与落库列名一一对应，不再出现两套命名；引用缺失的挖掘基线文档，不再作为阈值依据。

## 1. 现状盘点

序列挖掘器已实现，支持最小支持度过滤、按支持度取前若干、闭合模式判定与剪枝、加权扩展点与流式回调，本阶段只做编排接入，不改算法本体。

库表层面，接口实体、调用实例、序列模式、审核状态四表已落地，任务队列支持提交、消费、回写与心跳恢复。本阶段新增迁移只追加仓库登记与缓存表，并补齐调用实例的版本归属字段，不改动已有迁移的内容。

## 2. 交付物清单

依赖声明新增运行时解析核心、两种语言的语法包与纯 Python 的 Git 只读拉取能力，版本均已核实与当前解释器兼容。

数据层新增第四号迁移，内容为仓库登记表、增量缓存表，以及调用实例表的库标识、版本标识与外围调用者三列与配套索引。

新建源码抽取包，含包导出、语言配置、抽取记录模型、通用遍历引擎、两遍解析、增量缓存与仓库管理七个单元。

新建三个纯内存挖掘单元，分别为限定名与整数的双向映射、按点分层的频次聚合与可选剪枝、文件级共现计数。共现单元独立于挖掘主路。

编排层新增仓库建索引与模式挖掘两个函数，复用任务队列的提交与消费机制。命令行新增建索引与挖掘两个子命令，默认同步执行，可选经队列异步执行。

测试新增抽取、频次共现、端到端三组，外加一个三至五个文件的手写迷你验证仓库。

## 3. 设计决策

### 3.1 语言配置

语言配置为不可变声明，每种语言一项，描述该语言的类、函数、导入、调用四类节点类型名，调用节点的函数字段名，成员访问节点类型，支持接收者推导的语言标记，文件后缀集合，语言专属钩子与配置版本号。起步提供 Python 与 Java 两项，新增语言只加配置不改引擎。

引擎启动时做自检，配置元组非空、后缀合法、语法包可导入且解析器可构造，任一失败即显式报错，避免语法包漂移导致静默漏抽。

指纹为联合哈希，输入包括解析运行时版本、语法包版本、四类节点类型声明与配置版本。任一输入变化即全量失效缓存，这是已验证的安全升级路径。

### 3.2 抽取记录与确定性标识

接口声明记录含限定名、种类、所在文件与起止行。调用实例记录含解析后被调名、原始文本、实参摘要、调用者文件、外围调用者、起止行、置信与所属仓库。实参只记位置参数的字面量摘要与关键字名，非字面量记统一占位以保留元数，不求值，避免引入执行语义。

字段名与落库列名一一对应，避免两套命名漂移。实体标识为版本标识、限定名、种类的联合哈希。调用标识为仓库名、调用者文件、起止行、被调名、实参连接串的联合哈希。两表各有唯一约束保证幂等重跑， upsert 语义为存在即更新，不设冲突盐。

### 3.3 两遍解析与置信分层

第一遍逐文件收集声明与导入别名，汇总为全局事实表，声明含类与函数的限定名，导入含模块别名与来源别名的映射。第二遍解析调用，被调名的首段若命中别名表则替换展开，若根为自身引用则替换为外围类，得到解析后限定名。

置信分三级。解析结果落在仓库内声明集合中为显式抽取。经导入别名唯一指向外部模块为推导。存在多候选或无依据为待定。待定调用在落库时于审核表记一条待审，审核工作流本身归后续阶段。

### 3.4 增量缓存

缓存表以仓库名、相对路径、指纹、配置版本为主键，另存文件内容哈希与抽取记录。逐文件先算内容哈希，命中则复用记录并计数，未命中则解析后写回。内容变化、语法包升级、配置版本变化任一发生即失效。不做基于修改时间的预检优化，批量场景下哈希开销可控。

### 3.5 挖掘执行顺序

建索引流程为获取仓库、按后缀与排除规则遍历文件、缓存过滤、引擎抽取、两遍解析、落库。落库时先保证库与版本行存在，再幂等写入接口实体与调用实例，待定调用同步记审核待审。

模式挖掘流程为按版本读出调用实例，按外围调用者分组，缺失者按文件分组，每组按行序组成限定名序列。限定名经归一化转为整数序列库。挖掘器以给定最小支持度做闭合模式挖掘，结果经反归一化还原为限定名序列后落入序列模式表，闭合标记置位。命令行默认最小支持度为二，调用方在大库上可按序列规模自适应提高。频次聚合的层级按限定名的点分段定义，剪枝仅作为显式选项，默认关闭。共现计数为独立函数，不在主路调用。

### 3.6 纯内存硬约束

归一化、频次、共现、序列挖掘四个单元只接受纯数据结构，禁止引用数据层与抽取包。限定名与整数的映射表由编排层从库中读出后传入，保证算法可离线单测。

### 3.7 仓库获取

仓库管理以库数据目录下的固定子目录为根。远端地址首次拉取为浅克隆，已存在且要求更新时拉取更新并记录提交标识。本地目录直接使用，提交标识记本地标记，不做网络操作。文件遍历按语言后缀过滤，排除版本控制目录、缓存目录、依赖目录、测试目录与压缩产物，文件名含测试标记的按文档抓取分支的同名语义剔除。

### 3.8 出口与任务

命令行建索引子命令接受库名、版本与远端地址或本地路径，更新开关控制已存在仓库是否拉取。挖掘子命令接受库名、版本、最小支持度、剪枝规模与最大长度。两者默认同步执行，加异步开关后经任务队列提交，由同进程工作线程消费并回写任务表。本阶段不新增检索类出口。

### 3.9 依赖方向

抽取包可依赖数据层、解析运行时与拉取工具。挖掘包除自身外无依赖。编排层可依赖抽取、挖掘、数据与知识库。三出口只调编排层。向量引擎的唯一触达点不变。

## 4. 验证标准

抽取验证以迷你仓库的调用实例为黄金样例，逐条比对被调限定名、实参摘要与行范围。另以标准库解析器对同一文件做调用集合的抽样交叉比对，要求无差异。

两遍解析验证要求别名导入的调用被展开且置信为推导，仓库内声明的调用为显式抽取，多候选或未解析的调用为待定且审核表出现待审行。

增量与幂等验证要求同仓库二次建索引全部命中缓存且两表行数不变，指纹变化后全量失效重解析。

频次与共现验证以手算小数据为黄金样例，比对层级计数、剪枝结果与共现矩阵。

端到端验证以迷你仓库跑通建索引到序列模式落库，要求已知闭合模式存在、支持度精确、闭合标记置位，全量测试通过且既有功能不回归。
