# 基准归档的消费、校验与生产持久化取舍

本轮要解决两件事：生产是否也改成归档文件；基准归档在消费与校验上还缺什么。
结论先行：生产不改归档；基准归档补齐规格漂移校验、失败清理、流式读取、摘要校验收敛与
数据集目录保护。

## 一、生产是否改用归档文件

**结论：不改。** 归档与生产持久化优化的是相反的目标。

生产的两处持久化各自承担增量与回收职责：

- 源码：`repos_dir/{生态}/{库}/{版本}` 是一个可写的版本库检出。索引器按文件随机读，
  增量路径按单个文件重解析，更新路径在原地拉取，配额回收按版本整目录删除。
- 文档原始正文：快照库是"一个 URL 一个 blob"的归档，文件名是 URL 的散列，同名目录按版本切分。
  它服务于净化缓存命中、按版本淘汰与运维审查。

归档形态（一份不可变载荷 + 一份元数据）优化的是相反的特征：整体不可变、单一摘要、
整体复制、一次性消费。把它搬进生产会有三处直接退化：

1. **随机访问退化**：每个版本一个包，任何单文件操作都要先整包展开；而生产的热路径恰好是
   "按文件解析、按文件复用缓存、按文件热更新"。
2. **回收粒度退化**：配额与保留策略按版本目录与单文件计数实现，打包后只能整包淘汰，
   也无法按单文件统计体积。
3. **增量退化**：版本库本身已是内容寻址、差分压缩、可拉取；再包一层只会把增量变成全量重打包。

**路径层级不是冗余**：生态、库、版本三段就是身份本身，多版本共存、按版本键复验、
按版本回收都依赖它。基准之所以能把身份挪进元数据、把路径压成"项目/分支"两级，是因为
它每个项目分支只需要一份、永不原地更新、没有配额回收——需求不同，形态才不同。

因此：归档只属于基准。生产侧本轮不动。

## 二、基准归档在消费与校验上的缺口

### 缺口一：规格漂移没有被发现

文档声称"规格被改动但没有重新获取会在校验步骤暴露"，但校验只比对身份五字段，
获取配方（入口、页数上限、抓取延迟、仓库、子目录）不参与比对。改了 `bench.json` 的入口地址
或上限而不重新获取，校验照样通过，语料与规格静默不一致。

修改：配方由归档模块一处推导，获取时写进元数据，校验时逐字段比对；不一致即失败并提示重新获取。

### 缺口二：获取失败会留下半个归档

获取先落载荷、再写元数据、最后校验。任何一步失败，目录已经存在但没有通过校验，
下一次获取会被"已存在归档"拒绝，只能靠重新获取参数绕过。

修改：获取失败时清掉本次新建的目录，保证"失败等于没有发生"。

### 缺口三：整个语料一次读入内存

页面载荷目前解成列表再逐页消费，内存随语料线性增长。当前只有 23 页（正文约 1MB），
但多项目与更大站点会把这条路走死。

修改：读页面改为逐页迭代；内容摘要核对也走迭代，只在核对时累计页数与地址集合摘要。

### 缺口四：同一次获取里重复做整档摘要

获取过程对载荷做了三次完整摘要：写完一次、确认一次、返回前再一次。内容确认与最终校验
各做一次足够。

修改：写后做一次内容确认，置只读后做一次最终校验（身份加载荷摘要）。

### 缺口五：构建会无差别删除输出目录

构建先删输出目录再重建。传错路径（例如指向仓库根或别处的数据目录）会直接删掉不属于基准的
内容。误用代价远大于收益。

修改：只接受"不存在、空、或者只含数据集已知成员"的目录；其余直接拒绝并说明。

## 三、实施顺序

1. 归档模块：配方推导、配方比对、流式读页与内容核对、失败清理。
2. 获取脚本：改用共享配方与流式核对，收敛摘要次数。
3. 构建脚本：流式消费页面，输出目录成员校验。
4. 现有两份归档的元数据按新配方形态重写（载荷不变，修订不变），校验通过后再次只读冻结。
5. 文档：`docs/bench/design.md` 补生产持久化取舍与本轮改动；`tests/e2e/bench/README.md`
   补数据集目录约束。

## 四、验收

- 改 `bench.json` 任一配方字段后构建必须失败，改回后必须通过。
- 获取中途失败不得留下目录。
- 构建指向含未知成员的目录必须拒绝，`data/` 正常重建。
- 页面读取全程不出现整语料列表；两份归档校验、构建、评测、门禁全部通过，指标与改造前一致。

## 五、落地结果

- 生产持久化未改动，取舍依据写入 `docs/bench/design.md`。
- 归档校验比对身份＋获取配方＋载荷摘要；改规格不重新获取会被拒（已实测）。
- 获取改为"暂存目录写完再替换归档"，失败不落半个归档，也不破坏上一份归档。
- 页面载荷逐页流式读取，内容摘要核对不保留整语料。
- 同一次获取的整档摘要由三次降为两次（内容确认一次、置只读后最终校验一次）。
- 构建只接受空目录或已知数据集成员目录（已实测：含其他文件时拒绝且原目录保持不变）。
- 现有两份归档按新配方形态重写元数据，载荷与修订不变；构建、评测、门禁与全量测试通过，
  检索指标与改造前逐项一致。
