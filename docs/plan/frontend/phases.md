# 前端分阶段实施方案

> 按 `README.md` 的落地顺序展开为可独立验收的阶段。每个阶段只依赖已存在的后端能力
>（含已落地的鉴权补强与响应契约，见 `docs/plan/auth-openapi-prefrontend.md`），
> 不等待后续阶段。阶段编号即建议实施顺序。

## 阶段零：工程骨架与契约接入（前置一切页面）

- 建 `webui/` 独立 npm 工程：Vite + Vue 3 + Element Plus，开发期代理到本地 `8001`，
  产物由 Python 自托管（托管结论见 `docs/architecture/frontend-hosting.md`）。
- 按后端 `/openapi.json` 生成 API 类型与客户端（参考 linkrs 的 `gen:api` 做法：
  描述文件入库、生成物可复核），请求层统一注入凭据、请求标识与错误转译
 （401 转登录、403 转无权限说明、429 读重置时间）。
- 建设计令牌单源与一致性检查脚本（做法见 `style-guide.md`），以及登录态、
  全局限定的筛选器、主题三份全局状态。
- 搭应用外壳：顶栏（健康状态点、登录态）、侧边导航（按权限 scope 显示隐藏）、
  内容区（含降级横幅与空态插槽）。
- 验收：空页面骨架可登录、可登出；契约检查脚本与类型生成纳入流水线；
  构建产物被 Python 末位 SPA 回退正确托管。

## 阶段一：检索问答（只读核心）

- 页面：文库目录、搜索、问答、文档阅读器（范围见 `pages.md`）。
- 组件：全局三元筛选器、结果列表、引用块、阅读器三种模式切换、联想建议区。
- 状态：可回答性与降级原因展示、无证据空态、向量降级提示。
- 验收：从目录下钻到搜索再到阅读器全链路可用；零结果、低证据、降级三种状态
  各有明确展示；深链可分享复现。

## 阶段二：源码洞察（只读扩展）

- 页面：API 洞察、调用、符号、导入、模式、健康度。
- 组件：标签输入（逗号多值）、置信徽章、证据列表、调用与符号双向跳转、
  模式筛选器组、健康度标红。
- 验收：五个洞察视图筛选与分页正确；模糊调用默认置灰；证据可跳回阅读器核验。

## 阶段三：入库引导与任务中心（首次写操作）

- 页面：入库向导（三步：解析定位、探测评估、正式提交）、任务中心。
- 组件：发现结果一键填入、参数表单校验、任务轮询器、失败重提。
- 验收：向导提交后跳任务详情并轮询到终态；目标不合规与配额超限有明确提示；
  跨租户不可见任务返回未找到而非越权数据。

## 阶段四：审核反馈与系统管理（高权限）

- 页面：审核队列、反馈、密钥管理、配置刷新、指标。
- 组件：审核单条处理与自动定位下一条、反馈带入实体、密钥一次展示与复制、
  高危操作二次确认。
- 验收：非法流转 409 展示当前状态；无权限角色看不到对应页面；
  密钥原文关闭后不可再查。

## 阶段五：打磨（可选，不阻塞上线）

- 深色主题与密度切换、返回不丢位、错误文案统一校对。
- 国际化按 `i18n.md` 落地：默认中文界面，首批支持英语，采用编译期类型化词条；
  词条完整前不暴露切换入口。

## 与 linkrs 经验的对应

- 描述文件入库加类型生成、Mock/预览模式、令牌一致性检查脚本、布局三件套
  （顶栏、侧边栏、页头）、能力门控映射，均借鉴 linkrs 前端做法，
  仅框架层按本项目既定技术栈换成 Vue 3 + Element Plus。
