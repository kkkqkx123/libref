# 前端国际化 (i18n) 设计方案

> 范围：`webui/` 的多语言支持。以现有 Vue 3 + Element Plus + TypeScript 工程为基座，
> 不改变后端契约与托管方式。默认语言为简体中文，首批新增英语；后续语言按同一结构扩展。

## 1. 背景与目标

- 现状：全部界面文案直接写在 Vue 模板与 TypeScript 中，Element Plus 使用 `zh-cn` 语言包，
  路由标题为中文字符串，`api/client.ts` 的错误回退文案为中文。
- 目标：支持运行时切换语言（首批 `zh-CN` 与 `en`），切换后无需刷新页面，选择持久化；
  词条具备编译期类型安全，缺失或多余词条在构建期失败；不翻译业务数据。
- 非目标：不翻译库名、符号名、URL、后端 `detail` 原文；首批不支持从右到左 (RTL) 布局；
  首批不改造后端本地化。

## 2. 现状盘点

- 文案规模：模板与脚本中约三百处中文字符串，分布在页面、通用组件、状态存储与路由。
- 错误语义：后端 `detail` 为英文原文；前端 `describeFailure` 提供中文兜底文案。
- 依赖：当前无 i18n 依赖，Element Plus 已自带多语言包。
- 托管：产物由 Python 自托管，语言包必须随前端产物一起交付，不新增服务端逻辑。

## 3. 设计原则

1. 编译期词条：采用类型化词条目录，插值使用函数而非占位符字符串。
   函数的参数个数与类型由 TypeScript 约束，翻译者无法拼错占位符。
2. 单一真相：定义一个 `MessageCatalog` 类型；每种语言一个实现，形状必须一致。
3. 仅界面壳层：只翻译导航、标签、状态、空态、错误态、表单与帮助文案；
   业务数据原样展示。
4. 默认中文：未识别或不受支持的语言一律回落到 `zh-CN`；不生成机器翻译的伪语言包。
5. 运行时切换：语言变化后所有组件自动更新，不丢失筛选器、登录态与路由位置。
6. 可测试：词条完整性、空字符串、函数返回类型、组件快照均纳入门禁。

## 4. 技术选型

- 不引入 `vue-i18n`。运行时键查找会削弱类型安全，且增加依赖与包体积。
- 采用轻量自研方案：类型化目录 + Vue 响应式 + 动态导入语言包。
- Element Plus 语言包直接复用其官方 locale 对象，通过 `el-config-provider` 注入。
- 数字、日期、百分比使用 `Intl` API，不手写格式规则。

选型理由：与项目既定的“编译期词条”经验一致，且避免运行时字符串键拼接；
类型检查可直接覆盖所有语言实现。

## 5. 模块结构

建议新增目录：

```
webui/src/i18n/
  types.ts          # MessageCatalog 类型与领域分组
  locales/
    zh-CN.ts        # 默认语言，完整实现
    en.ts           # 英语实现
  index.ts          # 当前语言状态、检测、持久化、useMessages
  format.ts         # Intl 数字/日期/相对时间封装
  element.ts        # Element Plus locale 映射与动态加载
```

- `types.ts` 只定义类型与分组，不包含文案。
- 每个语言文件导出一个对象并声明满足 `MessageCatalog`，编译期校验形状。
- 单文件过长时，可按领域拆分为 `locales/<lang>/<domain>.ts`，再由
  `locales/<lang>/index.ts` 聚合；类型约束不变。

## 6. 词条组织与插值

- 领域分组与页面/组件域对齐：`app`、`nav`、`common`、`search`、`answer`、`reader`、
  `catalog`、`insights`、`ingest`、`jobs`、`review`、`feedback`、`admin`、`auth`、
  `errors`、`routes`。
- 动态文案全部写成函数，例如删除确认、计数、偏移提示；禁止 `"共 {n} 条"` 这类
  占位符字符串。
- 复数与数量表达由函数内部处理；需要 locale 感知的复数时，使用 `Intl.PluralRules`。
- 长文本（如帮助说明）使用字符串数组，便于逐段翻译与渲染。
- 共用文案（确认、取消、复制、刷新等）只在 `common` 定义一次。

## 7. 运行时切换与状态

- `index.ts` 维护一个 `locale` 响应式引用与 `messages` 计算属性。
- 组件通过 `useMessages()` 获取当前目录；模板引用 `m.nav.search` 形式，
  语言切换时自动更新。
- `setLocale(next)` 校验支持列表，更新引用，持久化到本地存储，并更新
  `document.documentElement.lang`。
- 根组件使用 `el-config-provider` 包裹应用，其 `locale` 绑定到当前
  Element Plus 语言包的计算属性；切换语言时动态导入对应包。
- 主题、筛选器、登录态不受语言切换影响。

## 8. 语言检测与持久化

检测优先级：

1. 地址栏查询参数 `?lang=`（用于分享特定语言的深链）。
2. 本地存储中的已保存选择。
3. 浏览器 `navigator.languages` 中首个受支持语言。
4. 默认 `zh-CN`。

- 用户显式选择后写入本地存储，后续访问优先使用。
- 不支持的语言代码一律回落默认，不抛错。
- 语言选择不写入业务状态或 URL 路由，避免干扰深链参数。

## 9. 路由与文档标题

- 路由元信息中的中文标题改为词条键（例如 `routes.search`）。
- `beforeEach` 中根据当前语言解析标题并设置 `document.title`。
- 语言切换时，若当前路由未变化，需额外触发一次标题更新（监听 `locale`）。
- 404 回退与重定向标题同样走词条，避免硬编码。

## 10. Element Plus 与第三方库

- Element Plus 语言包按需动态导入，避免默认把所有语言打入首包。
- 日期选择、分页、空态等组件全部跟随 `el-config-provider`。
- 图标与无文本控件不受影响。
- 图表或第三方库如后续引入，需单独评估其本地化方式。

## 11. 后端错误与 i18n

- `describeFailure` 中的 HTTP 状态兜底文案迁移到 `errors` 词条。
- 后端 `detail` 原文继续展示，保证可追溯与审计对账；前端只追加请求标识与配额重置时间。
- 可选后续阶段：后端错误响应增加稳定 `code` 字段，前端按 `code` 查表翻译；
  此阶段需同步修改契约与类型生成，但不阻塞界面壳层国际化。
- 后端本身保持英文错误文本，不引入服务端本地化。

## 12. 格式化

- 新增 `useFormatter()`，基于当前语言封装 `Intl.NumberFormat`、`DateTimeFormat`、
  `RelativeTimeFormat`。
- 页面中的计数、百分比、日期、偏移量统一通过该封装输出。
- 避免在模板中手写 `{{ n }} 条` 这类夹杂文案与数值的字符串。

## 13. 布局与样式影响

- 英文通常比中文更长，按钮、表头、徽标可能出现溢出。
- 文本容器使用弹性布局与最小宽度，避免固定像素宽度；必要时允许换行或截断。
- 为长文本提供统一截断工具类，避免各页面重复实现。
- 不在首批支持 RTL；结构上保留 `dir` 属性扩展点。

## 14. 测试与门禁

- 类型检查：每个语言文件必须满足 `MessageCatalog`，缺失字段直接编译失败。
- 单元测试：词条键集合在各语言间一致；无空字符串；插值函数返回字符串。
- 组件测试：关键页面在两种语言下渲染快照，防止回退。
- 端到端：切换语言、刷新页面、验证持久化与 Element Plus 组件语言。
- `npm run check` 与 `npm run build` 必须通过；新增 `check:i18n` 可作为可选脚本。

## 15. 迁移计划

与 `phases.md` 第五阶段衔接，按可独立验收的步骤推进：

1. 建立 i18n 模块、语言状态与 Element Plus 提供器；迁移应用壳层与通用状态。
2. 迁移路由标题与高频页面（搜索、问答、阅读器、文库目录）。
3. 迁移源码洞察相关页面。
4. 迁移入库向导、任务中心、审核、反馈与管理页面。
5. 补齐英语词条，强化布局与测试，更新文档。

每步完成后默认语言仍为中文；英语包完整并通过类型检查前，不向用户暴露切换入口，
避免展示半翻译界面。

## 16. 风险与缓解

- 工作量：约三百处文案迁移，需按页面分批，避免单次大改。
- 类型摩擦：插值函数与字符串混用可能造成不一致，通过评审与门禁约束。
- 包体积：语言包动态导入，中文用户不加载英语包。
- 响应式陷阱：`useMessages()` 必须返回计算属性，模板才能随语言更新。
- 后端文案语言不一致：通过文档明确边界，避免误解为缺陷。

## 17. 不做的事

- 不引入 `vue-i18n`。
- 不使用机器翻译填充英语包。
- 首批不本地化后端错误 `detail`。
- 首批不支持 RTL。

## 18. 验收标准

- 可在界面中切换 `zh-CN` 与 `en`，所有壳层文案即时更新。
- 刷新页面后语言选择保持。
- 默认语言为 `zh-CN`，未支持语言回落默认。
- 英语包通过类型检查与词条完整性测试。
- `npm run check` 与 `npm run build` 通过。
- 无页面因文案长度变化而出现明显溢出或不可用控件。
