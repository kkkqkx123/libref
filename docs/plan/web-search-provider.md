# 通用网页搜索 provider 设计

## 背景

精准提取失败时完全依靠人工与 AI agent 自行搜索，指引已在失败线索中给出。
本方案补一个显式调用的通用搜索入口，解决 agent 拿到裸 URL 后仍需自行判断
文档与仓库归属的问题。调用方明确触发，结果标注未核实，确认后走显式地址使用。
不做静默自动兜底，不做候选回退。

## 非目标

- 不接入注册表扇出，无生态限定的模糊发现不自动带上网页搜索。
- 不写覆盖文件，不污染版本分区与发现缓存之外的任何存储。
- 不引入密钥型搜索引擎，首个实现只用无密钥来源，接口保持可插拔。

## 数据源选型

首个实现用 DuckDuckGo 网页端。理由：无密钥可用，实测返回 200，
结果链接用重定向地址携带真实目标参数，可直接提取，无需跟随跳转；
标题与摘要节点稳定，容错解析与现有包索引页面解析同属一类。
已知风险：非官方端点，标记漂移与反爬限流是常态，解析必须容错，
失败统一归为可重试类，网络失败按环境不可用处理。

## 模块划分

- 新增搜索 provider，只放地址构造、目标提取、载荷解析与分类。
  地址构造做查询编码与条数钳制；目标提取解析重定向参数，
  直链直接采用；解析按结果块逐个提取标题与摘要，缺失可跳过；
  分类复用现有仓库与文档地址判定，输出仓库、文档、其他三类。
- 服务层加独立显式入口，不经过注册表扇出。入口校验查询非空与条数范围，
  复用发现开关与离线语义，离线直接报错；请求复用共享客户端工厂与重试；
  结果映射为与发现候选同形的记录，来源标为网页搜索，版本为空，
  无仓库的沿用缺仓库标注。

## 出口与调用方式

- MCP 新增独立搜索工具，只做参数校验加服务调用加结果整形。
- 命令行新增独立子命令，只做参数解析加服务调用加结果打印。
- 失败线索中的手动步骤可引用该工具作为备选，但解析失败路径本身不自动调用。

## 配置与合规

- 不新增配置项与密钥，离线模式直接拒绝。
- 只返回公网地址，复用现有地址清洗与私网拒绝。
- 无网络的部署环境返回环境不可用，不视为回归。

## 落地顺序与验证

- 先交付 provider 加单测，用内嵌页面夹具断言地址构造、目标提取、分类。
- 再接服务入口与薄出口，加集成测试，用注入传输断言成功映射、离线拒绝、
  服务端错误分类。
- 最后加端到端用例，真实网络断言返回结构正确且标注未核实，
  网络失败按环境不可用跳过。
- 合并为尽量少的一次全量测试运行，输出先落盘再读。
