# MCP 工具返回形式问题清单与修改方案

现状来自对出口注册与三个出口调用链的实测。出口只有参数透传与结果整形，编排全部在服务层。网页出口已有统一包络与请求校验，命令行直接打印服务结果，MCP 出口介于两者之间但两边都不对齐。

## 现状总览

当前共九个工具，可按返回形状分成四类。

检索与问答类。检索返回带结果列表与降级标记的字典，单条命中携带定位键与摘要类元数据。问答返回回答文本、引用列表、降级标记与模型名，空召回返回空回答，无问答密钥或参数非法时返回带错误原因的字典。

精读与目录类。按地址精读按模式返回三种不同形状的字典，找不到时返回空值，模式缺参时直接抛错。目录按是否给库名返回两种不同形状的裸列表。

挖掘洞察类。接口洞察与序列洞察各按视图参数返回三种或四种不同形状的裸列表，视图缺参时直接抛错。频次、共现、参数形状、序列、证据、特征树、聚类各自字段差异大，但都缺少总数说明。

治理与解析类。审核按动作返回待审裸列表或成功标记，失败时返回带成功假值的字典。任务查看按是否给编号返回任务摘要字典或任务详情字典，找不到时返回带错误原因的字典。地址解析成功返回解析结论字典，失败返回带错误种类与提示的字典，但实现上会联网并写缓存。

网页出口对照。网页对目录、检索、洞察、待审列表统一使用带条目列表与总数的包络，检索多带降级标记。参数非法返回请求错误，资源缺失返回未找到，审核冲突返回冲突，注册表缺文档返回未找到或网关错误。网页请求全部经过模型校验，取值范围与必填关系明确。

## 问题清单

包络不一致。字典包装、裸列表、空值与任意类型混用。调用方需要为每个工具写分支判空，通用解析与通用展示无法收敛。目录与洞察的裸列表尤其缺少总数，调用方无法判断是否被截断。

错误处理双轨。问答、解析、部分审核与任务走带错误原因的正常返回，检索、目录、洞察、精读缺参走抛错，精读缺失走空值，审核失败走带成功假值的字典。同一类参数错误在不同工具表现完全不同，智能体需要同时处理协议层报错与载荷内报错。

多态工具的条件必填缺校验。视图、模式、动作决定了哪些参数必填，但工具声明上全部表现为可选。缺参要到服务层才抛错，MCP 层直接透传为协议层报错，提示不如网页的参数校验友好。取值范围同样缺校验，非正或超大分页值可直达存储层。

引用链断裂。检索命中有完整的回读定位键，问答引用只保留地址与标题。拿到问答结果后无法直接按引用做窗口或章节回读，只能重新检索，既浪费又可能对不准原文。

载荷与一致性缺口。检索单条字段多，精读全文与分块明细重复同一正文，序列证据整组返回全部调用。分页只有条数没有游标，大结果无截断说明。审核待审项的参数是原始字符串，而参数形状查询返回已解析结构，同概念异构。

与网页出口不对齐。网页已统一包络、统一校验、统一状态码，MCP 保持裸列表与混合错误。同一服务在两个出口表现不同，文档与测试需要维护两套心智模型。

描述与实现不符。地址解析自述只读，实际会联网拉快照并写缓存。任务查看只能看不能提交，作为观察手段合理，但与任务提交的对应关系没有说清，容易误以为 MCP 可驱动完整任务流。

## 修改方案

总体原则是直接改断，不保留旧形状。不建新模块，只改原模块。出口保持薄，只做参数透传、取值校验、包络组装与错误收敛。校验尽量与网页对齐，但传输差异保留：网页用状态码区分错误，MCP 用载荷内错误原因返回，工具本身不抛错。

列表包络统一。目录、接口洞察、序列洞察、审核列表统一返回带条目列表与总数的字典。检索统一返回带条目列表、总数与降级标记的字典，与网页包络同形。任务查看保持摘要键名与详情键名不变，本就与网页一致。问答、精读、解析保持各自字典形状不变，只修错误与缺失语义。

失败形状统一。所有工具成功返回数据包络，失败返回带错误种类与说明的字典，必要时带提示信息。不再返回空值，不再抛错，不再用成功假值表示失败。精读找不到返回未找到错误，模式缺参返回参数错误。审核动作非法或状态迁移非法返回参数或冲突类错误。检索模式非法、洞察视图非法、分页越界同样返回参数错误。

参数校验补齐。MCP 层补齐与网页对等的取值范围校验与条件必填校验。视图缺关键参数、窗口缺位置、章节缺分组直接返回参数错误，不再透传到底层抛错。服务层保留兜底抛错，MCP 层统一捕获为错误字典。联网与缓存行为如实描述，地址解析不再自述只读，注明会联网并更新缓存。任务查看定位为只读观察手段。

引用补齐。问答引用补齐可回读定位键，包括文档编号、来源分组、块编号、页面编号、块顺序以及库与版本。引用顺序与检索顺序一致，保证按引用可直接调精读。检索条目形状不变，问答只 enrichment，不改检索。

参数解析一致。审核待审项的参数字符串解析为结构，与参数形状查询一致。解析失败时回退为原文包裹，保证不丢信息。其他挖掘字段保持不变。

本次不做。不断言多态工具必须拆分为单功能工具，包络统一后多态的理解成本已可接受。分页不引入游标，大载荷不做通用截断，只保证总数可见。检索与挖掘算法不动，只改出口形状与引用携带。

## 落地顺序

先改问答引用与审核参数解析，这两处在服务层，受益面覆盖三个出口。再改 MCP 注册层的包络、校验与错误收敛，对齐网页行为。最后更新问答引用期望与相关集成断言。文档与实现同一次改动内对齐。

## 验证

问答引用期望按补齐后的定位键更新。MCP 握手测试只断言子串与工具名集合，包络化后仍通过。审核排序与状态迁移测试不受参数解析影响。收敛为一次全量运行，输出重定向到文件后阅读，不在改动过程中反复全量编译测试。
