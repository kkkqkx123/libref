# astminer 新增 Rust / Go / C# 语言支持设计方案

> 状态：设计中（本阶段交付 Rust、Go、C# 三语言；TypeScript 等后续再议）。
> 来源：查询子集取自 code-context-engine（cce）`cce-parser` 的 scheme 定义（已验证），按 libref 引擎契约做捕获重命名与裁剪；语法包版本经 PyPI 核实。

## 1. 现状与目标

现状：astminer 只支持 Python、Java、JavaScript；新增语言按声称只需加查询模块与语言配置，不改引擎。但三门新语言存在两处结构差异，引擎需配合小幅扩展（见第 4 节）。

目标：三语言的实体、调用、依赖、注释四类抽取可用，复用现有两遍解析与三级置信；同一仓库混多语言时各文件按后缀独立抽取、统一落库。

非目标：cce 的行为（behavior）与控制流（control-flow）查询不在本阶段引入；宏定义体、泛型具化、跨包精确消解（go.mod 模块前缀、Rust crate 名映射、C# 别名 using）留待第二阶段。

## 2. 查询子集选取原则

只取实体、调用、依赖、注释四域；凡 cce 中服务于关系图谱但本引擎无消费方的捕获一律裁掉（类型引用、trait bound、选择子表达式、闭包体内细节）。

捕获命名必须服从引擎已有的后缀契约，而不是照搬 cce 命名：实体根统一落在种类映射表能识别的根上，调用统一用对象、函数、实参三组后缀，依赖中只有扩展、实现两组后缀会进入基类，注释只有行、文档两组后缀会被计入。凡 cce 捕获名与契约不一致的，在子集改写时重命名，不在引擎侧做兼容。

## 3. 分语言子集说明

### 3.1 Rust

实体取结构体、枚举（含变体，归入枚举常量）、联合体、特征（归入接口）、类型别名（新种类）、函数（含特征方法签名体）、模块、常量与静态（归入变量）、结构体字段、闭包赋值（归入函数以便调用归属）。宏定义与属性宏不作为实体抽取。

调用取直接调用、方法调用、链式调用、关联函数调用（统一改写为对象加函数形式，使路径中的双冒号经通用点分函数归一化）、宏调用。泛型调用与闭包直接调用裁掉。

依赖只取四种 use 形态用于别名构建：简单路径、别名、通配（无别名）、路径加列表。通配与标准库前缀开头的导入不产生别名。trait bound 与类型引用不进入子集。

注释取行注释、文档注释、块注释，其中块注释计入文档。

### 3.2 Go

实体取结构体、接口（含方法规格，归入方法）、类型别名（新种类）、函数、方法（带接收者，供归属重写）、函数字面量赋值（归入函数）、变量（含短声明与循环变量）、常量（归入变量）、字段（含标签变体）、包子句。嵌入字段与选择子表达式不作为实体。

调用沿用 cce 全量形态：直接调用、方法调用、包级调用、链式调用，外加协程与延迟调用（其语句根需加入调用节点类型集合）。

依赖取导入四种形态用于别名构建：标准导入、别名导入、点导入与空导入（后两者无别名）；标准库导入（首段无点）不产生别名。结构体嵌入与接口嵌入同时 feeding 基类（组合即继承）。

注释取通用注释节点，计入行注释。

### 3.3 C#

实体取类（含基类表与体）、接口、结构体、枚举（含成员，归入枚举常量）、记录、方法、构造器、析构（归入方法）、属性与事件（归入字段）、命名空间（含文件作用域，归入模块）、委托（归入函数）、特性（归入装饰器）、字段、局部变量（含解构与模式变量）。运算符重载无名，裁掉。

调用取直接调用、成员调用、链式调用、静态调用（含命名空间限定）、对象创建（归入构造器调用）。委托调用与直接调用同形，裁掉以免重复；泛型调用裁掉。

依赖取 using（普通形式以首个标识或限定名为准，别名形式取别名加路径）与四类基类表（类、结构体、记录、接口，分别进入扩展或实现后缀）。

注释取通用注释节点，计入行注释。

## 4. 引擎与规则改动点

种类词汇新增三项：结构体、联合体、类型别名；其中结构体与联合体按类的方式分组与参与消解，类型别名参与消解但不吸收成员。特征直接复用接口，相关分组与消解集合保持不变。四个触及种类的文件需同改。

调用节点类型新增三项：宏调用、表达式调用语句、协程与延迟语句根。

装饰器、变量等其余种类复用，不新增。

两个归属问题需引擎配合，均为新语言数据驱动、老语言无感：

- Rust 固有实现块：方法定义在文本上独立于类型定义，字节包含关系无法建立归属。查询将实现块捕获为透明锚点（只记类型名与区间，不落为声明），引擎对落在其区间内的函数重写限定名与父级，使其挂到对应类型下。
- Go 接收者：方法声明为顶层节点，归属来自接收者参数。引擎从接收者捕获提取类型简名（去指针符与泛型实参），重写限定名与父级。

参数与返回值提取沿用通用函数：接收者字段名差异（模式而非名）由既有的子节点回退覆盖；泛型与指针类型经既有字段查找取得。

## 5. 别名与消解策略

别名构建按语言分派新增三个函数，复用既有点分与首段逻辑：Rust 解析路径加列表（列表项逐个展开，作用子句取别名）、Go 解析导入路径（末段为本地名，纯数字版本段向前取一段）、C# 解析 using（普通取末段，别名形式取等号左侧）。

消解层改动三处，均落在共享路径上且只收紧不放宽：别名展开未命中后，若原始文本恰为唯一声明后缀则取该声明（多候选时维持原行为）；标准库前缀新增三组（Rust 系、Go 由构建侧过滤、C# 系）；自身引用首段新增大写形式以覆盖关联函数。

模块路径按后缀推导：Rust 剥离约定的源码根并将入口文件名折叠到父目录；Go 与 C# 按相对路径转点分。包子句、模块声明与真实命名空间不一致时以路径为准，文档中明确为阶段性近似。

## 6. 缓存与指纹

指纹机制沿用：联合哈希输入含运行时版本、语法包版本、四类查询文本与配置版本。新增语言只新增各自的指纹分量，既有三语言的查询文本与配置版本不变，旧缓存继续有效。查询注册表的版本常量不提升，避免无谓全量失效。

## 7. 依赖与配置

语法包新增三项（版本见 PyPI，以锁文件为准），解释器下限与运行时版本不变。各语言配置只声明语言名、语法包名、后缀集合与配置版本。后缀新增三组，源码遍历与命令行按后缀分派处自动生效；文本分类与代码围栏提示的后缀映射同改。

## 8. 测试计划

查询编译检查覆盖全部六语言；三语言各有行内黄金形状测试（实体限定名、基类、调用原文与调用者、别名对、实现块与接收者归属）；新增三个最小夹具文件做端到端抽取断言，并把空源扩展到六语言。集成层沿用既有迷你仓库模式，不新增网络依赖。

## 9. 风险与第二阶段

主要风险是查询字段名随语法包版本漂移：防护为启动自检（配置加载即编译四类查询）加锁文件钉死版本；升级语法包后指纹自动失效缓存。

已知近似（文档与注释中明示，不在此阶段解决）：Go 跨包引用需剥模块前缀（读 go.mod）、Rust crate 根路径与 super 路径归一、C# 命名空间与文件路径不一致、泛型调用与运算符调用未抽取、宏定义体未抽取。
