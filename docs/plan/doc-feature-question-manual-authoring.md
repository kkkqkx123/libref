# 文档特征判定集人工手写方案

依据：`docs/plan/doc-feature-manual-audit.md` 的实际核查结论。冻结归档题目的最终真值改为人工逐题手写，不再由归档物化器产出。物化脚本及其单元测试已删除；`tests/e2e/generate_doc_feature_questions.py` 只保留候选探索用途，不进入最终判定集。

## 目标与边界

- 替换 `tests/e2e/fixtures/doc_features/questions.json` 中九个真实站点的 270 条题目，每库 30 条，dev/test 各 15 条；离线 `demo` 的 12 条不改动。
- 每题必须来自该项目解压后的原始正文，并与 `tests/e2e/bench/data/bench.db` 中同一版本的文档块、派生 facet、实体边、节点父链和一致性判定逐项对上。数据库只提供证据清单，不生成题目文字。
- 九个项目的 270 条题目已按下列口径逐题手写替换，`demo` 的 12 条保持不变；分项目逐题复核结果写入人工核对记录。
- `doc_feature_alpha` 保持为 0。全部项目替换完成并做独立复核之前，不修改门禁下限。

## 手写口径

- 题目文字用自然语言写出要查的事实，直接指向该章节的具体句子；不使用页首、目录、面包屑、页脚、脚本、表格表头拼接出的“查询”。
- 目标 URL 与标题路径必须能在原始正文定位到同一个章节；同名标题存在多个块时，以数据库里该块的标题路径和 facet 为准，不从页面第一处同名标题兜底。
- 期望实体只在题目中点名、且在目标文档 `doc_api_links` 与源码实体表中都存在时写入。短名为普通英文词的候选一律不写，例如 `Warning`、`complete`、`configure`、`content`、`generate`、`sequence`、`wrapped`。无合格实体时保持空数组。
- drift 题的题面必须包含原正文中的 `deprecated`、`removed`、`no longer` 或对应中文弃用、移除句子；枚举值中的 `REMOVED`、通用政策和否定式问答不写为 drift。`expected_verdict` 只在目标文档结论唯一时写入。
- 无答案题选目标块没有任何 `doc_api_links` 的页面。不能把“查询片段里没有别名”解释成“没有受跟踪 API 边”。
- `expected_facets`、`expected_verdict`、`expected_feature_nodes`、`source_ref`、`grades` 从派生证据复制并人工核对；`id` 与 `split` 沿用现有编号规则，同一 URL 的题目必须落在同一划分。
- 每库题型覆盖示例、参数或返回、表格、变更说明、drift、无答案、限定名说明；某站点正文没有对应题型时如实缺项，不为凑配额编造题目。

## 分项目顺序

| 阶段 | 项目 | 重点处置 |
|---|---|---|
| 一 | httpx | 清理导航式查询和目录片段；重做带链接却被标成无答案的题目 |
| 二 | zod | 避开截断正文尾部的目录节点；去掉 `message`、`padding` 等泛词实体 |
| 三 | jsoup | 去掉 HTML 标签残留和页脚；修正表格题与代码段的对应关系 |
| 四 | fiber | 清理 `Examples Quick Start` 菜单；处理弱别名与 `Rules map` 迁移说明 |
| 五 | vue | 按 Markdown 锚点确认同名章节；核对版本标记和示例代码题 |
| 六 | pydantic | 处理重复短标题；去掉 `generate`、`wrapped` 等泛词实体 |
| 七 | FluentValidation | 去掉 `View page source` 与警告横幅实体；逐句核对升级说明 |
| 八 | Rocket | 去掉 `FAQ`、`What's next?` 等目录题；排除生命周期枚举误判 |
| 九 | gradle | 去掉 `llms.txt` 样板题与 `REMOVED` 枚举误判；重做泛词实体题 |

每个阶段完成后再进入下一项目，不批量套用同一句模板。

## 单项目作业步骤

1. 把该项目的 `pages.jsonl.gz` 解压到系统临时目录，只读查看原始正文；不把解压结果写进版本库。
2. 从 `bench.db` 导出该项目所有文档块的 URL、标题路径、facet、实体边、节点父链和一致性判定，作为人工选题的证据清单。
3. 人工挑选 30 个可核验块，按手写口径逐条写题面、实体和题型；题面长度以说清事实为准，不设机械截断。
4. 回查原章节，确认题面句子、标题路径、实体、facet、判定和节点都指向同一个块；发现同名标题错配时换块或删题，不靠开头兜底。
5. 跑冻结归档评测，记录锚点、实体、facet、判定和节点一致情况；报告只证明标签与派生表一致，不替代语义复核。
6. 由第二人逐题复核后方可标记该项目完成；复核结论与剩余问题写回人工核对记录。

## 完成定义

- 每库 30 条、dev/test 各 15，按 URL 隔离；题库中没有导航、页脚、脚本或截断片段题。
- 没有泛词实体、没有无链接的无答案题、没有句面不含弃用语义的 drift 题。
- 锚点、facet、实体、判定和节点核对全部通过；每库保留一份抽查记录，列出示例、参数、表格、变更、drift、无答案题的题面与原句对应关系。
- `questions.json` 的变更按项目分列；独立第三方复核完成前仍不写检索增益门禁，`doc_feature_alpha` 保持为 0。
