# 图遍历查询评测与审核输出收紧设计

## 背景

独立图查询通道已经具备五种查询形态、有界遍历、派生邻接缓存与三个出口。图 gold 采用稳定节点 ID、精确集合期望与行级证据引用；`tools/export_graph_audit.py` 同时导出 JSON 与 Markdown，默认不把命中率写成通用门禁。本轮收紧的是判定边界、审核输出的自足性以及指标口径，不改变检索排序、不新增图数据库、不新增事实表，也不把缓存命中率当作正确性指标。

## 评测口径

gold 由人工对照 `tests/integration/test_graph_query.py::_seed` 逐条写入 `tests/fixtures/graph_gold.json`，编写规则见 `docs/spec/doc-feature-judgments.md`。用例覆盖五种模式、九种关系、正向路径、反向未命中、强边与禁止节点、模式相邻对、簇与父链、文件级影响面、导入、继承、文档覆盖与导航、歧义调用以及截断期望。每条用例带 `source_ref`；契约测试校验事实行、稳定节点 ID、模式与关系覆盖。

判定按稳定节点 ID 精确匹配种子、节点集合、关系集合与证据引用集合，禁止节点不出现，找到状态与截断状态一致，且所有边都能回溯到作用域内的真实事实行。路径未命中的用例允许节点、关系和证据为空。证据可追溯性校验表白名单、行 ID、版本、租户，并在合成节点与 profile 作用域上区分边级证据与节点级证据；合成节点由同用例的行级边证据支撑。

指标分三层：用例层给出种子解析、找到状态、节点与关系精确率/召回率、边与节点证据可追溯率、截断状态；汇总层给出匹配率、错误数、路径找到状态一致率、平均精确率/召回率、证据可追溯率与截断异常数；性能层继续由独立性能报告给出中位数、p95、加速比与事实读取次数。查询错误单独计数，不混入 `unexpected_truncations`；严格模式在用例为空、存在错误或未全部匹配时失败。

## 审核输出

JSON 仍是机器可读真相，Markdown 从同一份报告渲染，不重复计算指标。文本报告给出数据库、gold、作用域、是否展开歧义、查询参数、种子、找到状态、节点与禁止节点、关系、期望与实际证据引用、边与节点证据可追溯率、合成节点与截断状态，使审核者无需打开 gold 即可复核主要判定依据。

默认行为仍是审核导出；只有显式 `--strict` 才按匹配结果返回失败退出码，供需要自动检查的调用方选择。性能报告与 gold 匹配率分开呈现。

## 契约收紧

Web 响应模型直接使用图节点和图边的 Pydantic 模型，前端快照与类型同步生成。CLI 与 MCP 复用服务层输出，不复制节点字段定义。三种出口的参数词表由服务层常量或契约测试约束。

## 测试与复测

gold 集成测试同时验证事实库支撑、逐例通过、指标汇总和导出工具；缓存差分测试复用同一 gold，确认 SQL 与快照路径的指标一致。契约测试检查 OpenAPI 节点与边字段，快照与前端类型同步生成。复测集中执行图查询与缓存集成测试、相关单元和契约测试、lint、格式与类型检查；性能测试不重跑，已有本地报告只作为观测。

## 不做

- 不引入 LLM 判分或人工标注平台。
- 不改变默认缓存关闭状态，不把命中率提升为质量指标。
- 不改写检索结果排序、分数、top-N 文本增强或现有搜索 gold。
- 不为图查询新增独立质量门禁，严格模式仅由调用方显式开启。
