# 图遍历查询评测与审核输出收紧设计

## 背景

独立图查询通道已经具备五种查询形态、有界遍历、派生邻接缓存与三个出口。当前短板不在功能路径，而在评测与审核：gold 集合只有五条种子用例，判定采用期望集合的子集包含，节点以展示标签而非稳定 ID 标识，证据引用只验证非空，截断状态不进入报告，导出工具没有可读报告，也没有可选严格退出码。OpenAPI 中的节点与边仍是通用对象，前端无法据此约束字段。

本设计只收紧图查询自身的评测与契约，不改变检索排序、不新增图数据库、不新增事实表，也不把缓存命中率当作正确性指标。

## 评测口径

gold 用例改用稳定节点 ID 标识种子、期望节点与禁止节点。每条用例显式声明期望找到状态、期望关系、期望证据引用和期望截断状态。判定改为精确集合匹配：种子解析一致，非路径查询不误报，路径的找到状态一致，节点集合、关系集合和证据引用集合一致，禁止节点不出现，截断状态一致，且所有边都能回溯到作用域内的真实事实行。序列模式的相邻对边按代表模式行核对，文档导航边按导航事实行核对。

聚合指标按三个层次输出：

- 用例层：种子解析、找到状态、节点精确率与召回率、关系精确率与召回率、证据可追溯率、实际截断状态。
- 汇总层：匹配率、种子解析率、路径命中率、平均节点与关系精确率/召回率、证据可追溯率和意外截断数。
- 性能层：继续由独立性能报告给出中位数、p95、加速比与事实读取次数，不混入 gold 匹配率。

证据可追溯要求边的证据引用携带事实表、行 ID、版本和租户；校验时按来源表白名单限定，核对行存在，并在事实表具备相应字段时核对版本与租户。合成文件节点仍保留派生型证据，但边必须指向真实事实行。文档导航边原来没有行 ID，本轮补上来源行，避免它成为唯一无法核对的边类型。

## 审核输出

`tools/export_graph_audit.py` 继续以 JSON 为机器可读真相，同时输出一份 Markdown 文本报告，逐条列出匹配状态、种子、节点、关系、证据引用和截断状态。控制台摘要同时给出 JSON 与文本报告路径。

默认行为仍是审核导出，不把质量结果写成通用门禁。新增显式 `--strict` 后才按匹配率返回失败退出码，供需要自动检查的调用方选择。文本报告只呈现同一份报告数据，不重复计算指标。

## 契约收紧

Web 响应模型直接使用图节点和图边的 Pydantic 模型，替换通用对象字段，并同步 OpenAPI 快照与前端类型。CLI 与 MCP 仍复用服务层输出，不复制图节点字段定义。三种出口的参数词表继续由服务层常量或契约测试约束。

## 测试与复测

- 更新 gold 集合为稳定 ID 与精确期望，保留五类核心场景。
- 集成测试覆盖新增指标、错误证据引用、意外截断和文本报告生成。
- 缓存差分测试继续复用同一 gold 集合，确认 SQL 与快照路径的新指标一致。
- 契约测试检查 OpenAPI 中的节点与边字段，快照与前端类型同步生成。
- 复测集中执行图查询与缓存集成测试、相关单元和契约测试、lint、格式与类型检查；性能测试不重跑，已有本地报告仅作为观测。

## 不做

- 不引入 LLM 判分或人工标注平台。
- 不改变默认缓存关闭状态，不把命中率提升为质量指标。
- 不改写检索结果排序、分数、top-N 文本增强或现有搜索 gold。
- 不为图查询新增独立质量门禁，严格模式仅由调用方显式开启。
