# MCP 工具裁剪方案

> 目标：MCP 出口支持按配置与环境变量裁剪可见工具，解决发现类工具互相冲突、代码类工具并非 always 需要的问题。不改变服务层行为，只改变出口注册。

## 1. 背景与现状

`build_mcp_server` 对全部工具无条件注册，调用方拿到的永远是完整工具表。已有的 `discovery_enabled`、`chat_enabled` 等开关只影响运行时成败，不影响可见性：被关掉能力的工具仍然出现在 `list_tools` 里，模型照样会选中再失败。`serve-mcp` 也没有任何工具过滤参数。

由此产生三类实际问题：发现通道冗余（`library_search` 扇出已含仓库源，再配独立的 `web_search`、`github_search`，模型易误选，且后两者返回未经核验候选，与 `search/read_doc/answer` 的 grounded 定位冲突）；场景错配（纯文档部署下代码四件套无数据，只能空返回）；治理面默认暴露（`review/job_show` 不应出现在只读问答会话里）。

## 2. 目标与非目标

目标：服务端权威裁剪，禁用工具从 `list_tools` 彻底消失；配置、环境变量、命令行三源与现有优先级一致；未知工具名启动即报错；默认行为不变（全部可见）。

非目标：不拆分多态工具，不改服务层编排与检索算法，不给 Web 出口加开关（Web 按需调用单个路由，不存在能力广播问题）。

## 3. 配置语义

`[mcp]` 分组新增两个字段，均非密钥，可进文件：

* 允许名单：缺省为空代表全部可见，显式给出即只注册名单内工具；
* 拒绝名单：缺省为空，命中即剔除，拒绝优先于允许。

两者正交，可单独使用也可组合。环境变量走 `LIBREF_MCP_ENABLED_TOOLS` 与 `LIBREF_MCP_DISABLED_TOOLS`，接受与文件相同的数组写法，也接受逗号分隔写法，由配置层统一归一化（去空白、转小写、去重去空）。命令行 `serve-mcp` 增加同名选项，优先级高于环境与文件，与现有显式覆盖规则一致。

`config-show` 直接透出归一化后的名单，脱敏逻辑不受影响（无新增密钥）。

## 4. 注册过滤

过滤点放在 `mcp_server` 组装处：先由配置算出有效集合，未知名字直接抛配置错误中断启动，再按集合注册。未知名 fail-fast 是故意的，拼写错误静默忽略只会让问题更难查。允许名单为空数组表示零工具，属显式选择，不做额外校验。

现有能力开关保持不动，与可见性正交：前者回答服务能不能做，后者回答出口给不给看。

## 5. 落地顺序与验证

先加配置字段与归一化，再改组装处做条件注册与未知名校验，再接命令行透传。测试覆盖缺省全量、文件与环境两种来源、逗号与数组两种写法、允许与拒绝组合、未知名启动失败、零工具极端。验证收敛为一次运行，输出重定向到文件后阅读。
