# 文档代码块语言声明、自动标注与失败留痕方案

本方案处理文档代码块语言缺失的两个来源：拉取时缺少站点级语言事实，以及解析后无可用证据却被静默丢弃。目标是把“语言从哪来、解析成什么样、谁做的标注”变成可回放、可复核的数据，而不是在派生阶段猜测语言。

方案只定义数据与流程，不改检索权重，不写门禁，不新增语言语法。新增语言仍按语法轮子与 `LanguageConfig` 的既有流程处理。

## 结论

- **源码仓不重复要求指定语言。** 源码文件语言由后缀与 `LanguageConfig` 决定，bench 源码夹具的 `languages` 只用于体检。再要求一次会产生两个真源。
- **文档站建议在拉取配方中声明候选语言。** 原始正文常没有语言标记，拉取是由人确认站点语言构成的唯一低成本时机。声明是“候选集合”，不是“给所有代码块贴同一个标签”。
- **当前解析失败处理不足。** tree-sitter 返回带错误节点的树，`extract_file` 不判定解析质量；`ingest_snippets` 对有语法配置但无产出的片段只计入 `parsed`，不支持语言的片段直接跳过；`ast_cache` 会缓存低质量结果。现有计数无法区分“无语言”“语言错”“解析成功但不是目标 API”。
- **需要单独持久化片段级记录。** 新增片段表保存每个抽取片段的语言证据、解析状态与尝试记录，让无标注片段进入自动标注池，让失败片段进入人工队列，二者互不掩盖。

## 数据流

### 拉取与冻结

文档夹具在获取配方中声明 `snippet_languages`：一组该站可能出现的语言名，取值必须是已注册语言。混合语料站点给出完整候选集，例如 Python 文档同时声明 `python`、`shell`；Gradle 文档声明 `java`、`kotlin`、`groovy`。

声明写入归档 `meta.json` 的 `recipe`，因此属于获取输入。修改声明必须显式重新获取并产生新修订，构建与评测只读归档，不再要求用户重复指定。生产抓取把同一声明放入抓取 scope，并由服务层写入该版本的来源选择事实，供后续增量重建复用。

### 代码块语言解析

语言事实按固定优先级消费：

1. 块级显式标记：`language-*`、`lang-*`、`data-lang`、围栏语言标签。
2. 文档来源标记：祖先节点类名、紧邻标题或说明中的明确语言词。
3. 人工规则：配置中的 URL/选择器规则，命中时记录规则标识。
4. 获取期候选语言：仅对仍无标注的片段尝试，且必须经解析验证。
5. 无证据：保持无标注，不推断、不进入评分。

获取期候选语言的自动标注只在“恰好一个候选产生可用证据”时生效；零个或多个候选可用时分别记为解析失败或歧义，交人工处理。候选尝试按片段哈希与语言缓存，设置次数上限，避免大站成本乘以候选数。

### 解析状态

解析状态不按树是否带错误节点单独判断。文档片段常是交互式会话或不完整语句，带错误节点仍可能包含有效调用。状态按证据与歧义划分：

| 状态 | 含义 |
|---|---|
| `ok` | 有明确语言，解析出可用调用或实体证据 |
| `partial` | 有语言且有部分证据，但存在错误节点或仅弱解析 |
| `unsupported` | 语言名无对应语法配置 |
| `unlabeled` | 没有任何可采信语言证据 |
| `ambiguous` | 多个候选语言都产生可用证据 |
| `failed` | 候选语言均无可用证据 |
| `non_target` | 解析正常，但调用不属于受跟踪 API |

`non_target` 是正常业务结果，不按失败处理；它不应被改写成目标调用以抬高覆盖率。

## 持久化设计

新增片段级表，按版本、来源键和稳定片段标识唯一。每行保存：片段原文与摘要、URL、标题、块序号、原始位置、抽取来源、语言、语言证据来源、解析状态、候选尝试记录、来源来源标识、审查状态、标注语言、标注人与时间、租户标识。

表只做增量 upsert：同一片段内容或语言证据变化时更新状态，不重复新增行；证据不变时复用结果。SQLite 与 PostgreSQL 终态需在同一次改动中同步，迁移追加在现有链条末尾。

不复用现有 `review_status`：它只服务 `call_instance` 的审批流，语义与片段语言标注不同。片段标注状态放在自己的表中，并提供按状态列举与回写入口。人工确认的语言写入后成为显式证据，下一次重建优先于获取期候选；若同类片段大量重复同一标注，再考虑提升为配置规则。

## 处理边界情况

- 站点声明的语言不等于每个块的语言。shell 安装命令、JSON 响应、控制台输出不得因站点声明而被强行解析为目标语言。
- 交互式片段中的提示符、行号、省略号不直接当作语法错误证据。可先记录 `partial`，只有产生可用调用时才自动标注。
- 多语言片段按块拆分，不按页统一语言。同一页混排时以块级证据优先。
- 解析成功但目标解析失败的片段保留为 `non_target` 并单独计数，不与语法失败合并。
- 自动标注必须写下证据来源；报告按来源统计 snippets 数，弱证据与人工确认分开呈现。

## 验证与验收

- 语言解析纯函数用例覆盖显式标记、祖先类名、邻近标题、人工规则、获取期候选、无证据与多候选歧义。
- 片段解析用例覆盖 `ok`、`partial`、`unlabeled`、`ambiguous`、`failed`、`non_target`、`unsupported` 七种状态，确认失败不会静默丢弃。
- 数据库用例覆盖 SQLite 与 PostgreSQL 双端的 upsert、租户隔离、状态筛选与人工标注回写。
- 用冻结归档做前后对拍：确认祖先类名与获取期候选带来的 snippets 增量，确认无标注和失败片段可逐条列出。
- 检索差分与树节点一致率只作观察，本轮不改 `doc_feature_alpha`、不写增益门禁。

## 非目标

- 不把单一生态语言强加给整个文档站。
- 不新增语法轮子或修改 AST 引擎，只为现有语法补证据与状态。
- 不先做人工标注前端；先提供可按状态查询与回写的数据入口。
- 不重写已冻结判定题，也不把派生状态当作新的语义真值。
