# 源码与文档分块对齐 code-context-engine 的缺口与修改方案

> 依据：`docs/ref/code-context-engine.md`（只取分块与嵌入索引设计，不取其自然语言转写部分），
> 以及本地 `~/code/code-context-engine` 对应实现（分块器、预算单元、合并、重叠、溯源精度的实际语义）。
> 目标：`chunking/` 产出双路预算口径一致的分块，`astminer/` 产出可直接作分块输入的实体分组，
> 两路在 `store/` 共用同一源对齐键。
> 范围：只改 `chunking/`、`astminer/` 及其直接消费界面（`store/document_store` 元数据形状、
> `services/ingest` 落库前检查、`cli` 调试出口）；不改分词器之外的 FTS 配置，不改向量库接口，
> 不引入自然语言转写、术语注入、插件注册表。
> 约束：只修改原模块，不建替代模块；新增文件仅按职责拆分（预算计量、实体的分组、源码分块组装各一），
> 不做任何向后兼容，不保留旧字段形状，随改随调测试与调用方。

## 1. 现状盘点

`chunking/` 现仅一个分块实现：按标题切分、围栏状态机避开代码块内伪标题、同路径相邻小节贪心合并、
超长块按行硬切并保证围栏成对。计量单位是字符数，单目标阈值加一个最小值，
产出只有地址、标题路径、末级标题、正文、顺序号。空块只做静默过滤，无计数无告警。

`astminer/` 现状是可用的抽取链路：声明式语言配置三语言、联合指纹缓存、通用引擎抽声明别名调用、
两遍解析定置信、仓库管理与文件遍历。抽取记录含限定名、种类、父子、签名、参数、起止行与字节。
缺的是抽取之后的东西：没有实体分组概念（类加方法、文件头加顶层项的归属），
注释查询写了但引擎从不消费（实体有无文档说明无人记录），抽取结果从不产出分块，
落库只进实体与调用两表，分块层拿不到源码 span。

消费侧现状：文档块与源码实体走两套完全独立的写入路径，文档块进 `documents`，
实体进 `api_entities`，两者无共享对齐键；向量文本组装只懂标题路径加正文，
不懂源码实体；抓取编排在分块后直接落库，无空块计数。

## 2. 缺口清单

下表每行对应一个必须补的任务，参考点指对标文档中的设计来源。

| 编号 | 缺口 | 参考点 | 不补的后果 |
|---|---|---|---|
| C1 | 无预算模型，字符数一刀切，无硬上限与规划预留之分 | 预算模型硬限与预留分离、两级检查 | 标题路径前缀与元数据挤占嵌入窗口；超限块静默入库或被嵌入层拒收 |
| C2 | 单路单阈值，无双路双预算 | 双检索路径判别式、双路双预算 | 同一份块同时喂全文与向量，一路合适另一路必失真；中文按空白切词计量错位更大 |
| C3 | 计量与检索引擎分词器不一致 | 计量用与索引同一分词器计数 | 预算形同虚设，中文块长度失控 |
| C4 | 合并不是三约束，无溯源记录 | 切分段限合并职责分层、合并三约束 | 被并小节归属丢失，审核工作流无法回溯；跨组乱并稀释主题 |
| C5 | 超长段另起一套行切逻辑，与主切分漂移 | 段限复用同一递归入口 | 两套切分语义分叉，修一处漏一处 |
| C6 | 无重叠，或后续容易做成双向重叠 | 单向重叠加来源标识 | 相邻块重复内容加倍，去重困难；重叠区无来源则无法排重 |
| C7 | 无溯源精度分级 | 溯源精度显式化、自包含豁免 | 行号区间真假混杂，审核界面无法提示可能不精确；有文档说明的成员被迫与邻居混块 |
| C8 | 空块静默丢弃，无计数 | 边界防御空 span 源头拦截 | 坏数据流入嵌入层报晦涩错误；问题规模不可见 |
| C9 | 超限无截尾告警 | 截断必须告警不静默不丢文件 | 超限块悄悄入库，门禁形同虚设 |
| A1 | 无实体分组 | 实体分组加组转换 | 类与方法各自分块，调用上下文丢失；文件头无归属 |
| A2 | 无源码直接分块基线 | 直接分块的工程价值 | 源码检索长期无零模型基线可用，分块质量无对照 |
| A3 | 实体文档说明未抽取 | 自包含标志 | 豁免规则无输入，全部成员一视同仁参与合并 |
| A4 | 模型缺 span 精度与分块对齐键 | 分块结果类型、双路共享源标识 | 源码块与文档块无法对齐融合；合并后来源组丢失 |

另有调试能力缺口：无分块可视化导出工具，无法像对标那样做文件到分块的行号字节标题预览，
分块质量只能靠检索指标间接猜。

## 3. 修改方案

### 3.1 分块预算与计量（`chunking/` 新增预算职责，原分块器消费）

新增一个只做计量的职责：路径判别（全文路与向量路）、每路的硬上限、最小块阈值、
重叠量、为标题路径前缀等装饰预留的规划量。硬上限是唯一对最终块生效的检查，
预留只是切分时的规划目标，追加装饰后仍按硬上限复检。计量单位按路径区分：
向量路按嵌入模型口径的 token 估算，全文路按与 FTS 同款分词器的词项数计数，
中文按词计而非按空白切分。分词规则与索引共用同一实现（标识符拆分加中文词典切分，
同一源码词与其拆分形共享位置），超长输入按前缀截断并计数。配置项进全局设置，
默认值沿用对标（向量路五百余 token、上限五十重叠、百余最小块；全文路百余词项、
个位数重叠、数十最小块），后续只调配置不改逻辑。

超限处理分两级：装饰前超规划只记违规保留块（属装饰估算偏差，仍受硬限约束），
装饰后超硬限截尾并打日志计数，不丢文件。

### 3.2 分块器重做（改 `chunking/splitter.py` 原模块）

保持两阶段外形（结构切分加贪心合并加超长处理），内部按以下语义重写：

- 一次切分产出两股流：全文小块与向量大块，各自按本路预算切分与合并，
  同一源共享一个源分组标识以便互相锚定，块标识为源分组加路径加序号。
- 切分尊重实体边界：文档路是标题节边界，源码路是实体成员边界；
  宁可碎块进合并，不跨界拼接。
- 超长段不另写分支，一律走回统一的切分递归，行切只作为递归终端的最后保底。
- 合并只做三件事：低于最小阈值的块才参与，只与源码位置相邻的块合并，
  合并块保留左块身份，所有贡献源记入被并集合（文档表以 JSON 列承载，不另建表）。
  有独立文档说明的成员豁免跨组合并。
- 重叠只向前：每块存前驱尾部，重叠区带文本、计量数、来源块标识与字节区间，
  不做双向。
- 每个块带溯源精度：完整实体、硬限截断片段（只声明所属实体）、
  退化到组、文档区间、不可用五档中选一；截断片段必须标为包络实体而非精确。
- 块超硬限截尾告警计数；空或纯空白块在源头拦截并计数，不流入嵌入层。

字段形状直接改到目标态，不兼容旧形状：分块结果新增路径判别、源分组标识、
块标识、计量数、字节区间、重叠区、被并集合、精度枚举；文档落库的元数据同步扩展。
调用方（抓取编排、向量组装、测试）随改随调。

### 3.3 源码分组（`astminer/` 按职责新增分组模块）

新增一个只做分组的职责，输入是引擎已抽出的声明列表（含父子、深度、字节区间）
与文件文本，输出是实体组：类加其方法、文件头（模块说明与顶层导入）加顶层项。
分组只按源码位置与归属关系，不依赖调用关系（调用关系已有落表，不在块层重建）。
分组结果携带每成员的字节区间，供分块器按成员边界切分。

同时引擎补齐两项输入：消费已有的注释查询，为每个实体记录有无独立文档说明
（供自包含豁免），以及文件头文本的抽取。记录模型加文档说明有无标记；
是否存全文只做有无判定，不存大文本，避免记录膨胀。

### 3.4 源码直接分块（`astminer/` 按职责新增组装模块，原引擎不动）

新增一个只做组装的职责，形态与对标的直接分块同构：分组器加组装加分块器的最小组装，
无模型调用。规则为：成员源码原文即块文本（两路填同一原文，计量各按各路算），
空区间源头跳过并计数；分组有成员时组头只作身份（以组名为文本，组名此时必非空），
无成员时组头取组 span 原文，仍为空则整组跳过。输出复用分块器的双路块类型，
直接落入与文档块同一的对齐键体系。

### 3.5 落库与编排联动（小幅随动，不另立方案）

- 文档表元数据加被并集合字段；源码块入库时复用文档表或独立 api 块表由实施时按查询模式定，
  但必须带源分组标识以便双路锚定，检索融合时按该键对齐。
- 抓取与建索引编排在落库前做空块拦截计数，计入已有的结局计数字典，
  向量失败仍只计数不推翻真源写入（保持现有语义）。
- 向量文本组装对源码块用实体限定名加文件路径加源码原文，与全文路的标题加路径加正文对称。

### 3.6 调试出口（改 `cli.py`，不新增服务）

加一个只读调试命令，按文件导出分块预览（文件到分块的行号、字节、标题、精度），
供人工评审与黄金样例制作。形态对标直接分块的可视化导出，
复用同一组装入口，不走任务队列。

## 4. 任务清单（按实施顺序）

1. 预算计量职责落地：路径判别、双路预算、与 FTS 同款的词项计数、截断计数；配置项登记。
2. 分块器重写：双路切分、统一超长递归、三约束合并（相邻、左身份、被并集合）、
   单向前重叠、精度枚举、自包含豁免、截尾告警、空块计数。
3. 文档落库元数据与调用方随动：存储、抓取编排、向量组装、检索对齐键。
4. 实体文档说明抽取：消费注释查询，模型加有无标记，缓存记录格式升级（旧缓存失效重解析）。
5. 实体分组模块：类加方法、文件头加顶层项，成员区间透出。
6. 源码直接分块组装：空区间拦截、组头降级规则、双路输出。
7. 调试导出命令与黄金样例：分块预览出口、入库两至三个文件的期望分块。
8. 门禁：分块单测（路径正确、合并收敛、围栏成对、预算不超、精度标注）加检索双轨记录
   （全文单路与混合各跑一遍，阈值变更需说明）。

缓存记录格式变化时指纹版本号加一，全量失效重解析，不做旧格式兼容。

## 5. 验证标准

- 分块单测：标题路径正确、贪心合并后块数收敛、围栏成对、每块计量不超本路硬限、
  被并集合非空可回溯、重叠仅前向且带来源、截断有计数、空块有计数。
- 抽取单测：分组归属（方法归类、顶层归文件头）、文档说明有无判定、空区间跳过、
  缓存升级后旧记录失效。
- 端到端：迷你仓库跑通抽取到源码块落库，已知实体存在且精度为完整实体；
  文档站跑通抓取到双路块落库，双路共享源分组标识。
- 全量测试通过，既有功能不回归；编译与测试合并为最少次数，
  过滤输出先落文件再读，避免重复全量运行。

## 6. 非目标

术语注入、插件注册表、组间关系图、跨文件类型推导、Rust 侧的并发共享语义均不引入。
新增语言仍只加语法包与语言配置，不动引擎。全文分词器配置本身不改，
只要求块计量与之同款。
