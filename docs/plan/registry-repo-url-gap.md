# 注册表仓库地址缺口与补充方案

## 背景

文档抓取只需要文档地址，代码索引还需要仓库地址。按名建代码索引要求解析结论中带有可克隆的仓库地址，否则只能要求调用方显式传入远端地址或本地路径。本次排查逐一核对六个生态按名查询返回的数据，确认哪些生态能直接给出仓库位置，哪些不能。

## 问题清单

- Go 生态仓库地址始终为空。代理快照的版本请求实际返回了来源信息，内含仓库地址，但解析函数只读取版本号并丢弃其余字段。按名解析文档可用，按名索引代码必然缺仓库失败，只能走显式源或手工覆盖。
- NuGet 生态仓库地址始终为空。注册索引的时间线只携带版本号与工程地址，不携带仓库地址，且代码写死返回空。工程地址为仓库根时也未提升为仓库地址。按名索引代码同样必然失败。
- NuGet 工程地址已改为取时间线最新非空值，包作者更换官网后返回新地址。
- Go 非托管路径存在长尾缺口。代理对部分变体路径不返回来源信息，模块路径本身也不在仓库托管域名下时，无法仅凭模块字符串推导出仓库。
- 离线单测未覆盖新增字段。既有 Go 与 NuGet 用例只断言文档地址与版本，未断言仓库地址，回归无法被测试捕获。
- 端到端缺少注册表仓库断言。现有端到端只覆盖文档抓取与仓库解析落库，未覆盖六生态按名查询到仓库地址的完整链路。

## 修改方案

- Go 解析补齐来源字段。版本请求保持不变，新增仓库推导：优先采用来源信息的仓库地址并做常规地址清洗；无来源信息时，若模块路径本身位于常见仓库托管域名下，按前三段合成仓库地址；其余情况如实返回空，不伪造。
- NuGet 补齐两路仓库来源并取最新工程地址。工程地址为仓库根时提升为仓库地址；稳定版另取一次包清单文件，解析其中的仓库声明并优先采用；时间线工程地址取最新非空值。清单请求失败只回退为空，不阻断版本与文档结论。自定义镜像下跳过清单请求，避免向公共地址泄漏包名。
- 保持解析失败语义不变。仓库缺失仍按无文档同类错误返回，调用方可据此提示显式源或手工覆盖。
- 单测补齐离线断言。Go 覆盖来源地址直取、大写转义路径、托管域名合成、无来源非托管返回空；NuGet 覆盖清单仓库优先、工程地址提升、清单失败回退、注册失败透出。
- 端到端新增六生态仓库验证。真实网络下逐一按名解析代表包，断言文档地址与仓库地址非空且仓库指向仓库托管域名，文档解析与仓库解析双入口均覆盖。网络失败按环境不可用跳过，不视为回归。

## 端到端补充说明

- 新增用例覆盖六生态各一个代表包，文档解析与仓库解析各执行一次，断言版本号非空、文档地址非空、仓库地址非空且指向仓库托管域名。离线默认跳过，需显式开启。
- 代表包选择兼顾稳定与可克隆：文档型包要求注册元数据自带明确仓库声明，避免依赖模糊推导；Go 选择托管在常见代码托管域名的模块，使来源字段与路径推导双路可验证。
- 本地已用真实网络执行验证，六生态文档解析与仓库解析均返回仓库地址，详见本目录验证记录。

## 验证记录

- Python 包按名解析返回文档站与代码仓库，仓库解析同源一致。
- JavaScript 包按名解析返回官网与代码仓库，仓库解析同源一致。
- Rust 包按名解析返回版本文档与代码仓库，仓库解析同源一致。
- Go 模块按名解析返回模块文档页与代码仓库，仓库解析同源一致。
- Maven 坐标按名解析返回版本文档与代码仓库，仓库解析同源一致。
- NuGet 包按名解析返回工程地址与清单声明的代码仓库，仓库解析同源一致。

## 替代方案

- Go 长尾路径可按需追加变体导入元标签解析。请求模块根地址的变体导入标记，解析其中的代码托管地址与仓库映射，优先级低于代理来源信息。该路径多一次文档型请求，只在代理无来源且路径非托管时启用。
- NuGet 可按需追加搜索接口仓库回填。搜索结果同样不带仓库字段，仅在清单缺失且工程地址非仓库时作为次级线索，不替代清单。
- 私有或内网包统一走手工覆盖与显式源，不扩展自动推导。覆盖文件允许只写仓库地址，文档缺席不阻断代码索引。
- 批量场景可先离线缓存快照再解析，避免重复请求注册表与清单接口。
