# 返回空时的后续处理与搜索兜底设计

## 1. 返回空的种类与当前后续处理

注册表查询失败分三种，调用方按种类处理：

| 失败种类 | 含义 | 当前后续处理 |
|---|---|---|
| not_found | 注册表无此包 | 直接报错结束，不写缓存 |
| retryable | 网络或注册表不可达 | 有过期缓存则降级使用并标记来源，无缓存则报错；离线模式无缓存直接报错 |
| no_docs | 有版本但缺地址 | 直接报错，附带主页与仓库线索，不伪造地址 |

地址缺失的两种形态：文档解析缺文档地址，仓库解析缺仓库地址。
仓库解析在新鲜缓存缺仓库地址时会跳过缓存强制重查，重查仍缺则报错。

显式地址永远优先于解析，本地目录、远端地址、起始文档地址均可绕过注册表。
代码索引无显式源时按仓库登记、库表仓库地址、注册表缓存的顺序回退，
均无才报错要求显式地址。指定版本不在版本列表中不校验，直接透传并标记未经确认，
后续抓取或克隆失败按单页失败计数，不阻断整批。

各出口的当前行为：

| 出口 | 行为 |
|---|---|
| 命令行解析与索引 | 打印失败种类、信息与线索后退出，显式模式缺参数报用法错误 |
| MCP 解析工具 | 返回种类、信息与线索的结构体 |
| MCP 检索 | 无结果且要求建议时自动跑一次模糊发现，失败则附带建议错误 |
| 命令行发现 | 无候选打印空提示，失败打印种类与信息 |
| 模糊发现 | 各源独立失败计数，全源失败且无结果才报错；含令牌且不限生态时才追加代码托管搜索 |

## 2. 现状缺口

- 线索薄弱。报错只带主页与仓库地址，调用方尤其是 AI agent 拿到后没有结构化的下一步，
  需要自行推断该调发现工具还是改用显式地址。
- 候选未被利用。解析结论保留完整候选地址，但抓取只用首个，首个失效即整批按失败处理。
- 发现结果部分缺仓库。模糊发现中部分生态的候选不带仓库地址，不能直接转代码索引。
- 代码托管搜索有门槛。仅在不限生态且配置令牌时启用，未配置时无仓库导向的搜索源。
- 无通用网页搜索。注册表之外没有兜底，包名拼写偏差或小众包只能靠人工场外搜索。

## 3. 是否需要通用搜索

需要一个显式调用的通用搜索入口，但仍不做静默自动兜底。修订理由：
调用方缺的不是搜索能力，是仓内语境的结构化——通用搜索只给裸地址，
调用方仍需自行判断文档与仓库归属，而判定逻辑仓内已有，封装后一次调用即得
与发现候选同形的记录，可直接进入确认加显式地址流程。裸脚本形式不采用：
游离于服务层之外，重复客户端、重试、清洗、排序实现，且挂不上测试门。

## 4. 方案

失败指引富化已交付（线索统一字段、命令行多行指引、MCP 下一步动作、
无仓库候选标注），本节只描述新增的搜索入口。

新增搜索 provider，只放地址构造、目标提取、载荷解析与分类。
结果链接的重定向参数直接给出真实目标，无需跟随跳转；
标题与摘要按结果块容错提取；分类复用现有仓库与文档判定。

服务层加独立显式入口，不混入注册表扇出。入口校验查询与条数，
复用发现开关、离线语义、共享客户端与重试；结果映射为发现候选同形，
来源标为网页搜索，版本为空，无仓库的沿用缺仓库标注。
该端点对非浏览器代理返回挑战页，仅对此端点使用浏览器代理，
非常规 200 一律归为可重试类。

MCP 与命令行各加一个薄出口，只做参数校验加服务调用加结果整形。
解析失败路径本身不自动调用，结果标注未核实，确认后走显式地址使用。
离线模式直接拒绝，无网络的部署环境返回环境不可用。

## 5. 验证

- 离线单测：provider 的地址构造、目标提取、命名、分类与页面夹具解析；
  指引渲染的线索字段与下一步动作字段稳定。
- 离线集成：搜索入口的成功映射、离线拒绝、服务端错误与挑战页分类；
  无仓库候选带标注。
- 显式端到端：真实网络断言返回结构正确且来源标注为网页搜索，
  网络失败按环境不可用跳过。
