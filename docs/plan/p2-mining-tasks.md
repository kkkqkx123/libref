# P2 数据挖掘完整任务清单与修改方案

> 依据：`docs/req/init-req.md` 分支 B（源码挖掘：调用顺序与参数使用模式）、`docs/architecture/module-layout.md` 与 `tech-stack.md`（挖掘纯内存、编排落库、版本隔离可溯源）、`docs/ref/overview.md`（调用实例粒度超越 graphify、序列级挖掘差异化）、`docs/ref/epicoder.md`（层级频次与剪枝可复用、特征抽取靠 LLM 不可直接借鉴）、`docs/spec/astminer-captures.md`（四域捕获规范）、`docs/plan/p2-source-mining.md` 与 `p2-mining-data-rework.md`（已落地链路与已确认的暂不做项）。
> 目标：分支 B 从源码到可用挖掘产出闭环正确、可重现、可观测；产出满足中层检索消费所需的最小完备形态。
> 范围：只动 `astminer/`、`mining/`、`db/schema.py` 与 `migrations.py` 中挖掘相关表、`services/ingest.py` 中建索引与模式挖掘两函数及配套任务载荷、`cli.py` 中建索引与挖掘子命令透参、`tests/` 中挖掘相关用例。不新增替代模块，只改原有模块。不动向量检索融合、不动 MCP 与 Web 出口、不动审核工作流界面、不动文档抓取分支。算法本体不重写。

## 0. 现状盘点与边界

已落地：查询匹配抽取引擎、两遍解析与三级置信、行范围加实参加组内序号、相对导入展开、文件哈希加指纹增量缓存、按外围调用者分组保序成序列、自研 PrefixSpan 闭合挖掘、实体调用模式三表幂等加清扫、待定调用记待审、五个只读挖掘查询靠查询时计算。

本计划解决的缺口：声明限定名无模块前缀导致跨文件同名靠距离消歧；参数只有名无类型、返回类型与泛型基类非结构化；部分调用形态捕获不全；接收者类型无最小推导；包内重导出未闭包；多候选平局强制取首；精确频次与层级展示频次混用；共现粒度与查询粒度不一致；大字母表截断位置错层；阈值长度策略写死；提交标识未绑到调用实例；挖掘查询缺支撑索引；清洗规则分散。

## 1. 抽取层任务（改 `astminer/` 原有模块）

### 声明限定名模块前缀化

现状为文件内父链拼接，跨文件同名依赖距离消歧。改为抽取时拼接当前模块路径，缺失模块路径时保持原行为。改动落在引擎声明装配与模块路径推导共用逻辑，缓存编码解码随之携带完整限定名，指纹版本同步递增以失效旧缓存，重跑后实体与调用按新限定名幂等落库。验证以同名跨文件迷你仓为准，要求解析后限定名含模块前缀且消歧不再依赖距离。

### 参数类型与返回结构化

现状参数只记名，基类为文本拼接。改为在查询中补齐参数类型、返回注解、基类类型实参加工位，规则层做文本整形与长度截断，模型与缓存随之携带结构化字段，落库时复用已有签名与参数基类列。验证覆盖装饰器、异步、泛型基类、 Java 实现接口与记录组件。

### 调用形态补齐

对照捕获规范核对三语言查询，补齐链式来源调用、等待内外层、超类方法、构造与对象创建、方法引用、回调参数体缺失项。改动只增查询文本与捕获选择分支，引擎归并与调用者归属逻辑不变，未知捕获保持忽略计数。验证为每种形态一条黄金样例，调用文本与实参数量断言。

### 接收者最小类型推导

现状仅靠作用域链、实参数量、字节距离消歧。改为在单文件内建最小变量类型表，来源仅限显式构造赋值与注解赋值，字段限定自身引用，循环变量与异常变量单列来源，不做跨过程推断。解析时以该表为优先于距离的消歧信号，无信号时回退原策略。验证为接收者为局部变量的调用由待定转为推导，无信号用例行为不变。

### 重导出闭包与通配策略

现状相对导入已展开，包内重导出未二次解析，通配导入直接返回空。改为导入表建好后做一轮包内重导出闭包，通配保持不展开且对应调用维持待定并可计数。绝对导入与通配行为不变。验证为重导出包的调用被展开为推导，通配文件调用维持待定且计数可见。

### 清洗规则收拢

现状排除目录与压缩产物分散在仓库遍历中，测试文件语义与文档分支一致但未显式声明。改为在仓库遍历原函数内收拢排除表，明确测试文件名、生成目录、压缩产物、大文件上限的取舍与计数口径，与抓取分支测试剔除语义对齐。验证为含测试与生成文件的夹具仓计数符合预期。

## 2. 解析层任务（改 `resolution.py` 原有逻辑）

### 平局严格化

现状多候选经多信号仍平局时取排序首位，可能伪造显式抽取。改为信号用尽仍多候选时一律判待定，不强制取首；单候选与唯一信号命中保持原置信。验证为构造平局用例要求置信为待定且审核出现待审行，原有单候选黄金样例不变。

### 调用标识稳定性说明

现状调用标识含起止行，格式化即抖动导致删增 churn，但保证语义键唯一。改动仅为文档化该取舍并在端到端验证中观测 churn，不改标识构成，避免引入跨版本误合并。验证为同仓二次建索引行数不变，格式化后重跑仅计数 churn 不残留旧行。

## 3. 统计挖掘层任务（改 `mining/` 原有模块）

### 精确频次与层级展示分离

现状层级计数含点分前缀父级，不可直接用于截断。改为保留层级聚合仅作展示，原模块内增精确计数按完整限定名计数，截断只消费精确计数。验证以手算小数据为准，层级与精确两套结果各自符合黄金样例。

### 共现粒度统一到作用域级

现状共现为文件级集合，检索侧共现查询为文件加外围调用者作用域级，两者口径不一致。改为共现输入改为作用域集合，调用方按作用域构造集合，文件级仅作为调用方的聚合选项。验证为同一夹具下共现矩阵与检索侧共现查询排序一致。

### 大字母表截断归位

现状截断计数写在编排层，与频次模块分离。改为截断统一调用频次模块精确计数，编排层只传规模参数，默认关闭，开启时仍受支持度阈值约束。验证为大字母表夹具下截断结果等于精确计数取前若干，且低支持模式仍被阈值剔除。

### 阈值与长度策略参数化

现状最小长度与最大长度写死在挖掘调用处。改为最小支持度、最大长度、截断规模、待定纳入开关全部由编排函数签名与任务载荷透出，命令行子命令只做透参，默认最小支持度保持小库可验证取值，大库由调用方按序列规模显式提高。验证为不同阈值下模式集单调收缩，最大长度截断生效。

### 序列输入卫生

现状空序列已过滤，单调用作用域靠最小长度自然剔除。改为在归一化前显式去重全同序列的空值与超长异常作用域计数，保持算法侧无感知。验证为含空文件与单调用文件的夹具不污染模式集。

## 4. 编排与持久化任务（改 `services/ingest.py`、`db/` 原有表与索引）

### 版本内多仓语义明确化

现状同一版本假设单仓库，实体调用清扫按版本全量比对，多源同版本会互删。改为文档化单版本单仓不变式，多源场景要求调用方使用不同版本号，编排层在违背时以显式错误拒绝而非静默互删。验证为同版本二次换源建索引拒绝执行，已有单仓幂等行为不变。

### 提交标识绑定到调用溯源

现状仓库登记有提交标识，调用实例只有仓库名字符串，溯源断在版本级。改为调用记录携带提交标识并落库新增列，存量数据重跑回填，缓存记录随之携带该字段。需一次新增列迁移，不改已有迁移内容。验证为建索引后抽查调用行提交标识与仓库登记一致，本地目录来源记本地标记。

### 挖掘查询支撑索引

现状模式证据与共现查询靠全版本扫描，大仓会退化。改为在原表上补版本加被调名、版本加调用者文件加组内序号的复合索引，不新增落库表，维持查询时计算以保证与真源一致。需一次加索引迁移。验证为万级调用夹具下五个挖掘查询延迟达标且计划走索引。

### 模式落库语义冻结

维持模式行只有名称数组与支持度加闭合标记，不持久化证据列，证据一律查询时按有序子序列算。改动仅为在方案中冻结该语义，避免后续重复讨论加列。验证为删源码后旧模式被清扫计数，证据查询返回文件与行范围与实参完整。

## 5. 执行顺序

先抽取层模块前缀与类型结构化，因其改变实体语义与缓存失效面；再解析层平局严格化与重导出闭包，因其依赖新限定名；再统计层频次分离与共现统一，因其为编排层调用前提；再编排层溯源列与索引迁移；最后补黄金样例与全量回归。每次收敛为一次全量测试运行，输出重定向到文件后阅读，不在中途反复全量运行。

## 6. 验证标准

抽取黄金样例覆盖装饰、异步、链式、等待、超类、构造、方法引用、回调、通配、相对导入、继承与实现、模块前缀、接收者推导、重导出。解析要求别名展开为推导、仓内声明为显式、平局为待定且审核有待审行。增量要求同仓二次建索引全命中缓存且三表行数不变，指纹变化全量失效。频次共现以手算小数据为黄金样例。端到端以迷你仓跑通建索引到模式落库，要求已知闭合模式存在、支持度精确、闭合标记置位、删文件后旧模式清扫。

## 7. 本次不做

向量重排集成、检索融合基准、审核状态机流转、令牌鉴权、前端审核界面、跨函数跨文件长序列挖掘、语义特征树建模、嵌入去重采样，均不在本次范围。声明限定名历史数据兼容不做，旧库要求重跑建索引。
