# 图遍历查询语义审查与修正

## 范围

本轮审查针对独立图查询通道的读模型与查询编排，覆盖 `store/graph.py`、`services/graph_query.py`、三个出口的参数契约以及图读路径依赖的事实表索引。审查目标是让过滤、方向、截断、身份和证据在五种查询形态中具有一致含义；不新增图数据库、不新增第二份图数据、不参与语义排序。

## 完整问题清单

### 语义与边界

1. `relation_types` 只在候选边阶段过滤，邻域构造阶段已经把文档、簇、特征、文件、模式等节点写入结果。关系过滤后的邻域会返回没有对应边的节点，这些节点还占用 `graph_max_nodes` 预算，可能提前触发截断。
2. `shortest_path` 在节点数达到上限时直接退出循环，但截断标志保持为 False；服务层在“未找到路径”分支也硬编码 False。调用方无法区分“确实无路径”和“预算耗尽”。
3. `community`、`usage` 固定双向，`impact` 固定反向，但服务签名仍接受 `direction`；`target` 对非 `path` 模式也静默忽略。无效参数被接受却不生效，属于误导性接口。
4. 方向语义在节点类型之间不一致：文档节点完全忽略方向；模式节点在 `forward` 下返回以自身为目标的边，在 `backward` 下反而返回空；特征节点把入边的父链和出边的成员边混在一起；文件与簇节点只用“是否为 backward”粗判。
5. 调用边的 `weight` 恒为 1.0。设计口径称结构权重可表达调用次数，但图内没有聚合同一对实体之间的多个调用实例，频次只在 `usage` 的挖掘统计中出现。
6. `profile` 解析不到时，服务仍返回调用、文档等非 profile 事实，节点与边的 `profile_id` 为空。拼写错误与“profile 尚未生成”会被当作正常的不完整图返回。
7. `resolve_entity` 与 `_entity_by_name` 对限定名的查询使用 `LIMIT 1` 且无排序。schema 允许同名不同 `kind` 并存，种子解析和继承、模式成员绑定可能落到任意一行。
8. 文档按 URL 反查未排序即取一条文档块，页面级 `doc_link_edges` 也只连接到一个代表块。按块存储的 `documents` 与页面级导航之间存在身份落差，导航目标不稳定且丢失同页其他块。
9. `_api_row` 在目标行缺失时构造占位节点，节点证据指向不存在的 `api_entities` 行，掩盖事实表漂移。

### 身份与证据

10. 簇节点的 `source_id` 取 `api_clusters.id`，`evidence_ref` 却使用 `cluster_id`；簇边有时用行 id、有时用簇 id。更严重的是簇邻居查询把节点 `source_id` 当成 `cluster_id`，导致同簇兄弟实体无法到达。
11. 特征节点声明来自 `feature_nodes`，但 `source_id` 经常写入 `doc_feature_node_links.id`，证据引用错指事实表行。
12. 文件节点是合成节点，却声明 `source_table="call_instances"`；由导入边派生的文件节点也沿用同一声明。
13. `STRONG_DOC_LINKS` 定义后未使用，强边条件在三处 SQL 中重复硬编码，存在口径漂移风险。

### 性能与契约

14. 图读路径缺少复合索引：调用按版本和实体反查、文档按 document_id 反查 API、特征按路径反查、簇按成员反查、模式按哈希反查、一致性按文档反查都依赖全表扫描或次优索引。
15. 邻域展开是“每节点有界”而非“整次查询有界”；模式展开还会对每个相邻对重新查实体。边界参数能限制单层扇出，但不能限制总 SQL 次数，也没有把预算耗尽反映到截断标记。
16. 查询形态字面量在服务、Web 请求模型、Web 路由、MCP 工具和 CLI 客户端中重复定义；服务与 Web/MCP 可以共享类型，但 HTTP 客户端不应依赖服务端实现，重复值缺少防漂移校验。
17. 图查询没有 Postgres 后端集成测试；SQLite 与 Postgres 的事实表 schema 虽有镜像，但图读 SQL 未做跨后端验证。
18. Web 与 MCP 用户文档没有说明固定方向的模式、参数拒绝规则和 profile 解析失败行为。

## 修改方案

### 语义修正

- 邻域展开先生成边、再按关系与置信过滤，然后只为被采纳的边物化节点；返回结果按“种子加实际边端点”裁剪，避免未采纳边污染节点集合或消耗节点预算。
- 最短路径把“未找到路径”表达为带 `found=False` 的空子图，节点上限与扇出上限都设置 `truncated`，服务层原样透传截断标志。
- 参数按模式校验：`path` 之外不接受 `target`；`community` 与 `usage` 只接受 `both`；`impact` 接受 `both` 或 `backward`，实际固定反向。方向按边的真实朝向解释，文档反向只返回指向该文档的链接，模式节点的邻接只在反向或双向生效，特征节点按入边父链和出边成员边分别返回。
- 同一对实体之间的调用实例按方向聚合为一条边，代表行保留行级证据，边的 `weight` 写入调用次数，证据附 `call_count`。
- `profile` 解析失败直接报参数错误，不再返回缺少 profile 事实的半张图。
- 实体解析要求限定名唯一；同名多 `kind` 视为无法解析。文档按 URL 反查扩展为按 `sort_order`、`id` 返回该页全部文档块；页面级链接展开到每个块，块数超过扇出上限时设置截断标记。

### 身份与证据修正

- 簇节点用 `path` 保存簇 id，用事实表行 id 作为 `source_id` 与 `evidence_ref` 的依据；簇成员边统一引用真实行 id，簇邻居查询改用节点 `path` 中的簇 id。
- 由文档特征链接派生的特征节点不再冒充 `feature_nodes` 行，改为合成节点：结构来源表保留，行 id 为空，证据引用按路径派生；由父链派生的节点仍引用真实 `feature_nodes` 行。
- 文件节点显式作为合成节点处理，不再声称来自调用实例事实表。
- 缺失的 API 行直接丢弃对应边，不再生成占位节点。
- 强边集合改为单一常量，三处 SQL 从同一常量生成占位符。

### 性能与契约修正

- 在 SQLite 迁移与 Postgres schema 中同步增加图读路径复合索引，覆盖调用反查、文档对齐、特征路径、簇成员、模式哈希与一致性证据。
- 新增 `graph_query_budget` 配置，在只读图视图内部统计单次遍历的事实表查询次数；种子解析不计入预算，预算耗尽时停止后续读取并在结果中设置截断标记，而不是抛错或静默返回不完整结果。
- Web 请求模型、Web 路由与 MCP 工具复用服务层定义的模式与方向类型；CLI 作为 HTTP 客户端保持独立常量，由契约测试断言其与服务常量一致，避免让客户端依赖服务端实现。
- 增加 Postgres 后端图查询集成测试，在无可用实例时跳过；覆盖调用邻域、反向路径与文档强边，验证跨方言 SQL 兼容。
- 用户文档与架构文档同步说明固定方向、参数拒绝、profile 错误、查询预算与截断语义。

## 落地状态

18 项问题已全部闭环：

- 语义与身份修改已落地在 `store/graph.py` 与 `services/graph_query.py`；集成测试覆盖关系过滤裁剪、路径截断、参数拒绝、合成节点证据、页面级文档链接多块展开与查询预算截断。
- 强边常量、Web/MCP 类型复用、CLI 常量契约校验、图读索引与文档同步已完成。
- Postgres 图查询集成测试已加入现有集成测试文件；未提供 `LIBREF_TEST_POSTGRES_URL` 时按既有后端测试惯例跳过。devs 上的 PG10 不满足生产 schema 的生成列要求，复测使用临时 `postgres:14` 容器；该轮同时修正了版本解析里 `? IS NULL OR ...` 的跨方言参数推断问题。
- 派生邻接缓存与模式展开去重已落地：缓存按事实水位失效、超容量或无水位时回退 SQL，SQL 与缓存共用同一 gold 差分测试。默认仍关闭，热点版本按配置显式开启；实测加速比与回本批次见 `docs/plan/long-term/graph-adjacency-cache.md`，当前规模数据与图数据库选型阈值见 `docs/plan/long-term/graph-storage-scaling.md`。
