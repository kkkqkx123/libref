# 源码索引与挖掘链路（现状实现）

> 描述对象是当前代码已落地的源码链。
> 挖掘算法包保持纯内存，落库一律由编排层完成。

## 1. 入口与仓库获取

统一编排在 `services/code_ingest.py`，复用文档链的版本目录。
显式地址、按名解析、无地址时按登记与缓存逐级回退三种来源，同一版本登记不同来源直接拒绝。
先保证库版本行存在，再做后续落库，保证源码与文档共享同一版本标识。
索引与挖掘分为两种任务类型，分别由各自的任务消费函数处理，互不耦合。
命令行同步与异步路径均按有无密钥装配向量组件，有则收尾同步，无则只写真源。

仓库管理以固定根目录为基础，远端浅克隆或拉取更新并记录提交标识，本地目录直接使用。
文件遍历按语言后缀过滤。

## 2. 抽取与解析

语言配置声明语言名、语法包、文件后缀与配置版本，新增语言只加查询模块并登记。
指纹联合运行时、语法包版本、查询文本与配置版本，任一变化缓存全量失效。

通用引擎按指纹缓存解析器与查询，首遍收声明与别名，次遍收调用，注释跨度用于判定文档说明。
声明装配限定名、种类、父级、深度、签名、参数、返回、基类与字节范围。
调用记录原始文本、实参摘要、接收者与函数拆分、外围调用者、行与字节范围。
两遍解析按文件汇总声明与别名映射，按文件、外围调用者、起始字节排序逐个解析，自身引用替换、别名展开、后缀候选与作用域链消歧，结论为显式抽取、推导、待定三档。

逐文件增量键为主键加文件内容哈希，命中复用并计数，否则解析后写回，收尾按存活集合清扫过期缓存。

## 3. 落库与源码分块

实体与调用均用语义键哈希保证幂等，写入后清扫版本内过期行。
待定调用在审核表记待审，删除调用时同步清理对应行。
源码分块按文件分组装配，成员原文直接作块文本，两路预算各切一遍，向量路配口语头，过小块向同组相邻块合并，有独立文档说明的成员不参与合并。
块转文档形态时回填限定名名单，合并来源一并计入，落库时经文档表复用，全文索引同样可查源码块，元数据中的实体名单供检索侧精确匹配。

源码落库后同样走收尾向量同步，与文档链共用同一共享函数，收集的删增标识来自各文件的存储返回。
向量缺失时只写真源，后续可经整版重灌补齐。

## 4. 挖掘与审核

按版本读出调用实例，按作用域分组保序成序列，过滤超长与过短，可选按频次显式剪枝。
归一化后做闭合模式挖掘，结果反归一化后幂等写入并清扫过期模式。
特征树按限定名逐级建节点，挂种类、调用数与覆盖作用域数。
分组按作用域构造集合，做确定性层次合并。
三表在调用为空或序列为空时保持一致清空。

挖掘与读取均尊重审核结论：冲突始终排除，待定默认排除、显式要求时纳入，已核准的待定视为可用。
读模型提供频次、参数形态、同作用域相关接口、模式列表与证据、特征树前缀浏览、分组浏览。
模式证据按有序子序列在调用序列中匹配，查询时计算，不持久化。
审核提供待定列表、批准、标冲突、重开，只接受合法流转。

## 5. 检索消费

源码块与文档块共用文档表，全文单路天然可查源码块。
混合检索按版本读出模式与分组，块有实体名单时做精确交集匹配，无名单时回退名称启发式。
命中支持度按版本内最大值归一，分组命中要求同组两个以上成员，加权只作用于融合后的头部，为零时退化为纯融合排序。
问答在检索命中后按标识回查全文，材料在行边界处截断，引用保留检索顺序。
