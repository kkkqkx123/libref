# MCP 工具面整理

> 依据：`src/libref/mcp_server/server.py`（当前 19 工具实现）。
> 定位：MCP 出口是只做参数校验与服务调用的参数薄层，业务逻辑全部在 `services/` 层；向量索引仅 `store/vec_store` 可达。三出口（MCP/CLI/Web）共用同一组统一入口，保证行为一致。

## 1. 工具总览

当前共 19 个工具，按使用场景分为 6 组：

| 组 | 工具 | 职责一句话 |
|---|---|---|
| 检索问答 | `search` | 预设检索，精确走全文单路，均衡与详尽走融合召回 |
| 检索问答 | `answer` | 预设检索加 grounded 生成，无证据返回空 |
| 阅读目录 | `read_doc` | 按地址读取文档：整页、前后窗口、整节三模式 |
| 阅读目录 | `catalog` | 类目浏览：无库名返库列表，给定库名返版本列表 |
| 发现解析 | `library_search` | 跨注册表模糊发现候选 |
| 发现解析 | `web_search` | 显式网页搜索，结果未经核验 |
| 发现解析 | `github_search` | 显式仓库搜索，结果未经核验 |
| 发现解析 | `resolve` | 按生态加名称解析文档或仓库地址，只读语义 |
| 探查 | `doc_probe` | 探查文档站结构，不存储，先探查再抓取 |
| 探查 | `repo_probe` | 探查仓库目录结构，不解析，先探查再索引 |
| 探查 | `repo_dependencies` | 查询某版本清单声明的依赖 |
| 源码洞察 | `api_insight` | 接口视角：频次榜、同现接口、参数形态、多接口公共调用 |
| 源码洞察 | `pattern_insight` | 序列与结构视角：模式列表、模式证据、特征树、分组、健康、标签、片段 |
| 源码洞察 | `symbol_insight` | 符号视角：详情、所属文件、子节点、签名 |
| 源码洞察 | `call_insight` | 调用视角：被调、调用、文件三视图 |
| 源码洞察 | `import_insight` | 导入边视角：扇入与扇出 |
| 源码洞察 | `mining_health` | 复用度与多样性健康信号 |
| 治理 | `review` | 审核状态机：列待定、批准、标冲突、重开 |
| 治理 | `job_show` | 任务查看：无编号列最近任务，给定编号返详情 |

除审核的状态迁移外，其余均为只读。地址解析虽写注册表缓存，但对外语义为只读查询。

## 2. 检索问答

通用检索用模式区分两路：混合模式为全文加向量的融合召回，恒定返回降级标记，向量缺失时退化为全文并标记降级；精确模式为同步全文单路，不标记降级。两路共享查询词、库、版本、生态、条数过滤，混合模式另可附带窗口扩展开关与半径。
两路都附带可答性字段（证据是否足以回答）与跨语言标记；可答性不过滤结果，由调用方决定是否弃答。预设只在服务层解释，窗口扩展开关的优先级为调用方显式指定、预设、配置依次降低，问答链路显式关闭窗口展开。

问答在检索之上做生成编排：先混合召回候选，再组装材料调用问答通道。问答通道缺配置时返回不可用原因，不抛异常中断会话。调用方应先检索，无证据时不必问答。

## 3. 阅读目录

文档读取三模式对应同一文档表的三种切片：整页按地址重组全部块，窗口按中心序号取前后若干块，整节按源分组编号取整节。窗口模式要求给出中心序号，整节模式要求给出源分组编号，缺失报参数错误。

类目浏览是库表与版本表的只读投影：无库名时返回全部库及其版本数，给定库名时返回该库的版本及其页数，生态作为可选限定。

## 4. 源码用法

接口视角回答“某接口如何被使用”：频次榜为调用次数与覆盖作用域排名，同现接口为同文件同调用者作用域中共现的接口，参数形态为某接口实参列表的分组计数。后两者要求给出接口名。

模式与结构视角回答“调用序列与组织结构”：模式列表为已挖掘闭合序列，可按包含成员过滤；模式证据为给定序列在源码中的分组实例，要求非空序列；特征树为按点分路径前缀浏览的分层节点；接口分组为聚类后的成员集合，可按包含成员过滤。

各视角共享库、版本、生态过滤，条数缺省沿用合并前各自的原值，调用方显式给定时覆盖。

## 5. 探查

探查是写入前的只读预检，与抓取共用同一发现器与范围策略。文档探查透传存活预筛、查询词、分数阈值与路径前缀，接受页数上限但不抛预算异常，超限时在返回体中标记超预算并给出实际规模；开启跟随链接时明确提示实际抓取可能继续膨胀。源码探查接受子目录与单文件限定，先按限定过滤再做预算判断，并回显未命中的限定路径；远端按复用槽、托管接口、无 blob 树、浅克隆从便宜到贵逐级降级。调用方应先探查确认范围再提交抓取或索引任务。

## 6. 审核运维

审核对应同一审核状态机的四个动作：列表按置信优先级返回待定项，其余三个动作对单实体做流转。仅待定可转终态，仅冲突可重开，非法流转返回失败原因。审核是出口唯一的写入面。

任务查看用任务编号是否给定区分列表与详情，未知编号返回未找到原因。地址解析用目标区分文档地址与仓库地址，失败沿用分类错误 envelope，便于区分参数错误、可重试错误与无地址。

## 7. 典型工作流

* 文档问答：类目浏览定位库版本，通用检索召回候选，文档读取展开整页或窗口，证据不足时调用问答生成。
* 文档入库：探查确认站点规模与范围，超预算时收敛范围再提交抓取任务，任务查看确认抓取结论。
* 源码用法：接口视角查频次与同现，模式视角按包含成员列模式，对候选序列取模式证据定位源码实例；索引前先探查确认文件集，单文件任务先用单文件限定预演。
* 运维：任务查看确认异步抓取与挖掘结论，审核列表处理待定调用，地址解析在抓取前确认文档与仓库地址。

## 8. 与服务层的对应

出口到服务为一一对应，不存在出口直连存储：分支逻辑只在服务层实现一次，三出口直接调用统一入口。检索对应 `SearchService.search_with_mode`，阅读对应 `PageService.read_doc`，目录对应 `LibraryService.catalog`，发现对应 `DiscoveryService`，探查对应 `probe_docs_async/probe_repo`，源码洞察对应 `MiningReadService` 各视角，审核对应 `ReviewService.apply`，任务对应 `JobManager.show`，解析对应 `resolver.resolve`。CLI 的 `probe-docs/probe-repo` 与 Web 的 `/doc-probe`、`/repo-probe` 为同一探查语义的换皮。新增过滤或排序语义时改服务层，出口只做参数透传。
