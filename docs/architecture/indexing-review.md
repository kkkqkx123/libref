# 索引链路总览与设计评审

> 基于当前代码的对照阅读。前两篇记录双链现状，本篇只做总装与是否合理的判断。

## 1. 双链总装

文档链是从站点发现到真源落库再到派生同步的横向管道，
源码链是从仓库克隆到调用实例再到模式与结构派生的纵向管道，
两链在版本标识、文档表与全文索引、混合检索三处汇合。
任务、配置、迁移、治理为两链共用的底座。

## 2. 已落地的合理部分

真源与派生分离：文档表单事务加触发器同步全文，向量失败只计数不推翻真源，集合按库派生隔离并经元数据治理，重灌与整版删除形成闭环。

增量语义完整：条件请求、页面哈希、块哈希三级短路，复用块只改排序与元数据，缺席清扫在来源无效或截断时主动放弃，删除留痕可审计。

分块可解释：双路不同计量口径，装配上限为硬限预留空间，硬截断在组装末端执行并计数，围栏成对断言，孪生去重，来源分组，字符区间回填。

源码侧幂等与缓存正确：语义键重跑幂等，缓存键覆盖运行时、语法包、查询与版本，语法升级必然失效，置信分级同时驱动挖掘过滤与送审。

出口与装配收敛：网关统一持有熔断限流并按端点共享，无密钥自动退化为纯全文并显式标记降级，配置三源优先级加密钥不入库，迁移版本化幂等，任务可审计。

本次已修复的对称性与一致性问题：源码收尾向量同步与文档侧共用同一函数；块到接口由元数据实体名单显式关联，检索优先精确匹配；默认检索语义统一为混合，精确单路显式命名；版本互斥下沉到数据库，跨进程可见；治理表纳入版本化迁移；挖掘与读取统一尊重审核结论；检索质量以平均倒数排名与召回率做双轨门禁，混合不得回退。

## 3. 剩余建议

渲染策略需要数据支撑：跳过已计数并告警，但是否开启降级仍需运维按候选率决策，建议在发现阶段统计渲染候选率后再固化默认。

权重调参保持小幅：全文列权重、融合权重、频次与分组加成上限仍为经验取值，基准已就位，调参需附基准变化说明，避免无依据放大。

任务队列仍为进程内内存队列，版本锁已跨进程，但任务分发本身仍是单实例语义，多实例部署需显式声明单实例或另行收敛分发。
